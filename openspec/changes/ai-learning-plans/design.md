# 知行成长 AI 学习计划设计

## Context

2026-10-14静态核对：现有服务为 FastAPI、SQLite 和原生 HTML/JS。`copilot/api.py` 的输入固定为 `renzhi`、课次1–168；`core.py` 读取已有规划并管理课程发布；`generation.py` 已有草稿、流式事件和请求记录，但仓库未发现 `copilot/transport.py`。英文与表达通过 `app.py` 的固定目录映射读取。平台已有今日学习和记录入口，不能另建第二套服务或数据库。

现有生成接口要求明确备课资料，外部10:00任务直接写认知模块，尚未统一共同锁。本设计保留其现有边界。本次不验证模型账号、密钥、依赖可用性或真实API效果。

## Goals / Non-Goals

**Goals:** 输入新目标后形成可编辑规划，确认后保存，继续生成第一课并在首页阅读；后续按计划推进，明确反馈后可修订未发布部分；全过程本地留存、失败可恢复。

**Non-Goals:** 第一期不做联网搜索、任意聊天、自动评估掌握程度、自动调整已发布课程、云端账户同步、新后台调度器。保留现有自动任务，既有模块不批量搬迁。不得把第一期描述为无人值守的自适应教师。

## Decisions

### 1. 用户流程与页面

复用“学习”导航：我的课程旁增加“创建学习计划”，计划详情展示规划、课程目录、下一课与进度。创建流程为：

1. 输入学习方向和目的；补充基础水平、周期、每周学习次数、每次分钟数。
2. 显示发送给AI的信息概要，用户点击“生成规划”，进入可取消的生成状态。
3. 预览阶段目标、先修知识、逐课主题、练习、复盘和总投入；编辑或重新生成。
4. 点击“采用规划”才建立正式计划。默认手动生成，不自动创建提醒。
5. 准备来源摘要后点击“生成第1课”；预览正文、资料，确认保存后出现在今日学习。

例子：“零基础经济学，每次20分钟，8周，每周5次，希望看懂新闻。”生成的规划应有40个学习单元，复盘占用其中的单元，不额外增加隐性时长。模型发现目标不适合时给出取舍建议，不虚构已能达成目标。

输入边界建议：1–52周、每周1–7次、每次5–120分钟；所有示例值可修改。已知总时间预算时，按每周总分钟数比较所有活跃计划；超出后提供减量、延长、暂停旧计划或明确接受超额。未填总预算显示“尚未设置”，不擅自假定45分钟。无论点击多少次，新计划都不会自动启用定时生成。

### 2. 稳定编号与旧课程兼容

服务端分配 `plan-YYYYMMDD-NNN`，北京时间日期加当日递增序号，由SQLite事务唯一分配。名称只作显示，不能由模型或用户决定磁盘路径。重名允许，但页面显示编号以区分；重命名不改变目录。

新增计划注册表保存新计划及旧模块的映射：旧认知、英文、表达标记 `legacy`，只提供汇总和原入口，旧模块继续使用原接口。它们的课次范围、完成规则不套用新规则。已有打卡不推断课程已完成。

不把旧目录改为链接、不迁移正文、不复制数据库。相较全量重构，这能把第一期变动限定在新增计划生命周期与通用展示接入。

### 3. 本地文件与数据归属

新计划目录相对 `/Volumes/Xiaohao/学习/`：

```text
学习计划/plan-YYYYMMDD-NNN/
  README.md
  计划信息.json
  学习规划.md
  课程目录.md
  学习记录.md
  规划历史/v001.md
  每日课程/YYYY-MM-DD-第NNN课-主题.md
  参考资料/第NNN课-参考资料.md
  备课资料/第NNN课.json
  备课资料/第NNN课-摘要.md
  附件/第NNN课/...
```

计划信息含 `schema_version`、`plan_id`、显示名、活动版本、学习条件、状态、创建时间和旧目录映射类型。每计划独立编号，不重复使用已发布课号；超出周期需修订或创建关联的新计划，不受旧认知168课上限影响。日期为实际生成日期，课号是进度，不因漏学跳号。

SQLite是计划状态、版本、草稿、请求与完成反馈的权威记录；正文和资料文件是可读内容，JSON/规划/目录是已确认状态的可恢复镜像。手动改文件不自动被数据库覆盖：比较发布哈希，显示冲突并允许人工审阅导入新版本。个人记录区仅追加约定内容，保留原文。

新增表建议为 `learning_plans`、`learning_plan_versions`、`learning_lessons`、`learning_drafts`、`learning_ai_attempts`、`learning_feedback` 和 `learning_publications`。课程唯一键 `(plan_id, lesson_no)`；版本包含 `base_version` 和已确认结构；草稿关联生成时的规划快照。新表不加入旧 `save_state` 或重置清单。

### 4. 生成与AI适配

把“规划生成”和“课程生成”作为两种任务，复用请求记录、取消、预览和发布理念。现有认知接口保持不变；提取通用能力时先做兼容验证，不把新计划硬塞进 `renzhi` 常量。

第一期采用现有Qwen配置约定，复用既有设置页和服务端环境变量读取密钥；新计划接口仅显示配置状态和模型名称，不返回密钥。数据库快照排除设置表中的API密钥。新增传输适配器之前核对现有依赖，若需新包先取得授权。每次显式生成才调用模型；重试必须显式触发，不因刷新、轮询、保存或超时自动追加付费请求。

规划输出结构化JSON，经后端验证课号连续、单元数量、时长预算、目标与先修关系后再渲染Markdown；格式错误保留草稿但不能采用。课程输出沿用正文与资料分隔协议，验证必要教学章节、引用和完整结束标记。模型输出不能控制文件路径或执行任何命令。

第一期规划可以依据用户目标与通用教学原则形成草稿，标明建议性质；涉及具体外部事实不得伪造引用。课程生成要求用户或现有对话助手提供已核验的来源清单与专用教学摘要，支持在页面录入或从受限模块目录选取；自动搜索留待第二期。记录来源标题、URL、核验日期、核验范围和主张边界；服务端只验证结构，不能声称替人完成事实核验。来源不足时可保存规划，课程生成提示“待准备资料”。

默认发送目标、条件、当前规划、选定资料和明确教学摘录；不扫描发送个人复盘、数据库全量记录或密钥。用于修订的学习反馈先展示选择范围，经用户选择后发送。来源与摘录当作数据，不执行其中指令。

生成状态为 `queued/generating/ready/failed/cancelled`；发布另记 `published`。同一幂等键只对应相同请求摘要；重连仅恢复已有结果。进程退出后的未完成调用标为中断，不自动恢复网络调用。设置请求超时、输出长度上限和全局单生成并发，长期失败不阻塞本地阅读。用量可知则记录，计价未配置显示未知，不填0元。

### 5. 规划修订与学习反馈

用户反馈“太难、太简单、时间不足”后，可点击“调整后续规划”，得到新草稿，展示课程变化和时间变化，确认后增加版本。已发布课程（无论是否学完）、原答案、笔记及已完成记录全部冻结；新版本只改尚未发布的课次。下一课草稿绑定旧版本时，禁止直接发布，要求重新核对。名称修改独立于课程修订。

采用规划不会自动生成所有课程；首课和下一课按需请求。保存课程不等于学会，完成只由明确反馈产生。首页展示今日已保存课程及历史待学习，不能把历史课伪装成今天新课。平台汇总需使用计划编号与课号，避免多个计划第001课互相覆盖。

### 6. 一致性、备份与接口

新计划通过服务端写入，注册和发布使用同一全局短锁串行化本地写入，当前单用户规模无需额外逐计划锁；网络生成阶段不持有写入锁，并使用独立全局生成锁避免旧课程与新计划同时调用模型。路径由注册表解析；拒绝越界与内容目录符号链接。现有外部任务不写入新计划；旧认知写入仍沿用现有安全时段机制。

多文件和数据库不能假定一次原子提交。发布先保存意图、旧哈希和暂存文件，逐文件原子替换后提交版本与索引状态；崩溃后凭日志补齐或回退已知内容，遇人工更改停止并提示冲突。未完成发布不能显示“已保存”。

增量迁移前做SQLite一致性备份；完整计划备份包含新计划目录、版本、草稿、日志、反馈和数据库一致性快照，排除密钥。预览恢复影响并停止写入后恢复；整库恢复须明示包含原平台记录。不能把旧认知单模块备份或旧JSON导出称为覆盖新计划的完整备份。

拟新增 `/api/plans` 路由组：创建草稿/列表/详情，规划生成与取消，草稿编辑/采用，规划修订，来源准备，下一课生成/发布，学习反馈。采用和发布传请求键及基线版本；课程读取按服务端标识解析，不接受任意文件路径。全部继承现有本机与局域网访问保护。前端复用现有导航和阅读器，新增 `plans.js`，不引入前端框架。

## Risks / Trade-offs

- 模型规划看似完整但不适合初学者 → 按目标、先修、示范、练习、评价标准人工检查，允许编辑，不承诺学习效果。
- 每增加计划都增加负担 → 显示总时间预算；新增默认不定时，不自动补课。
- 外部改文件与发布并发 → 新计划统一入口、哈希校验与恢复日志；旧任务不迁入，第二期才协调其写入。
- 新表被旧全量同步清除 → 表清单隔离，并以隔离数据库验证旧操作后计划仍在。
- 未配置模型、断网或无来源 → 保留手动规划和离线阅读；不展示成功，不自动重试收费。
- 项目已有未提交页面改动 → 实施前重新检查差异，逐项接入，禁止覆盖用户工作。

## Migration Plan

1. M1：计划注册、目录合同、数据库增量迁移及手动规划预览保存；旧课程以映射方式接入。
2. M2：AI规划适配器、结构校验、草稿与采用、预算提示；真实调用单独验收。
3. M3：来源录入、生成首课/下一课、发布恢复、首页阅读及反馈；这是第一期完整交付门槛。
4. M4：人工发起规划修订、版本差异、备份恢复和回归验收，完成第一期。
5. 第二期另立变更：来源检索、问答、反馈驱动建议、统一调度和外部任务共同写入。新提醒只有用户选择频率后才启用。

回退优先关闭新入口、保留新表与文件。旧程序继续服务旧模块；不得自动删表或删计划。全量恢复须先保存回退前新增记录，以免丢失旧模块同期学习数据。

## Open Questions

默认采用现有Qwen配置，不要求现在提供密钥；实施真实调用前核对账号、接口和费用。每日总预算没有既定数值，在首次创建时询问。上述问题不阻塞本规划和离线结构实施。

## 拟改文件

保留现有 `server/app.py`、`copilot/api.py`、`core.py`、`generation.py` 和 `backup.py` 的既有合同；按实际复用需要局部接入。新增 `server/plans/`（持久化、服务、API）、`copilot/transport.py` 和 `static/plans.js`；修改 `static/index.html`、`daily-learning.js` 接入列表与阅读。实施时更新 `内容存储规则.md` 以声明新计划结构，并补针对身份、恢复和兼容性的隔离测试。不得只修改文档就宣称新能力可用。
