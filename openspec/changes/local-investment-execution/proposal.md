## Why

现有投资页面的“本地筛选”实际由平台服务端运行规则，个人 AI 配置也由服务端转发模型调用，无法满足“电脑本地计算和评估，远端统一保存”的使用方式。新增一条本地执行路径，复用投资数据、引用校验和证据快照，让远端不参与这条路径的模型推理、指标计算与筛选排序。

## What Changes

- 增加投资本地执行模式：冻结明确选择的输入，本地进行确定性筛选、主分析与同模型反证，通过账号 API 保存批次与结果。
- 增加轻量输入交接、阶段快照和结果接收协议。远端只处理鉴权、范围/版本/格式/引用校验、幂等及持久化，不启动本地模式的模型任务，不自动降级调用远端模型。
- 复用既有筛选条件合同，以 `filter_snapshots` / `indicators` 为对照；浏览器使用有版本的无依赖精确比较。复用 `evidence_messages`、`validate_report`、现有投资分析报告和 `ai_evidence`，不尝试在浏览器运行 Python。
- 增加筛选批次与分析任务关联，保存候选范围、排除/未知计数、规则版本、输入哈希和逐候选状态。保存失败的结果可再次上传，不因重试保存而再次调用模型。
- 页面展示执行位置、候选范围、远端保存状态和证据，并区分“本地声明已执行”和“服务端检查通过”。个人模型密钥始终留在本地执行端。
- 保留现有投资记录、服务端分析入口和旧报告兼容性；保持上一批 `/api/data` 改动，代码交付按用户明确授权执行。

## Capabilities

### New Capabilities

- `local-investment-execution`: 本地计算与模型调用、分阶段冻结输入、可靠上传、账号内归档与恢复。

### Modified Capabilities

无已发布规格的破坏性修改。原投资 change 尚在进行，本批不把其未完成的实时、完整回测和全市场能力勾选为完成。

## Impact

- 服务端：`investments/api.py`、`investments/analysis.py` 及窄范围的新交接模块；按需新增账号内批次/回执结构。
- 本地：用户已选择浏览器直接执行；使用浏览器原生能力和无依赖 JavaScript 计算，通过现有账号 API 读写，不直连业务 PostgreSQL。
- 页面：新增 `static/investment-browser*.js`，对 `static/investments.js`、`static/investment-analysis.js` 和首页脚本引用做必要接入；不重写投资主界面。
- 存储：复用 `investment_objects`、`investment_analysis_jobs` 与 `ai_evidence_*`；新增内容进入完整数据库备份。
- 无新增第三方依赖、队列、云端调度器、模型代理或付费行情服务。首批不承诺全市场数据、自动下单、实时提醒或收益有效性。
- 浏览器端直接读取本人配置，直接调用允许 CORS 的模型 API；不使用服务端代理或备用推理。现有 Python 计算规则作为对照合同，浏览器使用带版本的精确分数比较；不冒充复用 Python 运行时。
