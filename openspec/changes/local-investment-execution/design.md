## Context

用户已明确选择浏览器直接执行。现有“本地行情条件筛选”实际在服务端计算，AI 配置虽保存在浏览器，模型请求仍由平台服务器转发。本批增加独立的浏览器路径，保留旧入口和上一批未提交改动。

## Goals / Non-Goals

**Goals:** 浏览器读取本人配置、计算筛选结果、直接进行两次模型调用，远端保存限定来源、实际发送消息、初稿、终稿与批次关系。旧投资报告和建议采用保持兼容。

**Non-Goals:** 不提供服务器模型代理/自动接管，不新增第三方依赖，不新增全市场来源、自动交易、实时或正式回测，不改变全局模型配置安全规则。

## Decisions

### 1. 浏览器承担执行，平台承担少量校验和存储

浏览器负责条件比较、指标、排序、模型调用和本机检查点。远端负责登录账号、限定来源读取、哈希/格式/引用/状态校验及事务保存。保存和鉴权仍有少量远端开销；不声称零服务资源。

新流程：明确选择范围 → 远端冻结原始日线输入 → 浏览器筛选 → 远端保存筛选摘要 → 冻结主分析消息 → 查看全部候选发送预览并确认 → 浏览器直接请求模型 → 保存初稿并冻结反证消息 → 浏览器反证 → 保存终稿 → 原报告页查看。

### 2. 计算合同与精度

Python 不能在浏览器直接复用。首批沿用既有条件字段和三值逻辑，用原生 BigInt 分数进行比较和排序，版本命名 browser-screen-rational-v1；价格、成交量、成交额以原始十进制字符串解析，不用浮点阈值比较，不新增 decimal 依赖。

浏览器只计算本次规则所需的收盘变化、MA20 比较和量比，摘要值以明确精度展示；不把近似展示值用于条件判定。ATR、年化波动、复权与收益概率不在首批新计算合同内。以 Python 原合同的常规、边界和缺失数据样例对照测试；不声称两个运行时在任意舍入边界完全相同。

### 3. 有界来源与快照

首批最多20个明确选择的已有缓存标的，每个最多200条日线，AI最多评估前5个。日线和来源身份在开始时冻结；筛选和排序在浏览器进行。数据不足保持未知，full_market=false，不冒充历史时点回测。

远端不重新计算本地指标。筛选摘要作为来源标明的投资 research 记录保存，关联原批次快照；主分析仅发送这些本地摘要和选定标的身份，不自动读取交易金额、私人笔记或其他账户资料。摘要保留实际使用的原始日线片段、条件结果、截取说明和本地计算版本。

主分析及反证分别使用既有 ai_evidence，不允许客户端上传任意 system prompt 改写冻结消息。消息由既有 evidence_messages 合同产生，浏览器只消费已保存快照。来源变更/删除不替换旧输入，按最新资料生成必须创建新批次。

### 4. 模型连接与配置

默认读取本人既有浏览器 AI 配置。新入口可填写本次模型配置，允许 HTTPS API，以及严格回环 localhost/127.0.0.1/[::1] HTTP；不改变其他业务的 HTTPS 限制。模型密钥只保存在本人浏览器配置或运行内存，绝不进入平台请求、证据、检查点和日志。

直接模型请求使用 credentials=omit、redirect=error，仅带模型所需请求头，不携带平台 cookie 或账号标识。平台 API 使用现有账号封装，两个目的地不互相复用凭证。支持标准非流式 chat/completions，单次180秒，响应有大小上限。

API 必须允许页面来源的 CORS，访问回环服务可能还需浏览器本地网络权限。失败明确提示，不能用 no-cors、浏览器禁用安全策略或平台转发绕过。file:// 打开的 HTML 不具备正常同源平台 API 和登录流程，必须从实际平台 HTTP(S) 地址使用。

### 5. 归档和复用

增加账号内 investment_local_runs 小表保存批次状态、条件、输入 snapshot ID、筛选回执和候选任务映射；不复制整份旧数据。主分析复用 investment_analysis_jobs、analysis-previews、Report、validate_report 和原报告页面。

接口增加 local-runs 的创建/列表/输入/筛选接收和逐候选创建/阶段输入/初稿/终稿接收。所有保存有稳定键、输入哈希和事务状态比较，查询不触发模型。新任务标记 execution_location=browser，远端重启不当作远端 worker 重启，不会启动 run()。

远端结构、逐字引用和条件校验通过不等于证明客户端实际执行了某模型。展示分别标注本地计算自报、输入哈希、输出哈希与远端接收时间；不将模型评分描述成胜率。

### 6. 浏览器生命周期与恢复

本机检查点按页面来源、登录账号、批次隔离，使用 IndexedDB 保存输入/请求键、阶段、已收到输出和待上传 body；不保存模型密钥。存储不可用时在调用前停止并说明。navigator.locks 防同源多标签页重复执行，拿到锁后重新读取最新检查点，旧历史卡片不能覆盖新调用标记；服务端执行归属防多浏览器领取同一候选。无自动接管。

每次模型调用前持久化 call_started，收到输出后先持久化 upload_pending，再上传。上传失败/回执丢失只重传原 raw、请求键和哈希，不重新调用模型。只有 call_started 而没有持久化输出时显示“模型调用结果不明”，不自动重跑；本人明确新建尝试才再次调用。

关闭页面或刷新会结束执行，不承诺后台持续运行。恢复入口只查询原批次并等待本人点击继续；取消在事务内生效，迟到提交不能把取消改回完成。单候选失败保留其他结果。账号切换须停止本地模型请求，禁止把旧账号输出上传到新账号。

账号登录/退出通过不含凭证的同源存储事件通知旧页面，正在进行的模型请求收到通知即中止；每次模型请求前另行核对服务端当前登录身份。逐候选保存已展示的输入哈希，预览失败的候选不能随整批确认直接调用。浏览器任务不占用原服务端分析的进行中名额，浏览器专用预览不能由原服务端提交接口转发；批次列表和详情均按候选任务的实际状态展示取消和中断。

### 7. 最小页面变更

投资工作台增加“浏览器筛选与评估”入口，展示选择范围、模型目的地、发送内容、运行/暂停状态和远端已保存结果。报告与依据直接打开原 InvestmentAI 页面；旧筛选改称账号缓存筛选，避免执行位置误导。

## Risks / Trade-offs

- CORS、本地网络权限、模型兼容性未知 → 明确连接错误，无服务端 fallback；真实连接单列验收。
- 浏览器关闭导致中断 → 先记录调用开始与输出，未知调用不自动重试。
- 大批量长任务 → 初版20标的、前5个候选、顺序执行，不引入后台调度。
- 本机缓存包含私人结果 → 账号隔离并明确告知，可在远端确认后清理本机检查点；密钥不写检查点。
- 本地自报可篡改 → 保留信任边界，远端验证引用和结构，不据此产生实际成交。

## Migration Plan

加法接口和存储 → 浏览器纯计算及检查点 → 直接模型调用和既有报告 → 隔离回归/备份恢复/差异 review。保持旧入口和全部已有改动。按用户明确授权与旧数据保存改造共同复查后提交、拉取及推送；真实模型、CORS、本地网络权限和远端实际部署分别待验收。回滚停用入口，保留批次与证据，不删历史。

## Open Questions

执行入口已确定。真实平台地址、模型 API 的浏览器跨域能力和本机服务权限留待实际环境验收，不在聊天索取密钥。全市场行情采集与本地 CSV 从零导入另批推进。
