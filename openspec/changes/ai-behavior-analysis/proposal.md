# 变更提案：AI 行为分析报告

## 日期
2026-10-15

## 提案人
CEO Review (选择性扩展)

## 问题陈述
系统收集了大量行为数据：打卡、复盘、决策、预测、应用记录、错误记录。但用户需要自己分析和总结模式。

AI 可以帮助：
- 识别用户可能没注意到的行为模式
- 提供基于数据的个性化建议
- 定期生成"行为健康报告"
- 发现数据之间的关联（如"你在高压力周的应用率下降"）

没有 AI 分析，用户可能不知道如何利用这些数据改进自己。

## 建议方案
增加"AI 行为分析报告"功能，调用 AI 分析用户的行为数据，生成洞察和建议。

### 核心功能
1. **一键生成报告**：用户点击按钮，系统收集近30天数据，调用 AI 生成分析报告。
2. **报告内容**：
   - 行为模式总结（哪些习惯在坚持，哪些在下滑）
   - 知识应用分析（学到的概念用得怎么样）
   - 错误模式分析（哪些错误在重复，哪些在改善）
   - 预测校准分析（预测准确度如何，是否过度自信）
   - 个性化建议（3-5 条可操作的改进建议）
3. **历史报告**：保存生成的报告，可以回看。
4. **定期提醒**：每月1号提醒用户生成新报告。

### 数据模型
```sql
CREATE TABLE behavior_reports (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    date TEXT NOT NULL,
    period_days INTEGER NOT NULL,
    content TEXT NOT NULL,  -- Markdown 格式的报告内容
    data_summary TEXT,      -- JSON 格式的数据摘要
    created_at TEXT DEFAULT (datetime('now', 'localtime'))
);
```

### API 端点
- `POST /api/behavior-report/generate` — 生成新报告（调用 AI）
- `GET /api/behavior-report` — 获取报告列表
- `GET /api/behavior-report/{id}` — 获取单个报告
- `DELETE /api/behavior-report/{id}` — 删除报告

### 前端界面
1. **仪表盘"AI 报告"区域**
   - 最新报告摘要
   - "生成新报告"按钮

2. **独立"AI 报告"页面**
   - 报告列表（按日期倒序）
   - 点击展开查看完整报告（Markdown 渲染）
   - 生成新报告按钮
   - 加载状态（AI 生成需要时间）

### 技术约束
- 单用户，纯本地 SQLite 存储
- 调用外部 AI API（使用现有的 COPILOT_API_KEY）
- 报告内容使用 Markdown 格式
- 数据摘要 JSON 包含关键指标，供 AI 参考
- 报告生成异步，前端显示加载状态

## 预期收益
1. **降低分析门槛**：用户不需要自己分析数据，AI 提供洞察
2. **发现盲点**：AI 可能发现用户没注意到的模式
3. **个性化建议**：基于用户实际数据，而非泛泛而谈
4. **追踪进步**：定期报告帮助用户看到长期趋势

## 不在范围内
- 实时 AI 聊天（太复杂）
- AI 自动设定目标
- 多模型支持（只用一个）
- 报告模板自定义

## 验收标准
1. 用户可以点击生成报告
2. 报告包含行为模式、应用分析、错误分析、建议
3. 报告保存并可回看
4. 不破坏现有功能

## 依赖
- 现有 COPILOT_API_KEY 配置
- 需要新增 API 端点
- 需要调用 AI API

## 风险评估
- **中等风险**：AI API 调用可能失败（需要错误处理）
- **中等风险**：AI 生成质量不稳定（需要 prompt 工程）
- **低风险**：报告存储简单，不影响现有数据
