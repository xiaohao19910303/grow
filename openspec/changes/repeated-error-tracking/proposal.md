# 变更提案：重复错误追踪

## 日期
2026-10-15

## 提案人
CEO Review (选择性扩展)

## 问题陈述
系统能追踪"用了什么"（行为应用），但不能追踪"哪里错了"。个人成长中，重复犯同样的错误是常见陷阱。执行复盘时，用户可能发现自己总是在同一类问题上栽跟头——比如总是高估自己的判断准确性、总是忽略某个关键步骤、总是在某个概念上理解偏差。

没有系统性的错误追踪，这些模式只能靠记忆，容易被遗忘或混淆。

## 建议方案
增加"重复错误追踪"模块，记录用户在复盘、写作、练习中犯的错误，并标记错误的重复性。系统自动识别"反复出现的错误模式"，帮助用户聚焦改进。

### 核心功能
1. **错误记录**：在复盘/写作/练习时，记录"犯了什么错"（错误类型、描述、严重程度）
2. **错误分类**：支持自定义错误类型（如"判断偏差"、"步骤遗漏"、"概念混淆"）
3. **重复检测**：自动识别相同或相似错误的重复出现
4. **错误趋势**：展示错误类型的变化趋势（哪些错误在减少，哪些在增加）
5. **改进追踪**：记录针对某个错误的改进措施，追踪是否有效

### 数据模型
```sql
CREATE TABLE error_records (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    date TEXT NOT NULL,
    module_id TEXT NOT NULL,
    error_type TEXT NOT NULL,  -- 错误分类
    description TEXT NOT NULL, -- 错误描述
    severity INTEGER DEFAULT 3, -- 1-5，严重程度
    context TEXT,              -- 上下文（在哪犯的错）
    improvement_action TEXT,   -- 改进措施
    is_repeat INTEGER DEFAULT 0, -- 是否为重复错误
    related_error_id INTEGER,  -- 关联的重复错误
    created_at TEXT DEFAULT (datetime('now', 'localtime'))
);

CREATE TABLE error_types (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,
    description TEXT,
    created_at TEXT DEFAULT (datetime('now', 'localtime'))
);
```

### API 端点
- `POST /api/errors` - 记录错误
- `GET /api/errors` - 查询错误列表（支持日期、类型、模块过滤）
- `GET /api/errors/{id}` - 获取单个错误
- `PUT /api/errors/{id}` - 更新错误记录（如添加改进措施）
- `DELETE /api/errors/{id}` - 删除错误记录
- `GET /api/errors/types` - 获取所有错误类型
- `POST /api/errors/types` - 创建新错误类型
- `GET /api/errors/stats` - 获取错误统计（按类型、趋势、重复率）
- `GET /api/errors/repeated` - 获取重复错误列表

### 前端界面
1. **仪表盘"错误模式"区域**
   - 本月错误数量（大数字）
   - 错误类型分布（饼图或柱状图）
   - 重复错误率（百分比）
   - 近30天错误趋势（折线图）

2. **独立"错误记录"页面**
   - 错误列表（按日期倒序）
   - 每条显示：日期、模块、错误类型、描述、严重程度、是否重复
   - 支持筛选（按模块、错误类型、是否重复）
   - 支持编辑（添加改进措施、标记相关错误）
   - 支持新增

3. **复盘页"记录错误"入口**
   - 在执行复盘四问后，增加"犯了什么错？"折叠区域
   - 选择错误类型、描述错误、标记严重程度
   - 如果系统检测到相似错误，提示"这是第N次犯此类错误"

### 技术约束
- 单用户，纯本地 SQLite 存储
- 零外部依赖，纯前端 SVG 可视化
- 不修改现有表结构
- 遵循现有模块架构（store.py + api.py + register 模式）
- 错误类型匹配使用简单字符串比较（暂不用语义相似度）

### 与现有功能的关系
- **执行复盘**：复盘时可记录错误
- **行为应用追踪**：两个独立模块，但可以在仪表盘中联合展示（"应用了什么" vs "哪里错了"）
- **仪表盘**：新增"错误模式"区域
- **导航**：在"记录"tab 下新增"错误记录"子入口

## 预期收益
1. **识别盲点**：用户能看到自己反复犯的错误，而不是靠记忆
2. **聚焦改进**：知道哪些错误最常见，优先改进
3. **追踪进步**：看到某些错误在减少，增强信心
4. **复盘深化**：从"做了什么"到"哪里可以做得更好"

## 不在范围内
- 语义相似度匹配（太复杂，先用字符串匹配）
- AI 自动识别错误类型（手动选择）
- 错误之间的关联图谱（太复杂，先用简单关联）
- 多用户支持（单用户）
- 跨设备同步（本地存储）

## 验收标准
1. 用户可以记录错误，选择错误类型
2. 系统能识别并标记重复错误
3. 仪表盘展示错误统计和趋势
4. 用户可以查询、编辑、删除错误记录
5. 复盘时可以快速记录错误
6. 不破坏现有功能

## 依赖
- 无外部依赖
- 需要修改 `app.py` 注册新模块
- 需要修改 `index.html` 添加前端界面

## 风险评估
- **低风险**：纯新增功能，不修改现有表
- **中等风险**：错误类型的分类可能不够灵活（先用自定义类型缓解）
- **低风险**：前端可视化复杂度可控（复用现有 SVG 图表函数）
