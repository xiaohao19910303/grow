## Context

### 1 现状与必须先修复的问题

当前平台已有认知阅读来源发现、每日精选、摘要导读、收藏与稍后阅读、个人笔记及本地保存。最新代码增加了原文抓取、详细总结和英语解读，但尚未形成可靠的完整流程。

| 当前问题 | 本期处理 |
|---|---|
| 创建任务时仅给 `guide` 准备上下文，`summary` 和 `english` 执行时却读取文章编号 | 统一生成任务上下文，创建任务前校验文章、正文版本、语言、模型可用性与请求身份 |
| 网页文字混合提取，抓取截取 15,000 字符，生成再截取 12,000 字符 | 保存有段落结构的正文，明确完整性；长文分块处理，不静默截取 |
| 抓取失败字符串被放入 `full_content`，可能作为原文保存 | 内容与失败原因分字段保存；无有效正文时不创建正式原文 |
| 页面主要展示导读与笔记，新增结果未完整接入 | 实现五个阅读视图及生成、预览、采用入口 |
| 既有文章已经去重保存，重新搜集不会替它补原文 | 为单篇旧文章提供“补充正文”，不通过重复收藏解决 |
| 文档、任务勾选与最新代码存在时间差 | 以逐项验收记录为交付依据，不以已有按钮、提交说明或规格校验证明可用 |

## Goals / Non-Goals

### 2 本期范围与默认选择

**Goals:**

1. 收藏公开文章链接或粘贴本人可使用的正文，保存后可在本地独立阅读。
2. 明确展示内容实际范围；生成结果可回到所依据的原文段落。
3. 英文文章支持逐段中文翻译、语境词汇、短语、语法与长难句讲解。
4. 原文、生成资料、个人笔记分别保存，保留版本，刷新与重启不丢失已确认内容。
5. 提供个人生词和站内基础复习，记录行为而不推断掌握程度。

**Non-Goals:**

- 工作项目、统一 Todo、日历、系统通知、云同步、多人协作、浏览器插件。
- 全网搜索、绕过登录或付费墙、保证任意网站全文提取、PDF/OCR/音视频解析。
- 自动批量翻译每天的全部文章、上传整个资料库、自动修改学习计划。
- 为这次阅读升级重写其他学习模块、合并旧课程目录或替换整个平台架构。

默认选择如下，用户确认整份方案即可确认这些产品规则：

| 项目 | 本期默认 |
|---|---|
| 使用方式 | 本地单人网页平台；沿用现有局域网访问保护 |
| 手动收藏 | 链接或粘贴正文；支持纯文本与 Markdown，不要求上传文件 |
| 自动收藏 | 原每日精选继续按偏好保存文章信息与摘要；不自动抓取全文和调用模型 |
| 正文采用 | 手动提取后先预览再保存；无法确认完整性则保留“待核对正文”或“部分正文” |
| AI 处理 | 用户明确选择生成项目和范围，生成后预览采用；收费与发送范围事先可见 |
| 英语难度 | 默认“通用阅读”，可选“基础解释更多”；不推断用户真实等级 |
| 归档与删除 | 支持归档和恢复；第一版不提供永久删除资料包 |
| 新依赖 | 优先复用现有依赖；如提取质量确需新库，说明用途后单独取得同意 |

“关闭互联网后可阅读”以本地服务仍在运行为前提；服务停止时，正式 Markdown 文件仍可用本地编辑器打开。第一版不承诺浏览器关闭服务后仍可离线运行。

## Decisions

### 3 信息结构与日常使用路线

保留“学习 → 认知阅读”入口，内部设置四个列表页：

| 页面 | 内容与主要操作 |
|---|---|
| 今日精选 | 现有推荐与来源状态；打开资料、保存文章、进入补充正文 |
| 我的文章 | 全部资料；按语言、标签、内容范围、阅读状态、加星与归档筛选；搜索标题、作者、来源和标签 |
| 生词与复习 | 本人加入的生词、今天到期的复习、回原文；不自动收录所有 AI 词汇 |
| 阅读偏好 | 既有来源、主题和调度设置，以及英语解释偏好 |

页首保留“添加文章”。“我的文章”默认显示最近保存的未归档内容；已加入资料库与“加星收藏”是不同状态，已有 `bookmarked` 映射为加星，不因取消加星删除资料。

首版搜索覆盖上述元信息，不承诺全文检索。标签用于整理，不自动改变课程归属。

典型使用路线：

```text
添加链接或粘贴正文
        ↓
预览标题、来源、段落和内容范围
        ↓
保存到我的文章 → 本地原文阅读
        ↓
选择翻译、总结或英语解析 → 查看发送范围 → 生成草稿
        ↓
预览并采用 → 双语精读 → 写个人笔记或加入生词
        ↓
本人确认读完 → 站内复习 → 保留后续任务关联入口的数据基础
```

### 4 收藏与补充正文的页面流程

#### 4.1 添加文章

“添加文章”提供两个选项卡：

- **粘贴链接**：输入公开 HTTPS 链接，点击“获取预览”。支持已配置来源的正文提取；其他公开网页使用通用正文区域提取，失败则转粘贴导入。
- **粘贴正文**：标题必填，正文必填；来源链接、作者、发布日期、语言可填写。未知信息显示“未知”，不由模型补成事实。语言初步识别后允许用户修改。

获取预览不调用模型，不进入正式资料库。页面显示标题、来源、语言、提取时间、字数、段落及提取范围。作者或发布日期来自页面时保留来源依据，用户可纠正。

正文编辑保留段落换行；点击“保存文章”时采用这一版。文章已存在时打开现有文章并提供“补充或更新正文”，不会新建第二篇。无来源链接的粘贴文章按独立导入身份保存；内容相同只提示可能重复，不自动合并。

无法获取正文时提供三条可执行路径：“仅保存链接与摘要”“粘贴正文”“重新获取”。摘要也没有时，只保存链接和用户填写的标题，不制造导读。

#### 4.2 内容范围必须可见

| 内容状态 | 页面说明 | 可用生成能力 |
|---|---|---|
| 仅摘要 | 只有来源摘要；不能据此声称阅读全文 | 既有摘要导读；没有摘要则不可用 |
| 部分正文 | 来源只开放片段，或用户明确导入节选 | 选定部分的翻译、部分总结、英语解析；结果始终带范围说明 |
| 待核对正文 | 已提取正文，但尚不能确认覆盖全文 | 可处理已保存正文，标题标为“基于已保存正文”；不能显示“全文总结” |
| 已核对完整正文 | 用户核对后明确确认完整，或具备经维护的来源完整性校验且记录校验依据 | 全文翻译、全文总结及英语解析 |

抓取状态另设“未尝试、获取中、成功、失败”；失败不会把上一版有效正文降级或覆盖。网络成功不等于全文完整。界面同时展示“正文完整性”和“本次生成覆盖范围”，二者独立。

#### 4.3 更新旧文章

旧文章可点击“补充正文”，进入相同预览流程；已有编号、收藏、读完状态、笔记和原摘要导读保持。

更新正文前展示旧版与新版的段落变化，确认后生成新正文版本。旧译文、总结和英语解析保留，但标为“依据旧版原文”；用户可查看其对应旧原文，或明确重新生成。旧笔记的引用仍指向旧版本，不静默改指新段落。

首次上线只做必要的数据结构迁移，不自动补抓全部旧文章；以后可逐篇补存。以后如建设批量补存，另行设计数量、失败处理及预算。

### 5 阅读页面与生成流程

#### 5.1 阅读页面布局

顶部显示标题、作者、来源链接、日期、语言、正文范围和阅读状态，提供返回文章列表、加星、稍后阅读、归档操作。返回列表保留筛选和滚动位置。

```text
文章标题                          加星  稍后阅读
来源 · 日期 · 英文 · 待核对正文

原文  双语  总结  英语解析  我的笔记
------------------------------------------------
阅读内容区
段落定位、选句讲解、加入生词、记录想法
------------------------------------------------
本人确认读完             资料状态与生成进度
```

桌面端双语视图并列显示同一段原文与译文；窄屏按“原段 → 译段”纵向排列，避免左右横向滚动。翻译隐藏只影响显示，不删除内容。五个视图共用当前文章与正文版本，切换后恢复段落位置。

中文文章默认打开原文，“双语”和“英语解析”显示简短不适用说明，不显示会发起请求的按钮；混合语言文章只对用户选定的英文段落启用英语处理。

#### 5.2 五个阅读视图

| 视图 | 需要呈现的内容 | 用户操作 |
|---|---|---|
| 原文 | 章节、段落、列表、引用、可安全显示的表格文本与来源；没有正文时展示明确缺失状态 | 选段、添加引用笔记、补充或更新正文 |
| 双语 | 英文段落与对应中文译文，已翻译段落数／目标段落数，缺失及失败段落 | 隐藏译文、跳到原段、选择缺失段重试、查看旧版 |
| 总结 | 核心问题、观点、论据、推理、局限、应用启发；各论据与关键观点附段落引用 | 跳转原文、编辑草稿、采用、查看版本 |
| 英语解析 | 语境词汇、搭配、语法与长难句；原句、所在段落和解释 | 基础／通用解释、加入生词、返回原句 |
| 我的笔记 | 用户原话、引用段落，可选“自己的概括、疑问、可尝试的行动”提示 | 独立保存；生成资料不会改写笔记 |

“可尝试的行动”本期仍是笔记文字，尚不自动创建 Todo。已有笔记加载原文，保留自由编辑；切换文章或离开页面前，如有未保存内容，提供保存或放弃选择。

#### 5.3 生成前

选择生成类型：中文翻译、详细总结、英语解析，可组合为一个资料包。默认处理当前保存正文；只有选段时清楚显示选段范围。

确认区显示文章、正文版本、段落数与字符数、将发送的内容预览、模型及服务地址、预计调用批次数。只发送选定正文与必要元信息，个人笔记、生词反馈和其他文章不在默认发送范围。服务地址去除凭证参数。

可用量或价格配置缺失时费用显示“未知”，不标免费或虚构报价。有价格时也只显示基于预算的估算，完成后记录供应商返回的实际用量。用户确认的是本次选择范围；刷新和切换视图不会新增调用。

“重新生成”和“继续失败部分”均为新的明确操作，并显示可能新增费用。取消停止本地后续批次和连接，不承诺供应商已经处理的请求不计费。

#### 5.4 生成中与预览采用

状态：等待、处理中、等待校验、可预览、部分完成、失败、已取消。展示实际完成段落与已用时间，不展示猜测进度。

生成结果先保存为草稿，校验通过后进入预览。用户可以编辑、查看原文依据，然后点击“采用并保存”。首次采用创建正式文件；已有正式资料时显示版本差异，采用新版本后保留旧版。

原文与译文对应关系由段落编号维护，不能靠段落排列位置猜测。编辑翻译仍须保留编号与覆盖清单；删掉一段后应显示缺失，不再标为完整翻译。

资料包中各部分分别处理：翻译成功、总结失败时，可以只采用翻译。部分翻译可明确保存为“部分译文”，缺失段落在页面和 Markdown 中均可见；不允许把未完成的全文总结当成正式全文总结。

生成期间离开页面，任务继续；回来读取原任务。重启后运行中任务标记为中断，保留已完成分块及旧正式资料，不自动重新计费。正文或目标资料版本发生变化时，采用操作返回冲突，不自动覆盖。

#### 5.5 内容质量规则

- 翻译保留数字、单位、否定、限定条件和作者语气；专有名词保留英文对照，必要时建立同篇术语表。机器翻译标为“AI生成，待核对”。
- 总结区分作者主张、文章证据与 AI 延伸建议；后者单独标识。没有证据的内容写“文中未提供”，不补造来源、实验、数据或链接。
- 词汇优先解释理解本文所需的意思，不以“高级”作为唯一筛选标准。默认最多 12 个词和 8 个搭配，素材不足时少列，不编造原文例句。
- 语法与长难句默认各选最多 3 处，允许同一句结合讲解；必须提供原句、主干、修饰／从句关系和中文意思。用户选句讲解限定在选句所在段落上下文。
- 音标不是生成成功的必填项。缺少可信依据时省略或显示待核对，不承诺 AI 音标准确。
- 生词释义、讲解和额外练习例句均可编辑；原创练习例句标为“练习例句”，不能标为原文引用。

### 6 原文提取与长文处理

#### 6.1 提取策略

优先使用已配置来源的正文选择规则，其次尝试页面 `article`、`main` 等语义正文区域。不能稳定定位时不给出“全文已提取”，转为预览待核对或粘贴导入；不直接把整页去标签结果作为可信全文。

剔除导航、页脚、推荐列表、脚本与样式，保留标题层级、段落、列表、引用与表格中的必要文本。不执行网页脚本，不主动加载文章图片或附件。图表依赖但未保存的内容列出缺失说明，不能用正文摘要替代图表证据。

首版自动获取限公开 HTTPS HTML 页面；PDF、登录页面、动态加载正文、反爬与付费墙显示原因，允许保留链接或由用户粘贴可使用的正文。

网络边界作为“允许手动输入链接”所必需的实现内容：拒绝本机、私网、链路本地、云元数据地址和带凭证的 URL；解析域名及每次重定向均检查，实际连接目标不得因再次解析而落入受限网段。最多 3 次重定向，仅允许 HTTPS 公网目标。不安全链接可以作为纯文字记录，不能成为可点击执行或抓取入口。

默认连接超时 10 秒、单次获取总时限 30 秒、解压后响应上限 2 MiB；必须边接收边限额。粘贴正文与提取正文上限 200,000 字符，超限拒绝并提示分篇导入，不自动截断保存。上述限额均为本期产品边界，不声称覆盖任意长文。

#### 6.2 段落与生成预算

正文结构保存章节和段落块，每块有编号与内容哈希；编号在同一正文版本内稳定。文章编号、正文版本和段落编号共同构成引用地址。

翻译按相邻完整段落分批，默认每批正文不超过 6,000 字符，并同时符合模型上下文预算；超长单段按句子拆成子段，记录其父段，不遗漏或重复正文。术语表和必要相邻上下文单独标明，不重复计入目标覆盖。

长文总结先生成每批带段落出处的要点，再汇总为文章级总结；若任意必需分块失败，全文总结保持未完成。英语解析从正文分块提取候选，再按原句核对和去重，不只取文章开头。

单任务默认最多 40 次模型请求，总时限 900 秒，同时保留现有单次请求超时。创建前计算批次与汇总调用数量，超过上限则要求缩小范围；运行中到达上限停止，不自动追加预算。真实模型的上下文容量不足时进一步拆分或阻止，不用固定字符数假定一定放得下。

每个分块必须收到完整结束信号并通过结构校验，才可作为完成分块复用。同一原文哈希、生成类型、参数和提示版本下，明确重试可只重做缺失／失败部分；更换模型或解释偏好时新建草稿，不能混用旧结果冒充同一完整版本。

### 7 本地目录与数据保存规则

#### 7.1 目录布局

所有路径相对于 `/Volumes/Xiaohao/学习/`。继续使用现有文章资料和笔记目录，新增文件只在实际保存内容时创建。

```text
认知阅读/
├── README.md
├── 阅读偏好.md
├── 每日精选/YYYY/MM/YYYY-MM-DD-今日精选.md
├── 搜集记录/
├── 文章资料/article-ID/
│   ├── 文章信息.json
│   ├── 中文导读.md                   保留既有摘要导读
│   ├── 原文.md                       当前采用正文的可读镜像
│   ├── 中文翻译.md                   当前采用翻译，可明确为部分译文
│   ├── 详细总结.md                   当前采用总结，标明依据范围
│   ├── 英语学习.md                   当前采用英语解析
│   ├── 正文版本/v000001/
│   │   ├── 正文结构.json             段落、范围、哈希与缺失说明
│   │   └── 原文.md
│   └── 资料版本/translation-v000001/
│       ├── 内容.json                 结构化结果、原文引用、覆盖清单
│       └── 内容.md
├── 阅读笔记/article-ID.md            用户原话，保留原路径
└── 学习记录/
    ├── 文章/article-ID.json          阅读状态与状态事件
    ├── 生词/word-ID.json             词条与来源引用
    ├── 生词/word-ID.md               词条的可读镜像
    └── 复习/YYYY-MM/review-ID.json   不可重复追加的复习事件
```

资料类型前缀固定为 `translation`、`summary`、`english`，各自版本递增；示例目录只展示翻译，其他类型结构相同。目录、标题变化不改变稳定编号。当前文件是可直接阅读的镜像，旧版本目录不覆盖。

正文中的段落编号以可见段落标记保存，翻译每段保留相同编号与相对原文链接。正式 Markdown 均写明来源、原文版本、内容范围、生成或采用时间、AI标识及缺失说明；在平台之外阅读也不会把部分内容误当全文。

不把 API 密钥、带凭证地址、完整请求头写入资料、日志或导出。抓取的原始 HTML 不作为长期正式文件保存，正文预览只保留规范化文本与结构，避免存入页面脚本。

#### 7.2 身份与关联

已有 `article-` 加 20 位十六进制编号不变。带 URL 的新文章继续采用规范化 URL 的稳定哈希；仅移除明确的跟踪参数，不删除可能区分文章的查询参数。保存原始 URL、规范化 URL、经验证的重定向终点与别名；命中任何已验证别名时进入已有文章。

无 URL 的导入以随机导入身份生成同形编号，同一提交请求重放仍返回同一文章。以后补来源链接不改变编号；发现与另一篇重合时提示人工选择，不静默合并笔记和生词。

引用统一为 `article_id + source_version + block_id`，英语例句另存原句文本与哈希。生词和笔记引用历史正文时能够打开旧版。后续项目、任务只引用这些标识，不复制整篇资料。

#### 7.3 数据职责与最小模型

SQLite 保存权威状态、版本关系、草稿、任务、发布日志和复习事件。正文版本文件保存不可变的正文结构与可读文本；数据库保存路径和哈希，读取时核对。Markdown 是可阅读镜像，外部编辑必须经过显式核对导入，不做双向静默同步。

| 对象 | 关键字段与约束 |
|---|---|
| 文章 | id、标题、作者、来源、URL别名、语言、标签、归档、当前正文版本、各资料活动版本、schema_version、record_version |
| 正文版本 | source_version、正文哈希、获取方式与时间、内容范围、完整性依据、段落、缺失内容；采用后不可变 |
| 资料版本 | kind、artifact_version、source_version、原文哈希、目标段落与覆盖段落、模型、提示版本、生成参数、用量、采用时间；可区分手改与AI生成 |
| 生成任务 | job_id、幂等键、请求哈希、文章与正文快照、每批状态、预算、错误、取消与结束时间；ready 不等于 adopted |
| 个人阅读记录 | bookmarked、read_later、read、read_at、read_source_version、状态事件；不由生成任务修改 |
| 生词 | word_id、规范词形、语言、语境释义、多个来源引用、本人备注、复习阶段、到期日 |
| 复习事件 | review_id、word_id、用户反馈、发生时间、下次到期日、操作幂等键 |

扩展现有 `reading_records` 记录类型并增加 schema_version，保持与旧 `article`、`job`、`preferences` 记录兼容。索引或独立阅读表只在实际查询需要时增加，禁止纳入旧 `/api/data` 的整表覆盖链路。正式正文不再用 `full_content` 在文章记录与文件中反复双写。

用户状态修改、正文采用、资料采用使用独立字段更新与 record_version 校验；后台生成必须重新读取最新个人状态，不能用开始生成时的整条文章快照覆盖用户刚保存的笔记、加星或读完状态。

#### 7.4 发布与冲突恢复

保存顺序：校验请求和版本 → 取得短时写锁 → 核对当前文件哈希 → 持久化发布意图 → 写临时文件并替换 → 提交活动版本及关联状态 → 标记发布完成 → 页面显示“已保存”。网络抓取与模型生成不长时间占用文件写锁。

文件与数据库不是一个原子事务，必须复用现有发布日志恢复机制：重启后按旧／新哈希识别已完成步骤，同一操作重复执行不生成第二份版本或索引。未知哈希停止恢复并显示具体冲突，不能删除日志后继续覆盖。

用户在外部编辑当前原文时，平台提示“本地正文已变化”，可查看差异并导入成新版本；外部编辑译文或笔记时也需要核对。外部改动旧版本文件视为冲突，不自动修复引用。导入后保留旧版与外部修改快照。

数据库缺失不能只靠 Markdown 恢复全部草稿、任务和反馈；正式恢复以完整备份为准。只有 Markdown 时可以手动导入内容，不能恢复出不存在的已读和复习状态。

### 8 个人生词与基础复习

加入生词必须由本人点击。按规范词形与语言提示已存在词条，同词可保留多条语境释义和来源；不把不同语境自动覆盖为一个中文释义。

点击词条显示原句与原文位置，先隐藏释义，用户可选择“还不认识、模糊、记得”。本期采用简单可解释规则，不称为掌握度评估：

- 新加入词条次日到期；复习间隔序列为 1、3、7、14、30 天。
- “记得”：推进一档并按新档位计算下次日期，达到 30 天后保持该间隔。
- “模糊”：阶段不变，次日再看；“还不认识”：回到第一档，次日再看。
- 到期未复习持续保留，不自动算完成；用户可暂停或归档词条。

日期按北京时间计算，到期仅在“生词与复习”内显示。本期不添加系统通知、外部自动任务或统一日程事件。重复提交同一复习操作不得连续推进多个档位。

本人确认读完记录对应正文版本和时间，允许撤销；更新正文后保留历史读完记录，并显示“读完的是旧版”，不冒充新版本已读。阅读完成、译文生成、生词记得都不能推断课程已完成或能力已提升。

### 9 服务接口与改动范围

以下为计划接口；具体路由在实现时可沿现有命名微调，但不能改变产品行为或读写边界。

| 操作 | 计划接口 | 关键约束 |
|---|---|---|
| 文章筛选 | `GET /api/reading/articles` | 分页、筛选、元信息搜索；保持旧列表兼容 |
| 获取收藏预览 | `POST /api/reading/imports` | 类型为 url/text，返回持久化预览任务；不调用模型 |
| 采用收藏预览 | `POST /api/reading/imports/{id}/adopt` | 稳定编号、幂等键与正文哈希；已有文章需显式更新 |
| 旧文补充正文 | `POST /api/reading/articles/{id}/source-drafts` | 生成候选正文，采用仍走预览与版本保护 |
| 查看正文或历史版本 | `GET /api/reading/articles/{id}/sources/{version}` | 只读，不触发抓取或生成 |
| 生成资料 | `POST /api/reading/articles/{id}/generations` | 类型、正文版本、段落范围、解释偏好和预算 |
| 采用生成草稿 | `POST /api/reading/drafts/{id}/adopt` | 当前正文／资料版本及外部文件哈希校验 |
| 查看资料版本 | `GET /api/reading/articles/{id}/artifacts` | 同时返回覆盖范围和过期依据 |
| 笔记与个人状态 | 保留现有 `/articles/{id}/personal` | 增加版本保护，继续兼容旧字段 |
| 生词与复习 | `/api/reading/vocabulary`、`/api/reading/reviews` | 每条独立保存，复习事件幂等 |

继续使用现有任务查询与取消能力。旧 guide 接口保留摘要语义；旧 summary/english 接口修复上下文后作为新生成服务的适配入口，也必须遵循草稿预览采用规则，不能绕过新保存流程。

预计改动 `server/reading/`、`static/reading.js`、必要阅读样式及完整备份校验；正文提取、结构校验等职责可拆为该模块下的新文件。仅在确需挂接导航、备份或初始化时触及 `app.py`、`index.html`、`plans/backup.py`，不进行全站重构。更新使用文档在实现完成后进行，本次不把未实现方案写成现行使用说明。

## Risks / Trade-offs

### 10 风险与取舍

| 取舍或风险 | 处理方式 |
|---|---|
| 任意网页提取质量不可保证 | 已配置来源优先，通用提取仅作候选；保留预览、范围标记和粘贴兜底 |
| 全文翻译耗时与费用随长度增加 | 展示批次与范围；允许选段、取消和明确重试；预算耗尽停止 |
| 段落对齐不代表语义正确 | 机器检查覆盖，人工检查否定、数字、术语和观点；两类验收分开 |
| 文章内有诱导模型执行的文字 | 把正文作为资料数据，与系统要求隔离；不执行其指令、不据此访问链接或读取其他文件 |
| 外部文件编辑与平台保存冲突 | 版本与哈希检查，显式导入，保留恢复记录 |
| 归档后仍有词汇和笔记引用 | 归档只改变列表可见性，链接与版本可继续读取；首版不永久删除 |
| 扩展为第二套英语课程 | 文章资料维持一份，现有英文课程只在未来按编号引用，本期不复制课程 |

方案比较：仅扩充摘要 Prompt 最省事，但无法实现可靠全文阅读；另建阅读器会增加数据迁移与维护；本方案选择在现有认知阅读中补齐正文、生成、个人记录三条链路，复用平台基础。结构化结果与 Markdown 双份表达增加写入管理工作，但能同时支持可靠段落引用与独立本地阅读。

## Migration Plan

### 11 实施顺序和迁移

1. **用户确认方案**：确认本期范围与默认行为后才改代码；新依赖、真实收费调用另按明确授权执行。
2. **可靠收藏**：修复上下文和错误内容保存，完成正文预览、版本、旧文补存及原文视图；这一阶段不宣称双语精读已完成。
3. **双语精读**：实现生成预算、分段、校验、预览采用、五视图和异常恢复。
4. **学习沉淀**：完成笔记引用、生词和站内复习，保持与课程状态独立。
5. **场景验收与交付**：通过第 12 节检查后更新正式使用文档、提交验收记录；是否提交代码或部署须依用户当时的明确指令。

迁移前保存数据库与阅读目录一致性快照；扩展记录字段保持向后兼容。无正文旧文标为“仅摘要”，存在旧 `full_content` 的记录先保留原值和迁移快照；“内容获取失败”等占位文本不作为正文迁移，其他文本仅标待核对，不自动判为全文。已有原文文件与数据库不同则停止该篇迁移并报告，其他内容保留。

首次正式采用一篇新正文时再建立其版本目录。迁移不触发网络请求、生成请求、阅读完成或词汇复习。不改外部课程任务，不把 Markdown 生成数当学习完成数。

完整备份需覆盖数据库、整个认知阅读目录、正文与资料版本、生词及复习事件，并排除密钥。恢复前停止服务与其他写入方，校验清单与哈希，保留恢复前快照，再恢复数据库和文件作为一致版本。恢复后核对活动版本、段落引用与个人状态。

回退优先关闭新入口和新任务处理，保留增量数据与历史资料；旧代码若不兼容新 schema，不允许直接运行旧写入逻辑，可只读查看 Markdown。整库恢复必须明确检查同期其他学习记录，不能用旧数据库直接覆盖后续个人数据。

### 12 验收标准

以下均为待实施的验收要求，当前没有“已通过”结论。自动检查使用临时目录、临时数据库、模拟网页和模拟模型；真实来源、真实模型质量与浏览器操作单独留证。不得直接拿个人文章测试覆盖与恢复。

#### 12.1 固定样例与判断原则

使用自写或允许使用的材料：一篇 6 段中文正文；一篇 10 段英文正文，包含否定、数字、单位、专名、指代和从句；一篇超过 15,000 字符的长文；带导航与推荐内容的 HTML；仅摘要、付费提示、PDF链接；一份同段号但内容已改的新版本。网络类测试同时提供失败和重定向样例。

结构验收必须满足：目标翻译段落覆盖率 100% 才标完整；所有原文引用都存在于对应版本；无占位错误文本进入正式正文；重复请求没有重复文章、版本或复习事件。

人工语义验收检查英文样例全部 10 段，以及长文开头、中间、末尾与各分块边界；逐条核对总结关键观点和所有英语解析例句。不得有改变原义的否定、数字、单位或主体错误，不得出现伪造原句与证据。发现错误须修正并记录复查，不能靠“AI待核对”免除验收。

#### 12.2 逐项验收表

| 编号 | 场景与操作 | 通过标准 |
|---|---|---|
| A01 | 输入公开 HTML 链接，获取、编辑预览并保存 | 来源与段落可核对；保存后刷新、重启仍可读；只生成一个文章编号 |
| A02 | 粘贴正文，无作者或发布日期 | 可保存；缺失信息显示未知；段落与用户修订保留 |
| A03 | 同一 URL 带跟踪参数、已知别名、重复点击保存 | 定位同一文章，不重复目录、索引或版本 |
| A04 | 同样文字以两个不同无 URL 导入操作保存 | 提示可能重复但不静默合并；各自笔记独立；重放同一操作不重复 |
| A05 | 链接失败、仅摘要、付费提示、PDF、动态加载页 | 显示可操作原因与粘贴兜底；不写“内容获取失败”原文，不标全文 |
| A06 | 提取含导航、推荐、列表、引用的网页 | 正文段落与结构保留；干扰内容剔除，无法定位时标待核对；图表缺失可见 |
| A07 | 超过 2 MiB 响应、200,000 字符正文或获取时限 | 有界停止并提示；没有截断后冒充成功的正式原文 |
| A08 | 请求私网、本机、带凭证链接或跳转到受限地址 | 获取前或重定向连接前拒绝；不访问被拒目标；安全失败不影响旧资料 |
| A09 | 补存已有只有导读的文章 | 原编号、笔记、收藏、读完记录不变；新增正文版本且不重复推荐 |
| B01 | 中英文文章切换五视图，桌面及 375px 窄屏阅读 | 中文默认原文，英文逐段对应；窄屏无正文横向溢出；返回列表恢复筛选位置 |
| B02 | 完整英文样例生成逐段翻译 | 10 段全部对应；不存在遗漏、重复或未知段号；隐藏译文不删除数据 |
| B03 | 仅摘要、部分正文或待核对正文生成资料 | 可用操作符合范围表；结果保留范围标签，不出现无依据“全文”声明 |
| B04 | 长文生成翻译与总结 | 开头、中间和末尾都被覆盖；分块边界无丢句；汇总保留段落依据 |
| B05 | 检查译文中的否定、数字、单位、术语及主语 | 人工核对无改变原义的错误；记录使用模型、样例与实际缺陷 |
| B06 | 检查总结与英语解析 | 核心论据、引句有可用原文引用；释义符合语境；无伪造原句与证据 |
| B07 | 原文内容含要求忽略规则或访问其他数据的文字 | 仅当作正文处理；不读取个人笔记、其他文件或自行访问外部指令链接 |
| C01 | 生成前查看发送范围，刷新、切视图、重复提交 | 只发送已确认正文范围；不含笔记；一个幂等操作最多创建一个任务 |
| C02 | 缺模型配置、语言不符、正文缺失 | 在付费请求前明确拒绝；不创建无法执行的运行任务 |
| C03 | 超过预计请求数预算或总时限 | 创建前要求缩小范围，或运行中有界停止；不会自动追加费用请求 |
| C04 | 某翻译分块失败、输出少段、乱序或缺结束信号 | 校验后如实显示部分完成；不可显示完整；明确重试只补所需块 |
| C05 | 取消任务、离开页面、重启服务 | 旧正式资料保留；完成分块可恢复；没有自动重新计费 |
| C06 | 生成成功但未采用、编辑草稿后采用、重复采用 | 未采用只存草稿；采用后正式镜像与版本一致；重复采用只得到原结果 |
| C07 | 生成中原文被更新、草稿已过期 | 采用被阻止并提示重新核对；旧结果可查看对应旧原文 |
| C08 | 资料包翻译成功但总结失败 | 能单独采用已成功翻译；不生成伪完成总结；失败原因独立显示 |
| D01 | 外部编辑笔记、原文、译文后在页面保存 | 检测冲突；旧文与外部修改保留；显式导入才建立新版本 |
| D02 | 发布中断于文件替换前后、数据库提交前后 | 重启恢复为一致状态；不重复版本；未知哈希阻止覆盖 |
| D03 | 一边生成，一边加星或保存个人笔记 | 生成采用不回退个人状态；字段冲突明确返回，不用旧快照覆盖 |
| D04 | 无互联网但本地服务运行；服务停止后打开 Markdown | 可读已保存原文、译文和笔记；缺失网络资源有说明；不依赖外部字体或脚本读取正文 |
| D05 | 归档文章后查看旧笔记和生词来源，再恢复文章 | 引用仍可用，资料与版本不删除；恢复后出现在原筛选范围 |
| D06 | 完整备份后在隔离目录恢复 | 文件哈希、活动版本、笔记、生词、复习状态一致；备份无密钥 |
| E01 | 收藏、生成、阅读滚动到底或停留足够时间 | 不自动标记读完、课程完成或掌握 |
| E02 | 本人确认读完、撤销、随后更新正文 | 状态与历史事件正确；新版本不会冒充已读 |
| E03 | 加入同词不同语境、修改个人释义 | 来源与语境都保留；AI重新生成不会覆盖个人词条 |
| E04 | 次日到期、三种复习反馈、跨日与重复提交 | 按北京时间和规则排期；同一反馈只生效一次；未复习不自动完成 |
| F01 | 迁移摘要旧文与错误占位 `full_content` | 旧资料完整保留，错误占位不变正文；不调用网络、模型或修改学习状态 |
| F02 | 每日精选、旧导读、旧课程和原始导出回归 | 原入口和记录保持；每日任务不自动付费、不批量抓取全文；新表不受旧整表覆盖 |

#### 12.3 交付门槛与证据

每项记录“通过、失败、未验证”及样例、操作、结果；不能只勾选任务清单。所有数据丢失、重复计费请求、错误全文标识、引用错位和静默截断问题必须解决后才能宣称本期完成。

模拟测试只证明结构与异常处理；真实来源用于验证提取适配，真实模型用于验证语义质量、耗时与费用，浏览器用于验证实际操作和窄屏阅读。真实收费验证取得授权后再执行；未授权时明确标为未验证，不能把模拟结果代替实测。

验收记录最终保存于本变更目录的 `verification.md`，实施后才创建并填写实际结果。正式使用文档只描述已完成能力；本期不要求 Git 提交或推送。

## Open Questions

### 13 用户确认点

方案没有必须现在补填才能阅读的空项，默认选择已经在第 2 节明确。用户确认时重点核对：

1. 五个阅读视图及“获取预览 → 保存正文 → 生成草稿 → 采用资料”的流程是否符合日常习惯。
2. 第一版采用链接与粘贴正文，PDF、全文搜索和外部日历留到后续是否合适。
3. 是否接受每日精选保持轻量，全文补存与 AI 双语材料由本人按篇触发。
4. 生词复习是否按第 8 节的简单站内规则先落地。

确认本方案仅进入约定范围的实现阶段，不自动授权新增依赖、真实付费模型调用、对外发布、代码提交或推送。后续发现超出本方案的优化，先说明影响，再由用户决定是否纳入。
