## Context

`daily-learning.js` 汇总认知、英文/表达和新课程规划三路数据。原列表逐课渲染，`plans.js` 则单独管理规划与生成。学习事实仍以原完成接口为准。工作区存在并行投资开发，本次不改投资代码或切换其分支。

## Goals / Non-Goals

**Goals:** 课程卡片与三级导航；可靠分类；有界计划的真实分母；跨刷新/设备的最近课次；移动端可用。

**Non-Goals:** 新推荐算法、复习调度、正文改写、改变行动/学完统计、部署到远端。

## Decisions

1. **独立课程列表组件。** `course-library.js/css` 负责卡片、详情和课程状态；日常续学复用原列表与阅读行为，不在外层挂载每课行动控件。详情路由为 `#course/<课程键>`，支持刷新、浏览器返回，导航归属我的课程。列表筛选在页面会话中保留。
2. **只读汇总规划。** 计划列表补充当前正式 `curriculum`（目标、阶段、所有计划课次）及完成日期；不请求全部计划正文。完成计数只认正式目录内已发布且本人确认的课次。持续更新的三个原有模块分母为已发布课次，完成后显示“已学至最新”，仍留在学习中。
3. **分类与生命周期分开。** 正式计划全部完成进入已学完；无开始记录且无完成事实进入待学习；其余进入学习中。暂停/归档优先进入独立折叠区，绝不视作学完。失败来源不伪造空数据。
4. **私人续学记录。** 在学习资料路由同源保护下提供活动 GET/POST，账号 schema 内加法创建 `course_learning_activity`。仅保存课程键、首次开始时间、最近课号与时间，不存正文或学习完成。成功载入正文才记录，失败不阻止阅读但显示可重试提示；已有完成事实直接作为已开始依据。记录的课次若已完成则跳到最早未完成课次，若尚未完成则恢复最近课次。
5. **详情逐层展开。** 顶部目标、进度、当前阶段与主操作；阶段目录仅展开当前阶段，未发布课次显示待准备。规划、课程工具放在折叠面板，完整编辑沿用原计划详情。新建课程直接进入原创建表单；草稿、预算和生成记录归入“草稿与课程设置”。原 `#plans/*` 链接兼容。
6. **沿用设计变量与 DOM 安全。** 卡片使用现有色彩、按钮和原生 progress；筛选用可聚焦按钮和 aria-pressed；详情标题聚焦，加载、失败与空态有文字提示，长名称可换行。

## Risks / Trade-offs

- 历史未完成课程没有开始证据 → 初次显示待学习，首次成功阅读后转入学习中；不虚构历史时间。
- 当前已发布课次读完但正式目录未全部发布 → 保留学习中并显示“已学至最新”，可从课程工具准备后续资料。
- 续学接口不可用 → 保留完成事实分类，展示警告与重试，不将失败读取覆盖成已保存。
- 多端同时阅读 → 最近服务器接收的成功打开事件覆盖续学课次；首次开始时间不变，不修改完成证据。

## Migration Plan

账号首次访问活动接口时，在当前私人 schema 中幂等加表。无历史回填、无外部写入。回退前端及路由即可，私人活动表可保留。计划摘要为加法字段，原客户端兼容。

## Open Questions

无阻塞项；本版不为原有持续课程增加“整门结束”操作。
