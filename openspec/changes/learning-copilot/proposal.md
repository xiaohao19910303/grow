# 学习副驾驶（Learning Copilot）

## Why

当前项目已经有 `学习仪表盘/server/app.py`（FastAPI + SQLite）、前端页面、打卡与记录、JSON 导出、Markdown 知识扫描及周月报。本变更补齐“课程发现 → 生成草稿 → 预览编辑 → 确认保存 → 本人记录学习完成”的闭环，复用现有仪表盘，不另建应用、数据库或端口。

现有每日认知与通识课程已生成第001、002课，均未记录学习完成。课程文件采用“日期-第NNN课-主题.md”，每课有本地参考资料和学习记录条目。168课是该模块第一轮的规划规模，不是整个学习系统的总课数。

## What Changes

- 在现有仪表盘新增课程入口，一期仅支持 `renzhi`（每日认知与通识学习），其他模块行为保持不变。
- 发现并导入现有课程，识别重复、缺课、资料缺失和工作区不可访问，保留原文件名及个人笔记。
- 分开展示内容生成进度与本人确认的学习完成进度；分别展示待学课程和下一待生成课程。
- 从已确认的周主题规划及已核验的本地资料生成 Qwen 草稿，提供流式预览、多行编辑、重新生成和恢复草稿。
- 以”课程正文 + 参考资料 + 学习记录条目”为完整保存单位，支持重复请求去重、外部修改冲突检测、失败恢复和重新扫描。
- 实现自动学习完成检测：监控阅读行为（滚动到底部、停留时间），提供三种完成方式（回答复盘问题、写学习总结、快速完成），提交后自动标记完成并记录复盘内容。
- 明确现有每日生成流程与手动入口的共存约束；本变更不自动停用或改写已有自动任务。
- 备份课程、资料、学习记录与数据库；明确扫描重建只能恢复内容索引，不能凭空恢复学习反馈和生成日志。

## Capabilities

### New Capabilities

- `course-discovery`: 既有课程导入、完整性检查、周主题来源和课次推进。
- `course-generation`: 基于已核验资料的草稿生成、流式事件、编辑与质量校验。
- `course-persistence`: 完整课程保存、幂等、并发协调、恢复和备份。
- `learning-progress`: 内容与学习状态分离、今日任务、历史与本人反馈。
- `learning-completion`: 阅读监控、复盘与总结提交、自动打卡记录。

### Modified Capabilities

无现存 OpenSpec capability 需要修改；本次为已有应用增加上述能力。

## Scope

一期包含单模块、单用户、本地运行、Qwen 服务端调用、离线阅读既有课程、自动学习完成检测与记录。支持三种完成方式：回答复盘问题、写学习总结、快速完成。复用现有页面样式和运行环境；所需新增依赖须在实施前说明用途并获得用户明确同意，不在启动时自动安装。

不包含其他模块课程生成、自动联网搜集资料、模型切换界面、自动评估掌握程度、旧课程自动重写、云部署、多设备同步、完整版本管理、自动开启下一轮课程。现有每日课程频率不因本变更擅自调整。

## Impact

- 预期修改：`学习仪表盘/server/app.py`、`学习仪表盘/server/static/index.html`，按职责新增少量课程服务文件；必要时调整现有启动配置和使用文档。
- 数据：在现有 `学习仪表盘/server/data.db` 增量建表；不把课程表纳入 `/api/data` 的全量覆盖、清空或重置操作。
- 课程输出：沿用 `每日认知与通识学习/每日课程/`、`参考资料/`、`学习记录.md`，不迁移已有课程，不覆盖个人记录区。
- 对外调用：只有明确触发生成才调用 Qwen；API Key 仅保存在后端本地配置，不进入前端、日志或版本库。
- 自动任务：读取到的外部新增课程应可导入；跨进程互斥的强保证依赖所有写入方采用共同保存入口或锁协议。未接入的写入方必须在界面标明共存限制。

## Success Criteria

- 第001、002课被正确识别，生成进度为2/168，学习状态仍为”待本人记录”。
- 当日已有完整课程时默认展示该课程，不自动生成下一课；跨日沿完整课次推进，缺课和冲突先处理。
- 正常保存后课程、资料及索引一致；重复保存不重复写入，外部编辑不被静默覆盖，故障可恢复。
- 无网络或无 API Key 时仍可浏览本地课程、历史并记录学习反馈；生成入口说明不可用原因。
- 阅读课程后，系统能自动检测阅读完成（滚动到底部、停留时间达标），并提示用户选择完成方式（复盘问题、学习总结、快速完成）。
- 提交复盘或总结后，系统自动标记课程为 completed，记录完成时间、复盘内容和阅读时长。
- 学习进度与生成进度分别展示，可查看所有历史复盘记录和总结。
- 正式需求场景均可验证，旧仪表盘记录、导出和报告不受破坏。
- 首字延迟、完整生成耗时、实际 token 用量、生成失败率和人工确认率分别测量。原”10秒完成、95%成功、80%直接确认、每月不到1元”不作为未经验证的交付承诺；记录模型、样本数和重试次数后建立基线。

## Delivery Order

先完成既有内容导入与状态分离，再实现规划和资料校验、草稿生成，最后完成可靠保存与共存验收。开发耗时在上述边界验证后估算，不继续沿用原7/8天承诺。
