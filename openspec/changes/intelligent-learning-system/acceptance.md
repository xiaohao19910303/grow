## 2. 未来验收数据准备

后续获准实现与验证后，仅在隔离环境准备数据，不修改真实账号历史来模拟场景：

- 账号 A、B 使用不同私人 schema；二者可有相同课程标题、来源键和请求键。
- A 拥有认知第一轮、英语、表达、两个不同新计划的已完成课程；另有生成未确认、unknown、归档和只有行动勾选的课程。
- 准备同一正文的 V1/V2、可模拟不可用的来源、一个包含 120 条课程的分页来源。
- 使用可控服务端时间覆盖北京时间 23:59/00:00，验证进程时区为 UTC 时业务日期仍正确；不通过修改真实机器时区验收。
- 准备双设备或两个独立客户端、可模拟丢失响应/事务错误的隔离条件、空库与不兼容结构副本，以及可恢复的备份副本。

## 4. 页面人工验收

后续必须留存人工检查结果，不以接口成功推断页面可用：

- 候选和队列区分“已确认学习”和“本人复习评分”，能看到业务时区、下一日期和来源故障原因。
- 键盘可以选择课程、提交评分、关闭横幅；横幅不抢占编辑、不中断其他模块、不阻止离开页面。
- 分数冲突、来源变化、网络失败时文字草稿与评分选择仍在，未知结果可查回执，不暗中更换请求键。
- 同课新版确认有清楚的代次与历史提示；暂停项不会因刷新、新版或恢复网络而擅自启用。
- 登录过期/切换账号后不展示前账号的课程、草稿和横幅；旧课程阅读、笔记和行动操作可继续使用。

## 5. 证据和发布门槛

每个 A 编号的证据记录应包含：实现版本、隔离环境、执行时间和业务时区、输入来源身份、请求 key/revision、前后数据库状态、期望与实际结果、失败与未覆盖项；不得记录真实 API Key、密码或其他账号私人内容。

发布须同时满足：

1. `openspec validate intelligent-learning-system --strict` 通过，四份能力规格都有合法 delta、Requirement 和 Scenario，能力名称与提案一致。
2. A01～A23 的全部场景有实际通过证据；文档静态校验不替代业务场景验证。
3. 页面人工检查有结果；正式备份恢复与关闭入口回退演练有独立证据，不能仅声称表已入库。
4. 原课程完成、笔记、打卡、行动事实、日常节奏提醒和 AI 配置行为无本 change 引入的改写；所有开发任务按真实状态勾选。
5. 没有为了通过验收擅自启用后台任务、增加依赖或扩大首版范围。
