# 智能学习系统：首版复习闭环

> 版本：v1.1 · 2026-10-24 · 方案待实现。本次仅完善文档，不授权修改业务代码或执行迁移。

## Why

现有系统已有学习完成记录、行动执行、打卡和日常节奏，但缺少从“本人已确认学过”到“再次回顾并评分”的统一复习入口。首版先验证一个可恢复、可解释的复习闭环，避免同时建设统计、后台调度和 AI 推荐。

## What Changes

- 只读接入认知课程、英语/表达课程、新学习计划课程的已确认完成记录；生成、打开、停留和行动勾选不替代课程完成证据。
- 用户从已完成课程中明确选择“加入复习”；已有历史记录只作为候选，不自动批量导入。首版不实现“学习完成后自动入队”，后续需要单独设计开关和历史基线。
- 提供到期复习队列、课程跳转、本人 0–5 分回忆评分，以及确定性的下一次复习日期；评分不代表客观掌握程度。
- 提供默认关闭、用户开启后在页面前台检查的站内提醒；可关闭、可当天免打扰，跨页面和多设备请求去重。
- 所有新增记录留在当前账号的私人 PostgreSQL schema，采用版本化迁移、事务和幂等回执，不进入旧 `/api/data` 全量快照。

### 首版边界

| 纳入首版 | 后续另立 change，本期不实现 |
|---|---|
| 三路已确认课程来源、本人选课加入复习 | 全量历史自动入队、概念/习题级拆卡、文章/词汇复习 |
| 课程级复习、评分、暂停/恢复、内容变化后重新确认 | 自适应算法、客观掌握判定、弱点识别 |
| 前台站内提醒、持久化去重和用户偏好 | 后台扫描、APScheduler、Celery、Redis、浏览器推送、邮件/微信 |
| 沿用已有学习和行动事实，不改变原统计 | 新连续天数表、计划完成率、低于 60% 警告、计划调整表 |
| 无 AI 依赖的确定性规则 | AI 推荐、知识关联、自动周复盘；后续优先用户主动请求，沿用浏览器凭证 |

不再采用不可关闭弹窗、强制解释、23:59 自动替用户选择休息或暂停计划。不承诺原 v1.0 的 4–6 周工期、学习提升比例或 AI 成本。

## Capabilities

### New Capabilities

- `confirmed-learning-sources`：三路完成证据、课程身份、来源可用性和只读接入。
- `spaced-course-review`：明确加入、0–5 分复习、确定性间隔、事务幂等和复习生命周期。
- `foreground-review-reminders`：前台提醒、分类与规则分离、去重、关闭和当天免打扰。
- `private-review-storage`：账号隔离、加法迁移、恢复、旧快照边界和首版范围约束。

### Modified Capabilities

无。现有课程完成、打卡、行动执行、日常节奏和 AI 配置的行为要求保持原样；本 change 只增加独立复习能力。

## Impact

- 后续实现预计新增 `知行成长/server/learning_review/` 服务与路由，以及独立前端复习入口；在 `server/app.py` 注册，沿用 `accounts.py`、`tenancy.py`、`db.py` 的身份和连接路径。
- 只读调用 `copilot/`、`study_materials.py`、`plans/` 的权威完成记录与内容读取能力。`learning_checkins.py` 可作为三路来源核对参考，不把按日打卡当作某课完成记录。
- 新增复习项、评分事件、操作回执、提醒、偏好五张业务表及一张迁移版本表；不修改 `study_learning_records`，不新增 `mastery_score`。
- 无新增第三方依赖、模型供应商、部署服务或外部通知渠道；正式课程 Markdown 和私人学习笔记不被复习操作改写。
- 详细约定见 [design.md](design.md)，开发清单见 [tasks.md](tasks.md)，发布门槛与场景映射见 [acceptance.md](acceptance.md)。所有开发和运行验收目前均未执行。
