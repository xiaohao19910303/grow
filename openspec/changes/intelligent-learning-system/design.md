# 智能学习系统设计：首版复习闭环

> v1.1 · 2026-10-24 · 设计阶段。替代 v1.0 的四表迁移、强制教练和后台 AI 路线；本文件描述未来实现，不表示已落地。

## Context

当前系统是 FastAPI + PostgreSQL + 原生网页，正式内容与私人记录分开。已有能力和接入边界如下：

| 现有位置 | 已有职责 | 首版使用方式 |
|---|---|---|
| `知行成长/server/copilot/core.py`、`copilot/schema.py` | 认知课程、完成记录、归档、旧学习反馈 | 读取 `copilot_learning_records`，首版限定现有认知第一轮，不转换旧掌握等级 |
| `知行成长/server/study_materials.py` | 英语/表达课程、本人完成记录、内容版本、并发保存 | 读取 `study_learning_records` 与课程内容版本，不改完成提交接口 |
| `知行成长/server/plans/store.py`、`plans/api.py` | 新学习计划课程、反馈、内容发布 | 联查 `learning_feedback` 与已发布 `learning_lessons`，仅 `state=completed` 可选 |
| `知行成长/server/learning_checkins.py` | 三路完成记录的按日投影 | 参考来源覆盖，不使用聚合打卡反推某课学习完成 |
| `知行成长/server/rhythm/`、`action_plans.py` | 行动事实、休息/最小步骤、提醒领取、周统计 | 保持行为；借鉴事务和去重，不将行动完成当作课程已学 |
| `知行成长/server/accounts.py`、`tenancy.py`、`db.py` | 可信身份与私人 schema | 复用请求身份；新增服务必须在取连接前显式要求登录身份 |
| `知行成长/server/static/ai-config.js`、`copilot/ai_config.py` | 浏览器保存 AI 凭证，随请求提供 | 首版不调用 AI，不改变凭证归属 |
| `知行成长/server/legacy_state.py` | 旧全量状态保存 | 新复习表排除在该路径之外 |

根目录 `openspec/specs/` 当前无已归档能力正文；本次四个 specs 均为新增能力，不重写其他活动 change。

## Goals / Non-Goals

**Goals**

1. 从真实已完成课程中选择复习，形成“本人加入 → 到期 → 回顾 → 本人评分 → 下次到期”的闭环。
2. 多账号、重复请求、内容变化和进程重启时仍能解释数据来源、保留历史且避免重复推进。
3. 提醒只在网页前台出现，用户可以关闭或免打扰，不产生自动休息/暂停事实。
4. 不新增外部依赖；通过需求场景和发布门槛明确后续验证范围。

**Non-Goals**

- 后台定时任务、离线 AI、自动周复盘、推荐引擎、外部通知、强制弹窗。
- 新连续天数、计划完成率及阈值告警；不新建 `learning_streaks`、`learning_plan_adjustments`。
- 对所有旧记录自动入队；自动抽取知识点/练习/词汇；改变现有课程完成或行动状态。
- 从自评分数推断客观掌握、临床/心理结论或学习效果提升。

## Decisions

### D1. 三路只读来源，课程级身份

新增 `learning_review/sources.py`，复用现有课程和记录读取规则，输出课程候选及按标识查询的当前来源状态。不得另读未经授权的文件路径或按客户端提供的 schema 查库。

| `source_kind` | 稳定 `source_key` 的组成 | 资格证据 |
|---|---|---|
| `copilot` | `module_id + round_id + lesson_no` | 当前账号认知第一轮完成记录存在、未归档，课程可解析 |
| `study` | `module_id + filename` | 当前账号英语/表达完成记录存在，课程可解析 |
| `plan` | `plan_id + lesson_no` | 计划存在、课程已发布，当前反馈 `state=completed` |

组合键采用固定字段名和规范 JSON 编码后计算标识，避免直接拼接歧义；课名、日期、课号单独使用都不是唯一身份。同一课程关联多个行动仍是一个复习对象。正文版本使用权威读取结果的 SHA-256；新增复习项的 `source_kind`、`source_key` 唯一，不按标题合并跨计划课程。

只读列表按来源分页，每页最多 100 项，游标绑定账号、来源和排序键，不能用未签名游标中的账号信息授权。只在加入或回顾时按需读取正文，不在候选列表中逐课联网。旧 Markdown 中未完成/待反馈文本、生成任务、停留时长、旧 `copilot_feedback.mastery_level`、行动完成都不替代完成证据。

来源可用性作为每次读取/操作时的投影：`eligible`、`source_unconfirmed`、`source_missing`、`version_changed`、`source_unavailable`。失败不等于未学习；表缺失或某来源故障时返回分来源状态与明确“不完整”标记，其他来源可读，不展示全站完整数量。首版不尝试修复旧模块存储。

### D2. 明确选课加入，历史不自动灌入

用户打开候选列表，选择课程并确认加入；加入请求携带课程身份、已展示的正文版本、幂等键。服务端重新核验完成证据和版本，持久化一项，初始 `total_reviews=0`、`success_repetitions=0`、`ease_factor=2.5`、`interval_days=1`、`last_quality=NULL`，首次到期为加入日后一天的本地 00:00。

历史完成课程同样需要本人加入，首次到期从加入日计算，不从很久以前的完成日计算。重复加入返回同一项，不覆盖历史评分或提前到期。未来自动入队需要额外的明确开关、来源事件和启用基线，不包含在本期任务中。

### D3. 采用明确版本的 SM-2 派生规则

命名为 `sm2-course-v1`，用于整课自评调度，不声称完整复现 SM-2 的细粒度记忆项目与当日重复流程。参考 [SM-2 原始说明](https://www.super-memory.com/english/ol/sm2.htm)。评分 `quality` 为严格整数 0–5：0 完全不记得、1 几乎不记得、2 回忆有误、3 回忆正确但困难、4 稍有犹豫、5 回忆顺畅。它不写回任何旧掌握字段。

一次评分使用旧 `ease_factor=EF`、旧间隔 `I`、连续成功次数 `n`：

1. 对所有合法评分计算 `EF' = max(1.3, EF + 0.1 - (5-q) * (0.08 + (5-q) * 0.02))`，保留 4 位小数，恰逢中点时四舍五入。
2. `q < 3` 时 `n'=0`、`I'=1`；不将因子重置为 2.5。
3. `q >= 3` 时 `n'=n+1`；`n'=1` 时 `I'=1`，`n'=2` 时 `I'=6`，其余为 `ceil(I * EF)`，乘数使用本次更新前的 EF。
4. `total_reviews` 总计加一，与连续成功次数独立；记录本次分数、服务端提交时刻与前后状态。
5. 下次到期为本次评分的业务日期加 `I'` 天后的本地 00:00，不根据原计划到期日追赶，不修改历史评分。

首版业务时区固定 `Asia/Shanghai`，页面明确展示；不修改行动计划的既有时区。时刻统一为带时区值入库，服务端在业务时区计算日期，不用服务器裸 `date.today()`。首版不支持时区配置，未来更改须另定历史提醒与到期迁移规则。

数值验收：从初始状态连续三个 5 分，间隔为 `1, 6, 17` 天，EF 为 `2.6, 2.7, 2.8`。初始状态评分 0 后 EF 为 `1.7`、连续成功 0、间隔 1；下次到期评分 5 后连续成功 1、间隔仍为 1。允许采用十进制等价实现，但结果须符合以上舍入约定。

### D4. 生命周期与来源变化分开

复习项持久化状态仅 `active/paused`，到期由 `next_review_at <= server_now` 动态计算，不存永久 `completed/overdue`。一次评分成功只表示本轮已回顾，下一次到期仍能出现。

- 暂停停止队列和提醒；恢复保留原日期与算法参数，到期已过则重新进入队列，不自动算一次评分。
- 完成证据被撤销、认知课程被归档、课程被删除时，来源投影阻止评分并说明原因，历史不删除。证据恢复且正文同版后继续原调度，不重新加入或增加次数。
- 正文变化时显示“内容已更新，需重新确认”，禁止把旧页面评分写入新版。本人确认重新绑定当前正文后，保留旧代评分事件和累计 `total_reviews`，`generation` 加一，连续成功次数、EF、间隔和最近评分回到初始状态，首次到期从重新绑定日计算。暂停项重新绑定后仍为暂停。
- 暂时网络或存储故障显示不可用，不转为休息、未学习或永久暂停；恢复后继续使用既有记录。

### D5. 独立私人存储与原子提交

拟新增 `learning_review/schema.py`、`store.py`、`service.py`。五张业务表和一个迁移表均在请求身份对应的私人 schema 内：

| 表 | 主要字段和约束 |
|---|---|
| `learning_review_items` | `id`、`source_kind`（三值枚举）、规范 `source_key`、展示标题、`source_version`、`generation>=1`、`state`（active/paused）、`algorithm_version`、`first_learned_at`（可空，仅真实来源时间）、`enrolled_at`、`total_reviews>=0`、`success_repetitions>=0`、`ease_factor>=1.3`、`interval_days>=1`、`last_quality`（NULL 或整数 0–5）、`last_reviewed_at`、`next_review_at`、`revision>0`；唯一 `(source_kind,source_key)`，索引 `(state,next_review_at,id)` |
| `learning_review_events` | `id`、`item_id` 外键、`generation`、`quality`（整数 0–5）、`reviewed_at`、前后状态快照、正文版本、算法版本、请求键；只追加，不覆盖 |
| `learning_review_operations` | 请求键主键、操作类型、规范请求哈希、已提交结果、提交时间；加入、评分、暂停/恢复、重新绑定、偏好和提醒状态操作均使用 |
| `learning_notifications` | `id`、`category=review`、`rule_code=review_due`、`rule_version=1`、`business_date`、`timezone`、`dedupe_key` 唯一、`priority=low`、首次到期数量快照、`created_at`、`read_at`、`dismissed_at`；保留时间，不采集虚构响应原因 |
| `learning_review_preferences` | 固定单行标识、`reminder_enabled`（默认 false）、`muted_until`（可空带时区时刻）、`revision>0`；不存 API Key |
| `learning_review_migrations` | `version` 主键、`applied_at`；版本记录与 DDL 同事务提交 |

评分请求包含 `item_id`、`generation`、`expected_revision`、`source_version`、`quality`、`key`。执行顺序为：可信身份 → 账号范围幂等回放/键互斥 → 来源核验 → 行锁与 revision/到期核验 → 插入评分事件、更新调度、写操作结果 → 一次提交。外部正文读取设超时，不在数据库行锁内等待网络；进入事务后重新核验可用的来源记录与版本元数据，来源权威读取不能证明版本时拒绝评分，不伪造跨 GitHub 与数据库的分布式原子性。

同键同载荷重试先返回已提交回执，即使期间来源或到期状态已变；同键不同载荷 409。不同键同时提交同一 revision 仅一个成功，另一个 409；未到期、暂停、正文变动分别返回可解释冲突。数据库失败整笔回滚。客户端保留账号范围的评分草稿和稳定请求键，未知提交结果先查回执，不使用新键盲目重试。

所有新连接要求可信 `current_user`，不能因为其为空就调用默认连接访问 public；客户端不能指定账号、schema 或任意 action URL。非本人对象返回 404，不泄露存在性；登录过期按现有认证约定拒绝且无写入。

### D6. 前台刷新替代后台调度

首版没有进程内定时器、账号遍历、离线执行或额外 worker。前台进入复习区时读取队列；页面可见时每 60 秒最多检查一次，后台页停止检查，恢复可见后立即检查当前状态。跨日无需跑午夜任务，下次读取按服务端时刻算到期。

拟新增 API（均需登录；写操作沿用既有同源请求保护）：

| 路径 | 职责 |
|---|---|
| `GET /api/learning-review/sources?kind=...&cursor=...` | 分来源候选、游标与可用性，不建复习项 |
| `POST /api/learning-review/items` | 本人加入，校验来源身份和正文版本 |
| `GET /api/learning-review/items?view=due/all&cursor=...` | 分页队列、动态来源状态；只读，不自动发通知 |
| `POST /api/learning-review/items/{id}/score` | 原子评分与回执 |
| `POST /api/learning-review/items/{id}/state` | 本人暂停/恢复 |
| `POST /api/learning-review/items/{id}/rebind` | 本人重新确认新版正文并开启新代 |
| `GET/POST /api/learning-review/preferences` | 读取/更新开启提醒、当天免打扰；写入带 revision/key |
| `POST /api/learning-review/reminders/claim` | 前台重新核对到期项，创建或返回当天提醒；领取结果供横幅展示 |
| `GET /api/learning-review/notifications` | 当前账号提醒列表与动态有效性 |
| `POST /api/learning-review/notifications/{id}/state` | 本人已读/关闭，重复操作幂等 |
| `GET /api/learning-review/operations/{key}` | 查询本账号已提交回执；不存在表示尚无提交证明 |

列表响应标注数据时刻、业务时区、来源可用性；分页未完成不把当前页条数当总数。来源故障时禁止新建每日数量通知；已保存历史仍可查看并标记当前不可核验。首版不要求为其他账号无请求地运行迁移或读取数据。

### D7. 提醒的分类、去重和事实边界

只实现一个规则 `review_due`，分类 `review`，低优先级站内横幅和列表。类别与规则分别持久化并受枚举约束；不再使用 `streak_broken`、`plan_at_risk` 等未实现触发类型。

- 默认关闭提醒；未开启、当天免打扰、无合格到期项时，领取接口不创建通知。
- 去重键为 `review_due:v1:Asia/Shanghai:YYYY-MM-DD`，唯一约束置于私人 schema。同账号同日最多一条，首次插入者获得 `display_banner=true`，其他页/设备得到已有项和 `false`；不承诺浏览器一定展示成功。
- 已读不等于关闭；关闭后当天不能重新弹出。免打扰持久化至次日业务 00:00，并关闭当天横幅；不要求原因，不影响评分或学习记录。
- 历史通知保留创建时数量快照，明确为历史；当前横幅数量重新查询，归零则隐藏，不能用旧数量继续催促。第二天仍有到期项且允许提醒，可产生新的一条。
- 页面关闭期间没有通知送达承诺；再次打开只生成当前日通知，不补发错过几天的横幅。未响应仅表现为 `read_at/dismissed_at` 未设置，不写入休息、放弃、暂停或缺学原因。
- 与现有 rhythm 行动提醒使用不同规则空间，保留其偏好和领取键；新提醒只在复习区展示，不接入全站强制弹窗循环。

### D8. 统计和 AI 延后，保留现有事实口径

首版只展示经核验的到期数量、复习历史和下一日期，不新增学习连续性或计划完成率。未来做连续性时必须使用按业务日去重的本人活动事实；今天未学时展示截至昨天的连续长度与“今天待确认”，不能在午夜预先增加。

未来做完成率必须先确定分母为哪些安排实例，分子取这些实例中具备有效完成事实且未撤销的唯一实例；处理暂停、取消、补记、跨日和重复执行，零分母为 N/A，按计划/窗口分别存版本化结果，不覆盖同日其他计划。以上为后续准入约束，不是本期新统计实现任务。

AI 后续优先用户在前台主动触发，沿用自己的模型配置；缺凭证时保留规则功能。离线 AI 需要独立评审凭证保存与授权，不能直接硬编码 Claude 或改成服务端兜底 Key。

## Risks / Trade-offs

- [没有后台提醒] → 明确站内前台能力，首版不承诺 20:00 离线送达；降低调度和账号遍历风险。
- [整课评分粒度粗] → 明示为本人回忆评分，不承诺记忆保持率；先验证用户是否持续回顾。
- [来源版本不完整或故障] → 分来源降级、保留历史、拒绝不确定写入；不回填虚构完成时间或掌握分数。
- [多设备横幅只领取一次但显示可能丢失] → 以服务器持久化通知列表恢复，不反复重弹、不将领取当作已读。
- [未来规则变化] → 保存算法/通知规则版本，不默默重算旧事件；升级另做迁移评审。
- [存量规模未知] → 分页候选、到期索引、按需正文读取；实施时记录目标账号数据规模和响应证据后再定性能基线，不先承诺毫秒指标。

## Migration Plan

1. 仅在未来获准实现后创建上述模块、路由和表；本次不执行数据库连接、DDL、服务启动或业务测试。
2. 采用 `rhythm/schema.py` 的账号 schema 内加法迁移模式，锁名包含 `current_schema()`；DDL 和版本标记同事务。新账号与已有账号首次使用复习时分别初始化。
3. 无版本标记但存在同名业务表、版本高于服务端或已标记但缺表时，明确报错并保留原状，不自动 drop/覆盖修复；模块失败不阻断旧学习入口。
4. 只建空复习结构，不批量导入历史、不修改旧记录或 Markdown；本人加入后才创建复习项。
5. 发布前核实实际备份入口覆盖新增私人表和版本标记，并在隔离环境演练恢复、比对评分事件与回执；不得假设某一旧导出接口已覆盖新表。
6. 回退时先关闭新路由与入口，保留新表和版本数据。重新部署后按回执和现存调度继续；不得清空评分或回放额外评分。旧 `/api/data` 保存不得碰新表。
