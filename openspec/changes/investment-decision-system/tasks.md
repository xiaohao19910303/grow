## 3. P1 — 首版必需的盘后研究、理财建议与 AI

- [ ] 3.1 交付证券身份、规则与新鲜度服务。验收：市场/品种/有效时间/实施状态、交易日历与规则未知状态可查询，ETF不泛化T+0，日线缺失不填零，源单位保留且量额转换后才合并；实时权限不从普通积分推定。验证：历史规则变更、休市、停牌/未入库、过期/缺权限及日线手/千元到分钟股/元转换；依赖：1.2、2.4。拟文件：instruments、rules、freshness、provider adapter、测试。
- [ ] 3.2 交付自选与来源证据快照。验收：自选阶段可管理，公告/资料有定位、时点和哈希，旧分析能回到原证据，安全抓取约束成立。验证：重定向/私网/超大响应/指令注入、后发公告及重述；依赖：3.1。拟文件：evidence、sources、research API、研究视图、测试。
- [ ] 3.3 交付确定性指标和风险计算。验收：量价/波动、预算数量、已知费用、R基数及数据要求明确；缺失输入不计算，分批风险不可回写。验证：手算指标、价格精度、数量取整、超预算及跳空情景；依赖：3.1、2.6。拟文件：calculations、risk、计算合同、测试。
- [ ] 3.4 交付股票/ETF 结构化研究页。验收：短线/波段研究、公司风险与估值假设分开，ETF净值时差/流动性/组合影响可读；来源不足可见。验证：股票、ETF、数据不足三套真实页面流程；依赖：3.2、3.3。拟文件：research store/API、研究视图与样式、测试。
- [ ] 3.5 交付投资分析任务纵向切片。验收：目的地与发送预览、后台状态、取消、幂等、刷新恢复、重启中断、密钥不持久化。验证：模拟模型集成/HTTP/客户端回归及日志无秘密；依赖：3.2、3.4。拟文件：analysis jobs/API、任务中心 adapter、客户端、测试。
- [ ] 3.6 交付 AI 理财情景与资金政策草案。验收：基于已选财务范围比较方案、缺输入不猜比例、隐藏金额不算精确数量、亏损后不自动加风险。验证：教育模式/完整资料/约束冲突三个场景；依赖：3.3、3.5、2.2。拟文件：capital prompts、输出合同、分析视图、测试。
- [ ] 3.7 交付 AI 股票/ETF 深度分析与反证。验收：关键事实引用、计算绑定、支持/反对理由、情景/缺项、时点和版本都可追溯；不支持的数字不能成为核验事实。验证：过期数据、矛盾来源、财报发布晚于交易、虚构数字；依赖：3.3–3.5。拟文件：research prompts、report validation、报告视图、测试。
- [ ] 3.8 交付条件式建议与计划采用。验收：建议有触发/失效/期限/约束、采用生成草稿、另行确认，旧报告输入变动后失效标记，不改成交。验证：双击/重试/版本冲突/不可执行建议，盘后数据不冒充盘中；依赖：3.6、3.7、2.4。拟文件：recommendations、planning API、建议卡、测试。
- [ ] 3.9 交付 AI 复盘与思考原则。验收：对照原计划和事实生成可编辑候选，原话保留、行为标签本人确认、规则有反例及试验范围。验证：主观标签、一个亏损案例、引用失效、采用撤回；依赖：2.9、3.5、3.8。拟文件：review prompts、principles store/API、复盘视图、测试。
- [ ] 3.10 交付周/月统计与建议跟踪。验收：净结果/样本/开放仓位/费用完整性、R和未知状态准确，所有AI建议保留，影子结果不混入实盘。验证：小样本、零分母、未采用/未触发/无法判定、入出金和阶段边界样例；依赖：3.3、3.8、3.9。拟文件：metrics、evaluations、周期视图、测试。
- [ ] 3.11 接入 Grow 今日、搜索、时间线和行动引用。验收：引用有账号授权、动作幂等、默认无金额外发、不误写课程完成。验证：双账号引用、删除源、重复转行动、浏览器导航；依赖：3.9、3.10。拟文件：integration adapter、分批接入现有客户端、针对性测试；涉及超过5文件时按入口拆分。
- [ ] 3.12 完成完整首版端到端验收与使用验证方案。验收：资金政策→研究→AI反证→条件计划→分批成交→复盘→规则试验链可用；说明数据权限、未交付实时能力和费用。验证：受控真实模型/数据样例、移动/桌面真实浏览器、恢复/断网/隔离回归；依赖：2.11、3.1–3.11。拟文件：验收脚本、证据目录、使用文档、试用表。

P1 检查点：完整首版必须交付 AI 理财情景、股票/ETF研究、次日条件计划、复盘与采用追踪。以真实数据/模型核验为单独证据；模拟成功不能替代真实可用性。初步一个月仅观察流程、缺失率、耗时、计划覆盖、引用正确性和恢复；不可据此宣称收益改善。

## 5. 验证与交付口径

规划阶段仅运行 OpenSpec 结构校验与文档一致性检查，不执行真实交易、付费模型调用或购买数据。实施阶段每片先验证关键失败路径，再跑受影响模块及必要的账号/备份/既有stocks回归；通过后不重复扩大无关测试。

最终交付须报告：完成切片、数据/模型证据、已知缺失、开关状态和未交付能力。不要将 OpenSpec 的“工件完整”解释成代码已实现，也不要将历史曲线、少数盈利交易或模型自报信心解释为未来收益保证。
