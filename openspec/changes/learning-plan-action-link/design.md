## Context

已有学习规划、正式版本、逐课发布与本人学习反馈；`action_plans.schedule` 支持未安排的内容行动，并以来源回执完成，未安排／未来行动不能凭空完成。规划采用时大部分课程尚未发布，不能创建无效目标或强制日期。

## Goals / Non-Goals

Goals：新目录环境可复验；采用后一键关联；正式课程补齐；行动页整体／阶段进度；幂等、隔离及部分成功恢复。
Non-Goals：生成所有课程、自动排日期、推送／AI报告、跨端写入、改造计时／勾选完成规则、操作真实业务库。

## Decisions

1. `learning_action_links(id,data)` 位于账号schema，id引用已有learning_plans；JSON保留enabled及课号到行动ID的映射与来源标记。使用规划发布锁→行动写锁的固定顺序，关联及新增行动同事务；显式请求key及期望正式版本防止重复或旧页面覆盖。
2. 采用页“同时关联到行动”默认选中，可取消；旧规划详情可关联、同步、停止／恢复自动补入。只生成已发布且当前未学完课程的未安排content行动，不带提醒或假分钟。优先复用同目标现有非归档内容行动；已关联行动即使用户编辑或取消也不自动复制、复活或覆盖。
3. 提取既有schedule的同连接创建逻辑复用，保持来源校验、容量、业务去重和三态不变。阶段是学习规划追踪，不伪造带日期上级行动。
4. 规划／课程正式保存成功后调用已关联规划同步，数据源是PG已提交正式记录。同步失败返回独立learning_action_sync_error；不重发模型或再次发布。账本和已发布课程是重试依据，详情及行动页提供显式同步入口。GET进度不补项／改库。
5. 整体分母为当前正式规划全部课次，分子为已发布且反馈completed的课次，每课一次；按document.stage归组。草稿、生成成功、笔记和单纯行动分钟不计学完；已学完但未确认某项行动不补造执行事实。
6. 暂停／归档规划停止新补项，保留已有安排和执行，其暂停／日期仍由本人管理；恢复后可同步。停止自动补入只改账本开关，不删除已建行动。用户手动改动／取消的关联行动不被同步覆盖；明确显示关联已变化的状态。
7. pending/active跨端接管期间拒绝新增关联或补项，不回落Grow本地写入；读取仅展示学习进度及不可管理说明。原Zook合同与门禁不变。
8. 原账号仅校验配置存在性，不连接或改写业务库；新根`.venv`从锁定依赖重建，旧环境保留但不作为新启动入口。迁移后的临时PG、测试目录与Chrome承担功能验收。

## Risks / Trade-offs

- GitHub保存与行动非同事务 → 来源成功单独返回，补项幂等且可重试，禁止把同步错误当作发布失败。
- 课程学完与行动完成不同 → 分别展示，不把无日期行动补成过去执行或累计时间。
- 规划改版 → 已发布课次既有冻结合同保留，未发布课次仅更新阶段分母，不创建占位行动。
- 已有安排被用户改变 → 映射保留、不自动重建，并提供学习／行动入口核对。

## Migration Plan

关联表随现有plans初始化增量安装；旧账号／旧规划不自动关联，不迁移或改写已有记录。无连接端放行。回退需保留新增表和行动事实，不清表绕过；隔离验收后仅本地提交。
