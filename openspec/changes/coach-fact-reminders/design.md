## Context

现有 `collect_activity` 合并自动课程确认与旧分类记录，习惯补记与学习分类分别有明确口径。行动提醒已有 30 秒前台轮询、恢复可见时刷新、到时行动优先和节奏提醒。事实提示不应另建推送体系。

## Goals / Non-Goals

Goals：D1/D2，今日及成长总览自动显示一条当前账号事实，包含依据，支持收起和失败重试，无模型成本。
Non-Goals：D3 自动 AI 报告、强制学习量、数据造样本、服务端调度、浏览器／设备通知、长期能力判断。

## Decisions

1. `GET /api/coach-facts` 通过 `db.connect()` 读取当前账号 schema，事务为 repeatable-read/read-only；返回 `{date, timezone, uses_model:false, fact}`。沿用成长统计的北京时间，排除未来与无效日期。可选课程表尚未初始化时跳过，不写表或触发生成。
2. 规则顺序固定：前三个完整日（不含今天）各至少一条分类记录且数量严格递减 → 最近学完确认距今至少14天的课程 → 本周录入且已核对的有效预测至少5条 → 连续至少2天的学习／习惯活动记录 → 近7天活动事实／空态。每日分类数是每分类每日一次，非课数或投入时长。预测仅计 correct/incorrect，不作概率校准推断。
3. 课程候选复用计划反馈、认知课程确认、英文／表达学习记录；未完成反馈、已暂停／归档计划和归档认知课程不提醒。文案精确为“最近学完确认记录”，不推断没有线下复习。路径、标题均按文本处理，点击进入已有学习回顾。
4. 两个页内 section 共享控制器，同一时刻仅当前视图可见。复用既有行动提醒循环进行限频刷新（5分钟），到时行动提醒优先，恢复前台与跨日时更新。首屏读取独立于行动接口是否成功。导航和确认保存可主动更新，不新增定时器或系统通知。
5. 收起只保存账号与北京时间日期，不缓存事实正文；浏览器存储不可用时当前页面仍可收起，跨标签页同步同账号收起。响应晚到、账号变化或请求失败时不展示旧账号／旧日事实。数据故障提供“重试”，不伪造空态。
6. 普通表单自动保存只使快照失效，下一次前台循环或导航时读取，避免输入期间反复查询；明确学完可主动刷新，且事实读取不阻塞原完成反馈。

## Risks / Trade-offs

- 无复习日志 → 提示仅据最近确认记录，不承诺识别实际复习或能力变化。
- 记录减少不等于退步 → 三日必须均有正样本，只描述分类记录数量变化及日期。
- 分类与手工习惯可能重复 → 天数按现有统计合并；不合计时长，不声称课程数量。
- 固定北京时间并非个人行动时区 → 界面明确标注，沿用已有成长统计边界。
- 网络失败或重复轮询 → 单请求去重、超时、5分钟限频，保存期间的失效刷新在当前请求结束后补一次。

## Migration Plan

无数据库迁移和依赖变化。添加后端注册、两个静态挂载点与控制器接入后部署同一版本；回退时移除注册及静态接入即可，收起日期可自然失效。只在一次性 localhost PG 与合成账号中测试。
