# 投资模块：需要本人配置的项目

核对日期：2026-10-28。无需把密钥发到聊天、文档或Git中。页面的「配置与验收要求」和 `/api/investments/readiness` 同步列出程序要求；该接口不读取密钥，也不代表权限已验证。

## 本次最少需要准备什么

| 准备项 | 在哪里填写 | 是否必需 |
| --- | --- | --- |
| AI服务地址、API Key、准确模型ID | 设置中的「AI模型配置」 | 真实模型验收必需 |
| 一个已建立并选中的投资账户 | 投资工作台「新建账户」或当前账户下拉框 | AI界面要求先选账户；首轮无需授权发送金额 |
| 一个核对过名称、六位代码、市场、品种的沪深股票 | 投资工作台「添加标的」 | 个股与盘后数据验收必需 |
| 一份可核对的公告/财报原文摘录、链接、发布时间 | 「保存研究」；不要只填写URL | AI事实与反证验收必需 |
| AKShare东方财富、合法未复权日线CSV，或Tushare Token及`daily`权限 | 「添加盘后行情」选择对应方式 | 三者任选；AKShare无需Token，不能替代Tushare权限验收 |
| ETF标的，选择AKShare、合法ETF日线CSV或有`fund_daily`权限的Tushare | 同上 | 需要ETF能力时单独验收 |
| 可接受的模型费用上限、数据配额/用途/存储范围 | 在服务商控制台核对；费用上限不是本模块的自动限额开关 | 调用前由本人核对 |

先使用公开资料、关闭「同时发送金额」即可核对个股分析链路。资金政策情景和基于实际成交的复盘另行选择资料与金额范围，不是本次个股连通验收的前置条件。

## 不需要配置凭证的部分

手工记账、实际费用/基金确认、CSV、本地筛选、复盘、统计、原则试验，以及公开规则/休市日历参考均可独立使用。

公开参考目前仅覆盖沪深2026日历和部分竞价限价买入规则；规则生效从2026-07-06起，应用维护复核截至2026-11-27。该期限是应用维护要求，不是交易所规定的到期日。北交所、场外基金、未覆盖历史时期及ETF具体回转机制返回未知。它不提供实时停牌/ST/新股状态、涨跌停价、券商权限或实际可卖数量。

## 现在可以配置的AI

在「设置 → AI模型配置」填写以下三个字段，先保存，再自行选择是否测试连接：

| 字段 | 填什么 | 注意 |
| --- | --- | --- |
| API Base URL | 服务商提供的HTTPS OpenAI兼容API地址，保留其要求的路径 | 聊天网页地址不能使用；不在URL中放Key。后端会补充 `/chat/completions` |
| API Key | 本人服务商账户的API密钥 | 需对所选模型有调用权限和额度；不需要券商凭证 |
| 模型名称 | 服务商控制台可用模型的准确ID | 不是随意起名或聊天产品名称。需支持流式Chat Completions、足够的上下文和按提示输出JSON |

当前传输支持 `messages/model/stream`，没有模型工具调用或下单权限。配置保存在当前账号的当前浏览器；服务端仅在本次任务内存中使用密钥。换浏览器、清理站点数据需重新配置；不支持依赖浏览器密钥的无人值守定时AI。

保存配置不调用模型。「测试连接」产生一次短请求；每次投资分析目前含主分析和同模型反证两次请求，可能产生费用。配置额度/账单预算，并在「预览将发送的资料」中检查目的地与正文；关闭结构化金额仍可能留下正文中的金额。

不要求购买特定品牌模型。使用本人已经有权限、满足上述协议的模型即可。模型能连接不等于投资报告质量已验收；需要另核对事实引用、数字、反证和不确定性。2026-10-28已用本人配置的deepseek-v4-pro完成股票/ETF真实接口样例，范围与限制见[AI验收记录](investment-p1-ai-summary.md)。

本次本人选择本地`.env`验收，脚本临时读取 `AI_API_BASE_URL`、`AI_API_KEY`、`AI_MODEL_NAME` 并按请求传入接口，不记录Key。这没有给生产页面新增服务端环境变量回退；页面仍使用浏览器按账号保存的配置。

## 已接入的免费AKShare东方财富盘后行情

投资工作台「添加盘后行情 → AKShare / 东方财富」无需Token或积分。股票使用 `stock_zh_a_hist`，ETF使用 `fund_etf_hist_em`；服务端按根目录 `requirements.txt` 安装锁定依赖即可，AKShare版本固定为1.20.1。CSV和Tushare入口继续保留，不自动切换来源。

先选沪深股票或ETF，选择最多90个自然日的日期范围，核对资料使用范围后保存。默认日期覆盖最近约60个自然日、截至前一天；节假日以最后实际返回的交易日为准。仅使用未复权日线，成交量从手转换为股/份，成交额原单位为元，与Tushare千元口径区分；保存来源、版本、原始量额、获取时点和AI可选研究证据。没有自动全市场更新或盘中能力。

新入口依赖有效的本地公开日历参考，超出覆盖或维护复核期停止。15:30前不读取当日日线，该门槛不保证上游已更新。单次取数进程最多45秒；断连、超时、空数据或格式异常不保存新行情，不覆盖已有快照。请求失败后可手动重试；不会自动重试或绕过上游限制，也不会把失败解释为停牌。

2026-10-28真实HTTP样例已成功获取浦发银行、沪深300ETF、创业板ETF各35条日线（2026-09-01至2026-10-27），保存在一次性测试库后删除。也观察到股票和ETF请求被上游断开，平安银行样例未成功；因此仅标记部分样例取数/保存链路通过，未宣称稳定性或全市场验收完成。详见[数据来源与验证记录](investment-data-source-report.md)。

AKShare官方将接口及数据用途定位为学术研究；免费技术可接入不代表商业使用或再分发已获授权，需按本人用途核对上游使用范围。[官方说明](https://akshare.akfamily.xyz/introduction.html)

## 可选的Tushare盘后行情

在投资工作台「添加盘后行情 → Tushare Pro」按次填写Token和日期，选择日历依据，并确认本人用途。Token不保存到投资记录；失败不自动购买、轮询或重试。

| 需求 | 接口/配置 | 当前可用性与权限依据 |
| --- | --- | --- |
| 股票日线 | 本人Token + `daily`，日历选公开参考 | 不必为了日历再开`trade_cal`。官方当前说明最低120积分可免费试用；实际账号能否访问仍需本人核对。[daily说明](https://tushare.pro/document/2?doc_id=27) |
| ETF日线 | 同一Token + `fund_daily` | 官方当前说明至少5000积分；不从股票日线成功推定ETF可用。[fund_daily说明](https://tushare.pro/document/2?doc_id=127) |
| 供应商日历 | 选择「供应商日历」并有`trade_cal`权限 | 官方当前说明需2000积分；公开参考模式不会调用它。[trade_cal说明](https://tushare.pro/document/2?doc_id=26) |
| 个人用途 | 服务商允许的使用/存储范围、配额和到期日 | 技术取数成功不替代许可；个人使用与对外分发分别核验 |

上述积分为本次官方文档快照，权限变动以本人账号和最新文档为准，程序不按这些数值自行授予权限。这里不是购买建议；已有合法CSV来源可继续使用，不需要为现有记录功能购买行情。

公开日历模式仅在明确覆盖且未过维护复核期时使用，超范围直接停止，不自动改为请求供应商日历。选择供应商日历才会额外请求`trade_cal`。两种模式均不测试实时权限。日线量额按来源单位转换并保留原值，缺记录不推断停牌或补零。

本轮仍需本人配置后验收的结果：一个合法股票样例、按需一个ETF样例、接口权限失败/空数据/配额的脱敏结果、日期/单位与官方原始资料的核对。不要提供Token本身作为“权限证明”。

## 配置后的实际验收顺序

1. **确认标的身份。** 创建或选择一个沪深股票，核对六位代码、名称、市场、品种；ETF另选一个。新AI预览的 `instrument` 会展示这些信息，主分析和同模型反证使用同一份冻结快照。信息来自本人维护，不代表系统独立核验身份；历史报告不回填。
2. **确认模型可连接。** 保存三个配置字段后，主动点击「测试连接」。成功仅证明该次短请求可用；正式投资分析还要求模型能通过流式协议完整返回符合约定的JSON。服务商若截断输出、额外返回Markdown围栏或不兼容流式结束标记，分析仍可能失败。
3. **取得真实盘后数据。** 可先选择无需Token的「AKShare / 东方财富」。建议首次取最近30–60个自然日、截至上一个已完成交易日的资料，单次最多90个自然日；需要MA20及20次收益率波动时，至少要21条有效日线，停牌等缺记录不能补零。若使用Tushare，先选择「公开日历参考」，仅在覆盖有效时使用；ETF权限独立核对。
4. **核对数据口径。** 检查保存条数、最后数据日、来源、OHLC与供应商原始值。Tushare量额原单位为手/千元，程序转换为股或份/元；CSV必须按文件实际单位选择，且使用未复权日线。官方股票`daily`说明在交易日15–16点入库；程序15:30门槛不保证供应商已全部更新，验收当天数据宜待16点后再核对返回日期。[官方日线说明](https://tushare.pro/document/2?doc_id=27)
5. **用真实资料生成一份报告。** 保存一份带原文摘录和可获知时间的公告，打开「AI研究与建议」，选择该标的、刚保存的行情资料与公告，先不发送金额。资料截止时间应不早于这次行情导入和公告保存的可获知时间；预览完整正文、标的身份和模型目的地后，由本人确认发送。一次分析包含两次模型调用。
6. **核对报告及采用结果。** 逐条确认引用属于所选原文，日期、单位和数值正确，反对理由有依据，缺资料时明确保留不确定性。新行情摘要标明已保存/已展示/省略的条数与指标输入范围；例如保存35条、摘要展示20条，不等于源数据缺失15条，也不证明应有交易日齐全。新AI预览提供从正文原样提取的短引用提示；不能把11.2补成11.20，也不能把少量引用理解成只收到少量数据。触发与失效须写清公开资料/行情/本人记录、核对时点和判据；“查不到则等待”可以保留，“确认无未公开重大事项”不能作为采用前提。`investment-v4` 及后续版本会在第二轮终稿、建议采用、草稿新建/修改及旧草稿确认时拦截已知不可核验表述；这不替代本人核对条件语义和资料完整性。若产生条件交易建议，采用后只能形成对应标的的草稿；若仅建议继续研究，保存为思考也正常。未发送账户金额时，不应给个人精确仓位；真实成交复盘须另选交易链验证。
7. **验证恢复与失败边界。** 已提交任务刷新后能查看进度/结果；断网恢复后应先查看原任务，不盲目重复付费提交。记录实际遇到的缺权限、空数据或配额错误，未遇到的项目继续标记未验收，不为测试主动耗尽配额。

脱敏记录至少包含：日期、应用代码版本、供应商/模型ID、所选标的、数据范围、任务或报告ID、耗时、成功/错误状态、检查结果及已知限制。不要记录完整Key/Token或私人财务正文。真实验收记录应与模拟回归分开；一次成功不代表整套首版或长期分析质量已放行。

## 未来P2所需条件，当前不用急于配置

实时/分钟尚未接入适配器，即使提供Token也不会开放。需要先确定供应商、具体接口、股票/ETF覆盖、历史分钟范围、延迟/时区、断流行为、额度、用途/存储许可及来源单位；历史日线权限不等于分钟权限。[Tushare实时分钟官方入口](https://tushare.pro/document/2?doc_id=374)

回放/MAE/MFE需要与实际持有时段匹配的路径；回测还需要历史上市/退市与状态、公司行动/复权、费用/滑点、涨跌停/停牌及成交约束。拿到分钟Token本身不能补齐这些合同，不能据此声称回测或可成交提醒已完成。

不需要：券商登录密码、交易密码、短信验证码、自动下单授权。当前模块不连接券商执行交易。

新增「交易簿 → 导入分时路径/路径复盘」和「复盘与策略 → 新建前向试验/前向试验列表」均不需要Token或AI Key。前者需要本人提供来源合法、未复权且时间/单位明确的一分钟CSV，不会用日线伪造分钟；后者需要本人预先填写方案，读取当前私有账本。它们不代表自动分钟接口、样本外回测或实时提醒已交付。具体限制与验收见[离线续实施记录](investment-offline-review-20261028.md)。

## 离线条件演练续实施

「今日与计划 → 离线条件演练」无需Token、模型或系统通知权限。需先导入本人合法来源的一分钟CSV，并保存同一证券的日历/规则核对资料；价格阈值、有效期间、最长有效秒数、模拟延迟和提示范围由本人明确填写。退出条件的买入日和回转间隔只是声明假设，不能当作真实可卖量。选择本页提示也不发送实际通知；关闭网页后没有调度。[功能与验收范围](investment-condition-drill-20261028.md)。

真实实时适配、与计划/资金/持仓约束结合的核对、自动调度/通知，以及回测和样本外参数重跑仍需要代码开发，不能靠配置凭证自动补齐。1.2和3.12的真实账号/模型验收仍依前述清单执行；本轮没有发起外部请求。
