## 二、已实现的 AI 功能详解

### 2.1 AI 分析任务管理

**后端实现：** `investments/analysis.py`

```python
class InvestmentAnalysis:
    def preview(self, payload):
        """创建分析预览（选择证据、计划、复盘）"""
        
    async def submit(self, preview_id, snapshot_hash, ai_config, key):
        """提交分析任务"""
        
    def get(self, object_id):
        """获取分析任务状态"""
        
    def listing(self):
        """列出分析任务"""
        
    async def cancel(self, object_id):
        """取消分析任务"""
        
    def decide(self, object_id, index, state, note, key):
        """处理建议（采用/拒绝/保留）"""
```

**前端实现：** `static/investment-analysis.js`

- AI 分析对话框
- 选择分析目的
- 选择标的
- 选择证据、计划、复盘
- 预览发送内容
- 提交分析任务
- 查看分析结果
- 处理建议

### 2.2 四种分析类型

#### 1. 股票/ETF 研究（kind: 'research'）

**输入：**
- 研究资料（公告、财报、观察等）
- 标的信息
- 分析问题

**输出：**
- 分析摘要
- 事实摘录（引用证据）
- 推断与假设
- 反对理由
- 尚缺资料
- 可选下一步建议

**使用场景：**
- 分析某只股票的投资价值
- 评估公告对股价的影响
- 研究行业趋势

#### 2. 理财与资金情景（kind: 'capital'）

**输入：**
- 资金资料（收入、支出、负债等）
- 流动性需求
- 分析问题

**输出：**
- 资金用途比较
- 流动性分析
- 集中度风险提示
- 替代方案
- 调整建议

**使用场景：**
- 评估资金配置是否合理
- 分析流动性风险
- 制定资金政策

#### 3. 交易计划检查（kind: 'plan'）

**输入：**
- 交易计划
- 资金约束
- 持仓状态

**输出：**
- 冲突检测
- 遗漏提示
- 条件建议
- 风险评估

**使用场景：**
- 确认交易计划前检查
- 验证计划是否符合资金约束
- 发现潜在风险

#### 4. 复盘与规则试验（kind: 'review'）

**输入：**
- 事前快照（计划、理由）
- 实际事实（成交、结果）
- 复盘记录

**输出：**
- 判断评价（事前依据是否充分）
- 执行评价（是否按计划执行）
- 结果评价（盈亏与预期对比）
- 避免事后归因
- 下一项试验建议

**使用场景：**
- 盘后复盘
- 完整交易复盘
- 周/月复盘
- 策略试验评估

### 2.3 两阶段分析流程

**第一阶段：主分析**
- 使用选定资料进行分析
- 生成初步报告（draft）
- 包含摘要、事实、推断、反证、建议

**第二阶段：同模型反证检查**
- 使用同一模型对初稿进行反证
- 修正初稿中的问题
- 生成最终报告

**优势：**
- 避免单一视角的偏误
- 提高分析质量
- 明确标注为同一模型的反证，不声称独立专家共识

### 2.4 报告结构

```python
class Report(Contract):
    summary: str  # 分析摘要
    facts: list[Fact]  # 事实摘录（引用证据）
    inferences: list[str]  # 推断与假设
    counterarguments: list[str]  # 反对理由
    missing_inputs: list[str]  # 尚缺资料
    suggestions: list[Suggestion]  # 可选下一步建议
```

**Fact 结构：**
```python
class Fact(Contract):
    evidence_id: str  # 证据 ID
    quote: str  # 原文摘录
```

**Suggestion 结构：**
```python
class Suggestion(Contract):
    title: str  # 建议标题
    action: Literal['wait', 'research', 'conditional_entry', 'check_exit', 'observe', 'decline']
    reason: str  # 建议理由
    trigger: str  # 触发条件
    invalidation: str  # 失效条件
    valid_until: AwareDatetime  # 有效截至
    evidence_ids: list[str]  # 引用的证据 ID
```

### 2.5 建议处理

用户可以对接到的建议进行以下处理：

| 状态 | 说明 | 后续动作 |
|-----|------|---------|
| adopted | 采用 | 创建交易计划草稿或思考记录 |
| rejected | 拒绝 | 记录拒绝理由 |
| retained | 保留 | 稍后核对 |
| untriggered | 未触发 | 记录未触发原因 |
| unfilled | 无法成交 | 记录无法成交原因 |
| modified | 修改 | 记录修改内容 |

**采用建议的后续动作：**
- 如果建议是 `conditional_entry` 或 `check_exit`，创建交易计划草稿
- 否则，创建思考记录（复盘）

### 2.6 安全与合规

**证据绑定：**
- 只能引用选定的研究资料
- 事实摘录必须在原文中存在
- 建议只能引用范围内的资料

**时间戳验证：**
- 不能使用未来信息
- 资料可获得时间必须早于分析截止时间

**账号隔离：**
- 只能访问本账号的数据
- 建议只能用于本账号

**幂等请求：**
- 相同请求返回相同结果
- 避免重复付费

**AI 配置安全：**
- 密钥只在调用期间保留在内存
- 不进入任务/日志/报告
- 不承诺无人值守 AI

### 2.7 AI 配置

**支持的模型：**
- 通义千问（qwen_stream，默认）
- 其他 OpenAI 兼容模型（可配置）

**配置方式：**
- 前端：点击"配置个人模型"按钮
- 使用 `window.AISetup.open()` 打开配置界面
- 配置保存到浏览器本地

**调用流程：**
1. 用户选择资料和提出问题
2. 预览发送内容
3. 确认发送
4. 两阶段分析
5. 生成报告
6. 用户处理建议

## 五、P1 功能技术架构

### 5.1 后端架构

```
investments/
├── analysis.py  # AI 分析核心逻辑
│   ├── InvestmentAnalysis 类
│   │   ├── preview()  # 创建预览
│   │   ├── submit()  # 提交任务
│   │   ├── get()  # 获取状态
│   │   ├── listing()  # 列出任务
│   │   ├── cancel()  # 取消任务
│   │   ├── decide()  # 处理建议
│   │   └── run()  # 执行分析
│   ├── Report 类  # 报告结构
│   ├── Fact 类  # 事实结构
│   └── Suggestion 类  # 建议结构
└── api.py  # HTTP API
    ├── POST /analysis/preview  # 创建预览
    ├── POST /analysis/jobs  # 提交任务
    ├── GET /analysis/jobs/{id}  # 获取状态
    ├── POST /analysis/jobs/{id}/cancel  # 取消任务
    └── POST /analysis/jobs/{id}/suggestions/{index}/decision  # 处理建议
```

### 5.2 前端架构

```
static/
├── investment-analysis.js  # AI 分析界面
│   ├── open()  # 打开分析对话框
│   ├── showJob()  # 显示分析结果
│   ├── reportHTML()  # 渲染报告
│   └── decide()  # 处理建议
├── ai-config.js  # AI 配置
└── ai-setup.js  # AI 配置界面
```

### 5.3 AI 调用流程

```
1. 用户选择资料和问题
   ↓
2. 调用 /analysis/preview 创建预览
   ↓
3. 用户预览并确认
   ↓
4. 调用 /analysis/jobs 提交任务
   ↓
5. 后端调用 AI 模型（第一阶段：主分析）
   ↓
6. 后端调用 AI 模型（第二阶段：反证检查）
   ↓
7. 生成最终报告
   ↓
8. 用户查看报告并处理建议
```

## 六、P1 功能待改进项

### 6.1 已知限制

1. **数据源限制：**
   - 尚未集成实时行情
   - 需要手动保存研究资料
   - 不能自动获取公告和财报

2. **AI 模型限制：**
   - 默认使用通义千问
   - 需要用户配置个人模型
   - 分析质量依赖模型能力

3. **功能限制：**
   - 不支持批量分析
   - 不支持历史分析对比
   - 不支持自定义报告模板

### 6.2 改进建议

1. **集成数据源：**
   - 集成 Tushare 或其他数据源
   - 自动获取行情、公告、财报
   - 减少手动输入

2. **增强 AI 能力：**
   - 支持多模型对比
   - 支持自定义 Prompt
   - 支持分析历史记录

3. **改进用户体验：**
   - 支持批量分析
   - 支持历史分析对比
   - 支持自定义报告模板
