## 根因与边界

真实调用`stock_zh_a_spot_em`及`stock_zh_a_hist`，东方财富特定请求报ProxyError/RemoteDisconnected；本机还存在系统代理，即使相关环境变量为空requests也会读取macOS代理设置。独立直连同一上游仍复现连接中断，不能把问题只归于代理或依赖缺失。小范围探针偶尔200不代表完整接口可用。当前证据不足以区分具体上游临时限制和链路策略，不声称已修复东方财富服务端。

同一锁定版本`stock_zh_a_spot_tx`真实返回5577只沪深京证券。原应用仅接东方财富，且把网络、依赖、格式错误都归为provider_unavailable，用户没有明确选择其他AKShare上游的路径。

官方参考：[东方财富实现](https://raw.githubusercontent.com/akfamily/akshare/main/akshare/stock/quote/stock_hist_em.py)、[腾讯全市场实现](https://raw.githubusercontent.com/akfamily/akshare/main/akshare/stock/quote/stock_zh_a_tx.py)、[腾讯日线实现](https://raw.githubusercontent.com/akfamily/akshare/main/akshare/stock/quote/stock_hist_tx.py)。第三方main会演进，以本机锁定版本和当前源码哈希为复验依据。

## 修复

- 研究工具增加明确的腾讯／东方财富选项。新页面初始选腾讯；API省略source时仍按旧合同选择东方财富，原幂等指纹和缓存语义保持兼容，不在失败后自动切换。
- 腾讯全市场通过AKShare原函数读取；成交量手→股、成交额万元→元、市值亿元→元，全部Decimal转换。保留实际上游、原单位、抓取时间及适配版本，不把参考交易日称为已验证的逐笔时间。
- 腾讯`pe_ttm`单列TTM市盈率，动态`pe`仍未知，避免混淆估值口径；支持已有5／10／20／60日来源字段。
- 腾讯股票日线使用AKShare兼容的固定腾讯协议，直接从原始字符串做Decimal单位转换，避免锁定库先转float导致金额误差。主板／创业板成交量手→股，688科创板保留原始股数；金额万元→元。只支持明确的沪深股票日线；ETF、分钟、北交所须明确选择其他支持的入口或CSV。
- 日线接口可能忽略所选日期返回640条，适配器按明确起止日期裁取；不发送额外起始年探测或替代端点请求。输入缺交易规则仍只支持回放，不补造回测条件。
- 工作进程内关闭东财分页助手的自动重试，单次请求先检查HTTP状态；网络、依赖、超时、429限流和格式变化分别反馈。异常仅返回固定分类和类名，不返回认证URL或凭证。
