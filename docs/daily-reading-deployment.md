# 每日阅读部署

“今日 → 今日阅读”始终显示；阅读主题由服务端返回，包含认知、科技、经济学、社会学、心理和成长。

云端沿用 PostgreSQL 保存偏好、任务、索引和个人状态，GitHub 保存正式阅读正文。日任务不调用付费模型。

Render 免费实例会休眠，因此 `.github/workflows/daily-reading.yml` 在北京时间 10:00 触发搜集，10:20、10:40 作为恢复检查。GitHub 的定时运行可能有延迟；服务启动后也会补当日任务。电脑和浏览器无需保持开启。

工作流使用 GitHub OIDC 短期身份凭证，无需保存网站密码或长期密钥。服务端核验 GitHub 签名、有效期、受众、固定仓库 ID、main 分支和工作流文件。该身份仅授权 `/api/reading/scheduled-run` 的触发和最小状态查询，不授予文章、笔记或其他接口权限。凭证不进入 URL 和日志；原用户仍可通过网站认证查询和重试。

成功任务当日不重复搜集。失败记录保留，至少等待 15 分钟后可重试，同一天最多 3 次尝试。工作流等待实际保存完成，失败会显示在 Actions 和页面的搜集记录中。

选文优先兼顾尚未覆盖的已选主题，再兼顾不同来源及语言。若经典目录已经读完，混合模式可用符合日期条件的新文章补足数量；不足时仍明确提示，不用重复文章凑数。

暂停每日搜集或调整时间、数量、主题仍使用“阅读偏好与来源”。当前外部触发时间覆盖每天 10:00，修改为其他时间时需同步调整工作流；后台仅在所选时间之后执行。

打开英文文章的「中文导读」页签时自动生成中文导读可在“阅读偏好与来源”中开关，使用当前账号在当前浏览器保存的个人 AI 配置；生成后保存并复用。导读包括核心观点、证据与边界、英文阅读提示及应用问题，明确区分保存原文片段与来源摘要。缺少配置时可继续阅读已有内容。

每篇文章的“阅读反馈”可记录价值、难度、收获、疑问、行动和标签；支持按这些内容搜索与筛选有反馈的文章。私人反馈留在账号数据库，与笔记一起受版本保护；不会发布到 GitHub 或发给模型。选文使用日任务编号确定随机顺序，同一任务重试保持一致；最近反馈温和影响主题排序，同时保留主题覆盖和探索。


### 在本站阅读已搜集文章

进入「今日 → 今日阅读 → 已搜集文章」，点击「本站阅读」，默认打开文章正文。尚未保存的结果单独显示在「待保存的搜集结果」，可点击「查看并保存」，展开「本站预览正文」。来源网页链接收在文章末尾的来源信息中。

旧文章首次打开正文时自动补取；HTML 使用正文提取并保留段落，PDF 提取可读文字。正文经现有发布日志保存到当前账号的 GitHub 内容仓库，私人笔记和完成状态继续留在账号自己的 PostgreSQL 数据中。加载期间切换笔记页签不会清空输入，刷新可复用已保存正文或观察尚在运行的加载任务。正文加载不需要个人模型配置，也不会调用模型。

访问限制、付费墙或网络错误会显示失败原因和「重新加载正文」。来源摘要明确标注为摘要，不冒充正文；失败不会替换已有正文。刷新失败文章不会自动重复请求。抓取仅访问经 DNS 验证的公开地址，连接固定到所验证的 IP，每次重定向重新校验，限制响应大小和时间。HTML/PDF 超出正文上限时不会静默截断。

验证：`test_reading_content.py`、`test_reading_site_browser.py`、`test_reading_growth_browser.py`、`test_legacy_cloud_browser.py`；浏览器验收需设置 `RUN_LEGACY_BROWSER=1`，数据库使用隔离的测试 PostgreSQL。

正文任务的创建、数据库读写与 GitHub 发布在工作线程执行，避免远端保存阻塞 ASGI 健康检查。`test_reading_responsiveness.py` 在模拟慢发布时验证健康检查与任务查询仍可响应。
