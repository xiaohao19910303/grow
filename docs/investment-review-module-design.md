## 一、范围与文档职责

### 1.1 用户目标与当前基础

面向用户已确认的「A 股与国内基金／ETF优先、短线交易与波段复盘为主」，将理财资金计划、股票研究、交易计划、实际记录和复盘连接起来。

Grow 当前为 FastAPI + PostgreSQL + 原生 JavaScript/CSS，保留「今日、行动、学习、记录、成长」五个主栏目。代码已有 `知行成长/server/stocks/` 和「记录 → 专题记录 → 投资复盘」入口，能够保存操作、理由及结果；它不是完整成交账本，旧盈亏不能直接视为经过对账的真实收益。

本功能从该入口升级为「投资工作台」，复用阅读、笔记、知识图谱、决策、行动与账号隔离。投资学习作为现有学习体系的专题，不再建设一套独立学习进度与知识库。

项目相关文件仅在 `/Volumes/肖豪/project` 当前项目中定位。历史方案提到的独立交易项目、TradingAgents、dailyStock 和用户 Tushare 权限均未在本次修订中核验；不作为首版依赖，也不据此承诺可复用代码或可用接口。

### 1.2 文档与规格的分工

- 本文保存产品流程、设计决策、数据边界和审查修正依据。
- [OpenSpec 提案](../openspec/changes/investment-decision-system/proposal.md)界定完整交付范围。
- [详细设计](../openspec/changes/investment-decision-system/design.md)补充工程决策；[五组规格](../openspec/changes/investment-decision-system/specs/)是行为验收依据。
- [实施任务](../openspec/changes/investment-decision-system/tasks.md)是唯一任务清单，本文不维护另一份按周排期。
- 产品边界或核算规则变化时必须同步相关规格与任务，再进入相应实现；文档完整不代表代码交付。

### 1.3 首版目标

完整首版为 P0 + P1：既交付资金计划和可信交易记录，也交付 AI 理财情景、股票／ETF研究、条件建议与复盘。P0 是内部可用里程碑，不能仅上线日志就宣布完成。

P2 在数据权限、时效与交易约束验收后扩展盘中提醒、分钟回放、系统回测和全市场筛选。用户在券商自行执行，模型工具限于研究、计算、记录和草稿。

## 二、主流程与三个页面

```mermaid
flowchart LR
    A[资金边界] --> B[自选研究与反证]
    B --> C[确认事前计划]
    C --> D[实际成交或主动放弃]
    D --> E[对照复盘]
    E --> F[一项规则试验]
    F --> B
```

### 2.1 今日与计划

展示交易日／休市状态、资料截止时间、待核对持仓、本人确认的计划和待复盘事项。月预算、周计划、单标的计划在页内切换，研究作为抽屉或详情展开。

盘前先检查现有风险，再从本人自选中选择少量需要研究的标的。默认允许等待、放弃和今天不交易；行情波动不自动生成每日必买清单。

### 2.2 交易簿

展示实际现金、成交、持仓和完整交易链。支持手工快速记、CSV 导入预览、费用补充、分批进出、核对差异与审计更正。

委托、条件触发、实际成交、模拟结果分别保存。成交事实可以先记录，理由可后补并标注时间；不能因没有计划而阻止如实记账。

### 2.3 复盘与策略

页内切换盘后、完整交易、周／月复盘；策略、思考笔记、AI 建议跟踪按需展开。保存一分钟原话，深入整理可选。

桌面采用列表与详情并排，移动端单列。手机布局纳入首版验收。研究从自选、计划或成交详情进入，不另设独立首页和第二套导航。

## 三、投入计划与复盘节奏

| 周期 | 计划／检查 | 复盘输出 |
| --- | --- | --- |
| 首次建立，季度或生活变化时复核 | 资金用途、收入稳定性、近期用钱、负债、损失承受能力 | 资金政策与风险边界 |
| 每自然月 | 拟入金／取款、现金缓冲、交易资金和风险检查线 | 净结果、资金偏差、回撤、费用与耗时 |
| 每交易周 | 允许策略、关注事件、持仓安排、观察名单 | 保留／观察／暂停的方法及下一项试验 |
| 每交易日盘前 | 新事实、可卖数量、原计划有效性 | 今日条件清单，可不交易 |
| 决策／成交当时 | 触发、失效、风险、实际成交和偏离 | 带时间的计划与事实 |
| 每交易日盘后 | 核对成交、持仓与计划差异 | 一句话总结及明日待核对事项 |
| 完整交易结束或复核日到达 | 逻辑、执行、结果、退出 | 一项可检验改进 |
| 公告／停复牌／规则或逻辑变化 | 相关计划是否仍成立 | 专项检查与调整草稿 |

使用 Asia/Shanghai 与经核验的交易日历；交易日、自然日和自然月显式区分。计划保存有效截至、预计持有交易日、最晚复核日和提前失效条件。到期提醒意味着需要检查，不自动要求卖出；跨周持仓延续同一交易链与风险记录。

盘前／盘后各 5–10 分钟、周复盘 20–30 分钟仅作为交互负担目标，可关闭或调整，不作为每日必须使用的指标。

### 3.1 资金政策与理财建议

区分生活备用、近期支出、长期目标和交易资金。风险意愿与实际损失承受能力分别记录，资料不足时提供教育说明与缺项，不猜配置比例。

月政策保存：期初交易净资产、拟入／出金、现金缓冲、单笔风险预算、日／周亏损检查线、总持仓与同板块暴露限制、允许策略及暂停新增风险状态。比例和金额由本人提供或在补齐资料后比较多个情景，不写死统一仓位建议。

计划投入、实际入金、买入金额、持仓市值和计划风险分别展示。亏损不自动触发追加投入或提高风险。暂停新增风险仍允许管理持仓、补录事实和查阅记录。

AI 可比较现金流、负债成本、流动性、费用、集中度与长期目标，给出依据、替代方案和调整后影响。隐藏绝对金额时可分析比例，不能生成依赖未知资本的精确买入数量。

## 四、交易模型与核算约定

### 4.1 事实、计划与结果分离

以下是拟建逻辑对象，准确字段／API 在实施任务 1.1 冻结；本表不是可直接执行的数据库迁移。

| 对象 | 最少需要保存的事实／关系 |
| --- | --- |
| 投资账户 | 账号归属、币种、基准日期、期初现金／持仓及成本核对状态 |
| 资金流水 | 入金／出金／分红／利息／费用类型、金额、发生和到账时间、来源 |
| 策略版本 | 适用环境、必须／排除条件、退出规则、验证范围、确认时间 |
| 交易计划版本 | 账户、标的、策略版本、触发／失效、有效期、预算、风险快照、是否事后补记 |
| 实际成交 | 账户、证券身份、方向、成交时间、价格、数量、实际费用税、来源及外部编号 |
| 完整交易链 campaign | 一次投资逻辑的开始／结束、计划引用、成交分配、持有与复核状态 |
| 研究证据／报告 | 来源定位、资料时点、输入快照、计算／模型版本、结论与反证 |
| 建议与复盘 | 采用／拒绝／未触发／无法成交、对应版本、结果、下一项试验 |
| 审计更正 | 原记录、冲销／更正关系、操作者与时间、重算结果 |

同一股票在不同时期可对应不同策略，不能仅按股票代码合并历史交易。首版同一账户、同一证券同一时点仅允许一条进行中的完整交易链，支持其内分批进出；同时持有不同策略底仓／短线仓的独立损益分配暂不开放。多策略并存须先定义成本分配和账户对账规格，不能通过复制持仓实现；不同真实账户分别记账。

实际成交、现金、持仓变动与审计记录在同一数据库事务中提交。历史不完整可从经核对的期初持仓开始，未知成本标未知，不补造历史成交或零成本收益。

### 4.2 精度、单位与时间

- Python 核算使用 `Decimal`，PostgreSQL 使用 `NUMERIC`；API 金额、价格和数量以十进制字符串传输，JavaScript 不用二进制浮点累计资金。
- 合同初始候选采用价格／数量 `NUMERIC(28,10)`，金额 `NUMERIC(28,10)`；实施时结合来源范围确认。入库不统一舍入到两位小数，超过合同精度必须拒绝或显式处理，不能静默截断。
- 证券规则另存 tick_size、数量单位／步长和生效版本；显示精度与计算精度分开，实际币种金额的记账舍入和尾差分配方法固定并披露。
- 场外基金支持小数份额和净值精度。实际成交原价与分析复权价格分开，不用复权价重写成交账。
- 适配器先归一化源单位并保存原值与单位。Tushare 日线文档的成交量单位为手、成交额为千元，实时分钟文档为股和元；不能直接混用。
- 时间使用带时区的时间戳，界面按 Asia/Shanghai 展示；成交、记录、确认、资料发布和抓取时间分别保存。
- 未知费用为缺失状态，不能自动当作零并显示精确净收益。

### 4.3 成本与收益计算

首版人民币、做多股票／场内ETF按账户和证券使用移动加权平均成本核算经济盈亏：买入费用计入成本，卖出费用从卖出收入扣除；部分卖出按当时加权成本分配。尾差留在剩余持仓，最终清仓归零。此口径不代表税务申报或与所有券商显示一致。

资金核对至少满足：期末现金＝期初现金＋外部入金－外部出金－买入支出＋卖出净收入＋分红利息－未在成交中计入的其他费用。现金流水与成交派生项有来源关联，同一笔费用不得双计。

手算验收例（人民币、无其他费用与入出金）：

| 事件 | 数量／金额 | 结果 |
| --- | --- | --- |
| 期初现金 | 10000.00 | 现金 10000.00 |
| 买入 100 股，价格 10，费用 1 | 支出 1001.00 | 成本 1001.00，持仓 100 |
| 再买入 100 股，价格 12，费用 1 | 支出 1201.00 | 总成本 2202.00，持仓 200，均价 11.01 |
| 卖出 50 股，价格 13，费用 1 | 净收入 649.00 | 分配成本 550.50，已实现净盈亏 98.50 |
| 剩余 150 股，以 12 估值 | 市值 1800.00 | 成本 1651.50，浮动盈亏 148.50 |
| 核对 | 现金 8447.00＋市值 1800.00 | 总资产 10247.00，净变化 247.00＝98.50＋148.50 |

缺费用／成本／估值时明确显示未完整。外部入出金不是投资收益；已实现与浮动分开。分红、拆合份额和其他公司行动须有可核验事件与重算规则，缺支持时提示待核对，不静默沿用旧数量。

统计胜率以完整已结束交易链为单位，盈／亏／平分开；未触发、主动放弃、模拟记录和开放仓位不混入已实现胜率，开放风险另列。周期范围、归属口径、策略版本和样本数可见。

XIRR、TWR、现金流调整后的净值回撤需要相应现金流与估值序列，数据不足不硬算；XIRR无解／多解和短期年化应说明。与基准比较需匹配币种、期间、费用、分红及现金流口径。

### 4.4 场外基金与更正

场外基金分别记录申购申请、确认日期／净值／份额、赎回申请／确认、费用与实际到账。未知净值不推定成交，待到账不推定可用现金。

CSV 先预览、逐行校验和去重后提交，重复导入幂等；同一外部编号的不同内容进入冲突核对。修改成交通过可追溯更正重算，不覆盖原事实。券商确认事实即使与本系统规则判断冲突，也可如实录入并标待核对。

## 五、事前计划与交易约束

可快速保存理由草稿；确认可执行计划前必须具备证券身份、账户、策略／依据、触发／失效、预算、期限和足够新的数据与规则。

资金约束先于具体建议。程序在入场价、失效价和费用／滑点假设下计算预算内数量，再检查可用现金、持仓／行业暴露、数量步长、账户权限、可卖批次、停复牌、价格限制和有效期。

交易制度按市场、板块、证券类型、交易日、生效时间及实际实施状态核验，不将所有ETF视为同一机制。可卖数量同时依赖账户实际持仓／批次；信息不齐只能标待核验。停牌、价格限制、排队、跳空与交收限制可能使退出失败，计划止损估算不是最大损失保证。

确认策略／计划版本保留不可变快照；首笔成交绑定当时计划与初始风险。变更追加版本、理由及生效时间，事后补记单独标注；放宽失效条件不能改写原来的风险分母。R倍数使用已冻结的风险基数，分批加仓先确认新增风险、保留各次基数；无有效基数不算R。

## 六、AI研究、建议与复盘

### 6.1 六类工作与输出

| AI工作 | 输入与输出 |
| --- | --- |
| 理财情景 | 选定资金资料 → 用途、流动性、集中度与费用比较，形成可编辑政策草案 |
| 市场／板块摘要 | 自选／持仓相关的新事实 → 变化、相关性与待核对事项 |
| 股票／ETF研究 | 行情、公告、财务和规则 → 支持理由、反证、情景与缺项 |
| 计划检查 | 确认前计划＋程序校验 → 冲突、遗漏与条件建议 |
| 复盘教练 | 事前快照＋实际事实 → 判断、执行、结果分别评价 |
| 策略试验 | 多个案例与反例 → 事先冻结条件、期限和评价办法 |

流程固定为：发送预览 → 取数核验 → 程序计算 → AI主分析 → 反证检查 → 输出校验 → 本人采用／修改／拒绝 → 后续验证。

主分析与反证可使用同一模型分步完成，明确不是独立专家意见或校准后的成功概率。金额、仓位、盈亏与指标由程序核算；模型补充的数字必须标为假设，不能混入核验事实。

### 6.2 股票／ETF分析框架

分析分别覆盖市场与板块、量价与流动性、公告与催化、财务风险、波段估值假设、可成交性和组合影响。证据不足的模块标明缺失，不为了填满报告编造结论。

ETF增加跟踪标的、费用、流动性、净值时点、折溢价与底层持仓重叠；不同时间的价格与NAV／iNAV不能直接解释为可交易套利。估值方法须适配品种和财务状态，盈利为负时不能机械给出PE结论。

历史习惯作为待检验信号，不自动当成推荐偏好；热点与技术条件仅为研究线索，不直接解释为未来收益或“主力意图”。第一版从本人自选和持仓研究开始。

### 6.3 可追溯建议卡

每份报告记录：市场截止时间、证据／输入快照、策略／计划／规则版本、计算版本、模型与提示模板版本。每项重要事实引用原文位置或计算结果。

建议卡包含适用账户／策略、理由、支持与反对证据、触发条件、失效条件、有效截至、资金／交易约束、风险假设和缺失项。支持等待、进一步研究、条件满足后评估入场、检查退出方案和不参与。

用户采用建议只生成关联计划草稿，计划确认是另一显式动作。报告不会直接改成交或转移资金。资料变化后旧报告标过期，不能继续当作当前建议。

### 6.4 复盘避免事后归因

评估卖出是否合理，应比较当时已知资料、事前退出规则和实际执行；后续上涨仅作为注明期限的观察，不能单独证明卖错。没有事前规则则标为依据不足，不补造“原本应该怎样”。

周一胜率、追涨等模式显示样本数、筛选条件、行情环境和成本，作为候选假设；少于30个完整交易默认提示探索性，达到30也不是有效性的证明。心理标签需本人确认，不从单笔结果诊断心理。

AI建议分别追踪预测质量、计划质量、实际执行和净结果／耗时；保留未采用、未触发、无法成交、撤回及无法判定。影子结果标模拟、不代表可成交，不混入实盘资金。少数盈利案例不能证明AI提高收益。

### 6.5 任务与费用

复用本人浏览器AI配置、账号身份与任务中心交互，新增投资任务类型；AI配置本身不提供行情或联网能力。发送前展示模型目的地与实际选定内容，可删减或隐藏绝对金额。

同请求幂等、结果按输入快照缓存、支持取消和刷新恢复；重启标中断，不自动重复付费。AI密钥只在调用期间保留内存，不进入任务／日志／报告。浏览器持有凭证时不承诺无人值守AI，定时取行情与定时调用模型分别设计。

轻量核验优先程序与缓存；深度分析本人主动触发，显示资料覆盖与成本说明；不采用“每次筛选自动分析Top10”的默认付费策略。

## 七、数据来源、时效与安全

### 7.1 能力分级

| 模式 | 可交付 | 限制 |
| --- | --- | --- |
| 手工／导入 | 记账、预算、历史资料研究 | 日期和来源可见，不声称最新行情 |
| P1盘后 | 次日条件计划、波段研究、盘后复盘 | 数据未齐标未完成，不冒充当前盘中状态 |
| P2分钟／实时 | 时效与规则合格后核对盘中条件、回放 | 断流／延迟超阈值降级，暂停当前条件判断 |

每条资料保存来源、原始定位／哈希、统计期、作用时间、对外可获知时间、抓取时间与许可标签。历史复盘只把当时已公开的信息作为当时可知依据，并区分系统当时是否已读取；之后公告或重述不得倒灌历史。

日线新鲜度按交易日历与供应商入库完成情况判断；无记录需区分未入库、缺覆盖和已核验停牌，不能填零。前后复权与未复权口径分别标注，防止未来因子污染历史检验。

### 7.2 供应商核验

Tushare为盘后候选，不声明账号已有全部权限。实施前逐项核验股票／ETF／基金、指数／板块、公告、复权、交易日历与状态规则，以及限额、费用、许可和失败响应。

官方文档将历史日线与实时分钟分成不同接口；A股 `rt_min` 需要单独开通权限。历史分钟、ETF分钟与实时能力分别核验。提高历史日线轮询频率不会产生实时数据；没有权限时相关入口关闭，普通记录仍可用。

公告优先交易所、巨潮、基金管理人原文。AKShare或其他接口仅为候选适配器，不把可访问网页视为可稳定调用或可再分发的授权。缓存／共享数据的范围按供应商许可确定。

### 7.3 私人数据与权限

私人资金、成交、策略、笔记和报告保存于当前部署的PostgreSQL账号隔离空间，数据库可在本机或远端，不承诺始终不出本机。私人资料不进入GitHub正式课程仓库。

业务服务通过现有 `tenancy.scoped` 与 `db.connect()` 获取可信账号上下文，不能接受客户端指定schema。列表、详情、后台任务、缓存、搜索、引用、导入、导出与附件下载全部执行同一账号授权；不依靠前端隐藏实现隔离。

不自动将资金详情加入通用成长AI报告。日志和任务不存明文密钥；数据商凭证使用受管秘密，不能复用AI密钥。外部资料作不可信数据，校验URL／重定向／私网目标／体积，报告安全渲染，模型没有下单或转账工具。

局部导出明确范围，全量备份覆盖新表、版本和引用，密钥单独管理；隔离空库恢复须核对余额、持仓、来源哈希与版本。删除／归档需说明对历史核算、引用和备份保留的影响，未定义前不提供一键破坏账本历史的删除动作。

## 八、架构复用与旧数据过渡

新领域代码拟放 `知行成长/server/investments/`，由现有 `app.py` 注册；不另建 `server/app/` 应用树。前端使用现有静态入口与子视图，图表库先验证K线、体积和渲染安全再选择，不无条件新增pandas、TA-Lib或其他依赖。

| 已有能力 | 复用边界 |
| --- | --- |
| stocks | 保留旧接口与记录，提供来源和人工核对后的幂等关联 |
| 账号／数据库 | 延续服务端schema隔离与同源写保护，投资任务继承可信上下文 |
| AI配置／任务中心 | 复用配置和交互；独立适配投资任务，非直接复用课程kind |
| 阅读／学习笔记／知识图谱 | 关联已有资料与稳定ID，投资思考作为专题，不另造学习状态表 |
| 决策／行动／周期复盘 | 本人选择后创建稳定引用；重复操作幂等，不复制第二份交易事实 |

旧股票记录保留原始数值，缺历史成本／分笔／费用时标历史估算，不纳入新账本净收益。旧卖出价与后续价格的差额不是已实现收益。只有本人核对充分事实后才建立新账本关联，重跑不重复导入。

外部交易项目仅在找到当前目录、读取适用规则、审查代码／许可／测试后选择性复用。不得从历史路径自动搬入数据库、凭证、定时脚本或交易执行逻辑。

## 九、交付顺序与验证门槛

| 阶段 | 完整使用路径 | 放行条件 |
| --- | --- | --- |
| P0内部里程碑 | 账户与资金政策 → 策略／计划 → 实际成交 → 持仓核对 → 复盘 | 精度、分批核算、幂等、版本、账号隔离、备份恢复通过；无AI可使用 |
| P1完整首版 | 自选研究 → AI事实／反证 → 条件计划 → 采用与执行 → AI复盘／建议跟踪 | 供应商覆盖与许可、来源时点、真实模型样例、移动／桌面、任务恢复通过 |
| P2按能力扩展 | 分钟回放、约束回测、盘中提醒、全市场筛选 | 真实时效／断流、历史规则、可成交性与模拟边界分别验证 |

不再承诺未估算资源和数据依赖的“2–3周”排期。各项按唯一实施任务切片，每片交付可验证路径；市场排行榜与全市场筛选后置，先验证个人投资流程。

回测须保留历史样本／退市证券、当时可知资料、复权时点、T+1等制度、限价／停牌、费用／滑点／成交量约束。同K线止盈止损先后不明时保守处理或标无法判定，不能挑有利路径。参数先冻结，再样本外和前向观察；失败试验不删除。

### 9.1 必须覆盖的验收案例

| 案例 | 预期 |
| --- | --- |
| 两次买入、部分卖出及费用 | 与4.3手算例一致，现金／成本／盈亏可核对 |
| ETF价格1.231到1.234，10000份 | 价差收益30元，费用另计；不得舍成同价 |
| 小数份额基金尚未确认／到账 | 精度保留，不虚增持仓／现金 |
| 重复CSV、外部编号冲突、更正 | 幂等、冲突可恢复、审计和重算准确 |
| 首版同账户同证券试图新开第二条并行交易链 | 提示先关联既有链或保留研究草稿，不复制真实仓位 |
| 数据未入库／停牌／节假日／延迟 | 状态可区分，不补零、不误称实时 |
| 公告晚于决策／原计划事后补录 | 不进入事前依据，不伪称按计划执行 |
| 原计划退出后继续上涨 | 分开评价过程与后续走势，不直接判卖错 |
| 无规则／费用／成本等关键资料 | 对应可执行／净收益结论标未核验 |
| 异账号读取、缓存或导出 | 不返回私有对象或敏感存在性信息 |
| 刷新／取消／重启AI任务 | 恢复原任务、保留进度、不自动重复付费 |
| 旧stocks与备份恢复 | 原值保留，历史估算不污染新账，恢复后版本和余额一致 |

### 9.2 成功指标

先记录基线，再通过至少一个完整月的自愿使用观察流程；一个月不能证明策略或AI带来超额收益。

关注成交核对差异、事前计划覆盖、复盘覆盖、引用正确／缺失率、重复调用率、恢复成功、记录耗时和本人确认的规则偏离。每个指标显示分母、期间和采集来源，未核验资料标未知。

不把停留时长、每日交易数、连续使用或每周知识阅读次数作为成功目标。资金结果结合费用、回撤、持仓风险与时间成本观察；用户感觉有帮助作为主观反馈单列。
