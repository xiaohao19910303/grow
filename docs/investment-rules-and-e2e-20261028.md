## 无付费权限的自动核对

新增 `rules.py` 公开参考服务，版本 `cn-auction-20261028-v1`。公开事实人工核验后随代码版本发布，程序自动对照；运行时不抓取任意网页，也不声称自动追踪所有交易所修订。

| 范围 | 交付 |
| --- | --- |
| 身份 | 市场+代码+品种共同选择候选规则；代码前缀不能独立证明上市身份，明确保留未知字段 |
| 规则子集 | 沪深主板、创业板、科创板竞价限价买入的价格单位、最低数量、递增单位、单笔上限；股票买入后的卖出延迟参考。ETF仅通用报价/数量，回转机制未知 |
| 生效/实施 | 2026-07-06起的已实施子集；此前历史规则缺失返回未知。核对了上交所暂缓条文，不把暂缓事项当已实施 |
| 维护 | 2026-10-28核对，2026-11-27为应用维护期限；过期不沿用自动标记 |
| 日历 | 沪深2026年度休市通知，包括节假日和调休周末；其他市场/年份未知，不借用沪深代替北交所 |
| 阻止错误确认 | 股票误填T+0、报价单位/数量单位冲突、休市日误填开市等阻止条件计划确认；实际已发生成交不受阻 |
| 计算冻结 | 确认时保存规则/日历对照和哈希；持有期及最早可卖日须在核对覆盖内，数量受限价单笔上限约束 |
| 数据新鲜度 | 无记录、过期、最近完成开市日、未来/当日未完成、覆盖未知分开；日线始终不是实时，缺行不推断停牌 |
| 单位 | CSV和供应商共用精确转换，原始手/千元保留，转换为股份/元；未知单位不猜、缺值不补零 |

全日日线采用15:30后的保守接收门槛，避免把盘后窗口未结束的当日数据当完整日线；供应商仍可能尚未入库。手工保存15点竞价收盘价用于未来条件计划的原路径保留，其口径不等同完整日线。

页面「核对日历与交易规则」可「自动填入公开规则与日历」，不会代填收盘价格、不会把状态设为正常、不会替本人勾选确认。ETF未知机制须查具体文件后填入。服务始终不承诺立即可交易或实际可卖数量。

Tushare取数新增显式日历选择：公开参考覆盖内直接使用本地日历，只请求所需日线，解除对`trade_cal`的强制依赖；无覆盖/过期直接停止。选择供应商日历才调用`trade_cal`，不自动切换、不伪称未调用接口的权限已验收。

## 接口

- `GET /api/investments/calendar?market=SSE&start=2026-10-01&end=2026-10-08`：最长370日，超覆盖返回未知。
- `GET /api/investments/instruments/{id}/rules?on=2026-10-28`：参考规则、来源、实施状态、有效/复核日期、未知项及哈希。
- `GET /api/investments/instruments/{id}/data-status`：最新保存快照的新鲜度；未核验来源真实性，不发起取数。
- `GET /api/investments/readiness`：配置与验收条件，无密钥。
- `POST /provider/daily` 增加 `calendar_mode=public_reference|provider`；HTTP默认公开参考，原内部调用默认供应商模式以保留旧合同。
- `plan-checks.rulebook_id` 为可选自动参考标识；确认仍重新核对当前版本/期限，不能靠客户端标记绕过检查。

所有接口沿用登录租户隔离及no-store，写入沿用版本、同源与幂等约束。
