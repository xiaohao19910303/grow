# 日常节奏首版实施与验收

日期：2026-10-23。R05–R19 已实现并通过集成与全仓验收。R20、R21 保留原计划的后续开放门槛。功能默认关闭，未在业务库运行迁移或开启试用。

## 使用入口

1. 设置 → 日常节奏：自愿开启，默认每周3天、提醒关闭。首次设置立即生效；以后目标、时区和周回顾星期下周生效。
2. 今日 → 今日一件事：选择当天行动，或新建待办后选择；计时/课程行动也可沿用原新建表单。新建成功、选择失败时保留已建行动，重试仅补选择。
3. 今天轻一点：确认具体最小步骤。time/content 复用既有起步执行；check 必须明确确认做过这一步，仅新增零分钟的 partial 事实，完整待办保持未完成。休息不删除已有事实。
4. 执行结束可选填收获、卡点或结果及下一步；未填写仍保存执行。记录 → 执行记录可补填或修改；文章和课程完成后，有关联执行回执才出现可关闭的总结入口。
5. 成长 → 周期复盘 → 周/月汇总：顶部单列自然周行动成果，最多选三条成果和一项调整，可关联今天/未来行动。旧习惯周报继续分别统计。
6. 设置可主动加入两周试用、填写到期的D7/D14问卷、导出个人节奏JSON。关闭功能后，新节奏写入口和提醒关闭，已有事实仍可读、可导出。

仍使用现有五张节奏业务表，schema version维持1；本轮扩展JSON字段，无第二份总结正文。写请求仍为行动协议 `X-Grow-Action-Schema: 2`。总结历史在原 execution JSON中；周卡确认保存当时记录、统计和修订，不在GET时自动确认。

新增接口除开发计划所列外，还有：

- `GET /api/action-plans/rhythm/executions/{id}`：本账号执行及同一行动、同日已有总结的引用。后补来源完成无需复制一份总结。
- `GET /api/action-plans/rhythm/trial`：当前入组和 `trial_report`，避免被既有传输层误当成AI生成任务。
- `POST /api/action-plans/rhythm/reminder-claim`：前台循环调用的日级认领；认领不等于已送达。
- `GET /api/action-plans/rhythm/export?include_events=true`：分析事件显式可选，默认个人导出不含事件正文。

## 统计与两周验证

行动日按服务端确认的有效事实去重；撤销排除原完成；旧记录与补总结不制造新行动。同一plan、同一确认日期的投入与来源完成合为一个行动单位，已有任一总结即可承接；主任务仍须在行动前已选定。

试验使用入组时区及入组当日D1，入组前行动不进入分子。D1、D14都使用截止时刻的总结版本；截止后补填不改写过去结果。零活跃入组保留分母，未满14天单列，问卷缺失不视为满意。自然周卡和入组W1/W2分别计算，不混用。

参与者主动导出后，可在本机只读汇总同轮文件：

```sh
python3 知行成长/server/tools/rhythm_trial_report.py participant-a.json participant-b.json
```

脚本不连接数据库或分析服务，只输出汇总计数、分子/分母、未满窗、缺问卷、样本不足、最低模式分组和操作负担分布。试验仍需真实使用14天；合成测试不是留存效果证据。
