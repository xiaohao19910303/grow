# 行动计划使用说明

## 2026-10-27：目标驱动工作区

「行动 → 目标与计划」使用「＋新建」创建目标、计划或行动。目标可按年、月、自定义周期或暂不设周期；计划可按月、周或自定义阶段创建。没有年目标也可以独立使用，后续补关联不会创建副本。旧年目标的 ID、执行和复盘保留，旧达标次数沿用为行动计数口径。

按目标看方向和下一步，按周期看本月／本周／自定义范围。详情包含概览、计划与行动、进度与复盘；课程进度在「关联课程」展开查看。日程、今日与目标中的行动使用同一条记录。上级关联可以跳级，日期超出周期只提示；移动到未安排保留上级关系，并清除时间和提醒。

目标完成标准可选手动数值、阶段成果或固定目标行动数。实际投入单独显示，达到数字标准不会自动确认目标完成。修改结果保留历史，复盘快照不被当前调整覆盖。

日程中的「规划本周」支持未来周、重点、可选可用分钟和行动安排。未知时长单独提示；没有设置可用时间时不显示剩余时间；超量可调整或继续保存。取消周规划勾选不自动清除已有日期安排；需要取消日期时使用「移到未安排」。规划不产生执行事实，不自动开启日常节奏或提醒。

目标／计划详情中的「AI 辅助拆解」先预览发送内容、确认本人配置，再生成可编辑草案。默认具体安排未来七天，可选十四天；远期仅列阶段建议，最多三十项。可部分采用，未采用的草案上级不会成为必选，选中子项会关联原目标／计划。采用是原子事务，重试不重复创建；目标变化时先重新预览生成，草案保留。失败不自动重试收费请求，凭据不进入草案或日志。

创建和编辑有账号／上下文隔离的草稿、待确认请求及恢复副本。模板和重复安排可以在新行动的更多设置中直接完成。新版能力与行动完成 schema 2 分开声明；LightTick 接管端未支持此工作区，含新增数据时不允许丢字段接管。

实现与验证边界见 [交付报告](../../docs/verification/goal-driven-workspace-2026-10-27/README.md)。以下保留历史说明；与本节冲突的旧日期包含要求不再适用于新版工作区。

2026-10-20更新：Grow本地P0已通过回归及指定浏览器验收；LightTick连接端仍受合同门槛限制，未完成真实双端验收，也未部署本轮改动。

## 工作区私有接口（能力版本 1）

继续使用 `X-Grow-Action-Schema: 2`；新版写操作同时发送 `X-Grow-Workspace-Version: 1`。能力版本与行动完成事实版本独立，所有数据继续按当前登录账号隔离，不作为 LightTick 原生合同。

| 接口 | 用途 |
| --- | --- |
| GET `/api/action-plans/workspace` | 全部实体、继承的目标归属、越界／截止提示、结果和投入汇总 |
| GET/POST `/api/action-plans/goals` | 目标列表与创建；创建沿用 `plans` 数组响应 |
| GET `/api/action-plans/goals/{id}` | 单个目标的当前投影 |
| POST `/api/action-plans/goals/{id}/operations` | 目标编辑、暂停、恢复、归档、本人确认完成 |
| POST `/api/action-plans/goals/{id}/result` | 带 `key/revision/metric/note` 更新标准与结果，保留调整前快照 |
| GET/POST `/api/action-plans/week-plans/{week_start}` | 周一为起点的未来周规划；与事实周卡分别存储 |
| POST `/api/action-plans/planning-drafts/preview` | 根实体版本、基础、周可用分钟、近期重点和 7/14 天范围的发送预览 |
| POST `/api/action-plans/planning-drafts/generate` | 显式确认、预览哈希、本人 AI 配置，返回 202 和草案 ID |
| GET `/api/action-plans/planning-drafts?root_id=…` | 最近二十份草案与可恢复状态 |
| GET `/api/action-plans/planning-drafts/{id}` | 刷新生成结果；过期或跨进程未完成任务显示失败 |
| POST `/api/action-plans/planning-drafts/{id}/edit` | 带版本保存编辑后的项目，最多三十项 |
| POST `/api/action-plans/planning-drafts/{id}/adopt` | 采用已保存且选中的项目；事务内创建并关联，幂等返回原结果 |

实体新增 `entity_type`（goal/plan/action）、`expected_result`、可选 `deadline` 与目标的 `result_metric`。旧年、月、周、日记录读取时补充类型，不批量迁移 ID；没有新版语义的旧记录保持旧存储结构，避免污染既有接管包。新版数据使用 `workspace_version` 标识；导出备份保留结果历史、周规划和 AI 草案。

结果口径为 `unset/manual/milestones/actions`。数值口径使用 `current/target/unit`；成果口径使用稳定 `id/title/completed` 列表；行动口径使用有效完成的唯一行动数与固定目标值。目标状态独立于百分比。

周规划请求包含 `revision`、重点 ID 列表 `priorities`、带行动版本及可选日期的 `assignments` 和可选 `available_minutes`。保存前统一校验，冲突整笔回滚；日期安排只修改原行动。待调整列表的批量操作则逐项执行并保留失败选择，两者语义不同。

AI 草案项目仅接受 `ref/parent_ref/title/entity_type/period/start_date/end_date/estimated_minutes/selected`；模型不能写完成状态、来源关联、执行命令或凭据。生成限时九十秒，生成中任务按现有单 worker 运行方式恢复；没有跨 worker 调度租约。正式支持多 worker 前必须升级任务租约机制。

## 当前日行动（P0）

- 从「今日」新建行动，默认直接勾选；可以选择投入时长，或选择具体文章/课程后以内容完成。日期可暂不安排，具体时间可留空；提醒需要日期和具体时间。
- 计时行动可分段累计，例如先确认5分钟、再确认15分钟达到20分钟标准；中断即使已累计达标，也需再明确确认完成。页面计时不会自动认定实际投入。
- 文章/课程需要在来源中明确确认本次读完/学完。保存笔记与计时结束只记录对应事实；计时中已确认内容时，先结算投入再核对来源回执。
- 勾选完成为零分钟；撤销保留历史，再勾选仍只算一项当前有效完成。已完成的内容/计时行动需要再次执行时，复制为新行动。
- 「未安排」保存无日期行动；「待调整」展示过去尚未完成的安排，不自动顺延。「安排今日并开始」若执行冲突，会保留已保存日期并提示尚未开始。
- 保存结果未知时核对或重试原提交；修改后的输入另存草稿。保存成功但刷新失败无需再次创建。草稿按账号、来源、日期入口、上级及独立编号隔离。

P0字段与操作以 [规格](../../openspec/changes/action-plans-p0-clarity/design.md) 为准；[验证报告](../../openspec/changes/action-plans-p0-clarity/verification.md) 区分本地证据与未验证设备能力。下文保留第一版的层级计划、复盘和提醒说明；日行动的时间必填、单次达标等旧描述由本节与P0规格取代。

## 使用方式

1. 新建年、月、周或日计划，选择长期／短期分类；既可独立创建，也可关联日期、时区相容的上级计划。
2. 长计划设置目标达标次数，拆出具体日行动；日行动设置标准分钟、较小起步分钟、时间和提醒。最多显式安排同周七天，不自动把未完成计划滚入次日。
3. 首页优先显示正在执行和今日待执行行动。「开始学习」进入关联课程或历史文章；「先做 5 分钟」降低开始门槛。纸质书可仅记执行。
4. 刷新后继续执行；结束时本人确认实际分钟，可保存达标、起步、部分执行或中断记录。起步不会冒充达标，行动完成不会标记课程学完，课程笔记仍可独立暂存。
5. 在计划卡片查看进度，并打开「进度复盘与 AI 建议」。选择范围、记录做得好／阻碍／下一步，关闭后保留草稿，每次保存产生历史快照。
6. AI 使用设置中的个人配置。先查看数据预览，按需勾选执行说明和已保存复盘，确认后主动生成。总结、失败状态和历史持久保存；建议仅供参考，调整需手动保存。

进度以实际执行事实计数，进度条上限 100%，额外执行仍保留；长计划完成状态由本人确认，进度数字不等同于课程掌握程度。复盘日期按执行快照的业务日期，不会因服务器时区变化而移动。

## 提醒边界

网页打开时有站内提醒；桌面通知需主动允许，22:00–08:00 免打扰并按设备去重。可延后 15 分钟。网页关闭后的提醒通过下载 `.ics` 导入设备日历；需要在日历端确认通知权限。日历是独立副本，后续改期、暂停或归档需同步调整日历，当前没有后台 Web Push 或已上线的 LightTick 原生同步。

## 数据、接口和恢复

租户 PostgreSQL 中的 `action_plans`、`action_executions`、`action_operations`、`action_reminder_claims`、`action_reviews`、`action_reports` 独立保存私人计划、执行、请求回执、提醒去重、复盘、AI 结果；首次访问做增量建表，不改旧笔记、课程或待办表，不把私人数据写到 GitHub。

私有浏览器 API 均位于 `/api/action-plans`，沿用 Cookie 登录、账号请求头、同源写保护和 no-store：

| 路径 | 用途 |
| --- | --- |
| GET / | 计划、下级汇总、当前执行和服务端时钟 |
| POST / | 新建或同周批量创建，带持久请求 key |
| POST /{id}/operations | 带 revision 和 key 的编辑、暂停、恢复、归档、目标确认、开始、结束和延后 |
| GET /records | 30 条分页执行记录 |
| GET /requests/{key} | 查询失联请求是否已提交 |
| GET /{id}/calendar.ics | 带时区和可选提醒的日历导出 |
| POST /reviews/preview | 计划子树、日期和可选内容的准确预览与快照哈希 |
| POST /reviews | 保存手动复盘及当时统计 |
| GET /reviews?plan_id=…&page=… | 20 条分页手动复盘与 AI 历史 |
| POST /reviews/generate | 显式 consent、snapshot_hash、个人 ai_config 的异步生成，202 |

请求 key 重试返回同一结果，内容变化冲突；revision 防止旧页面覆盖。一个账号同时只运行一次执行。浏览器草稿和待确认请求按账号隔离；AI 凭据仅在调用时传给后端，不进入待确认请求缓存、操作回执、报告或日志。已有 AI 设置仍按项目既有方式保存在该账号浏览器中。

统计覆盖选定范围的全部事实，模型明细最多最近 30 条；执行说明最多每条 300 字符、复盘最近五次的每个文本字段最多 400 字符，截取标记可在完整预览查看。不读取学习笔记，也不推断刷视频时长。预览后数据有变更则拒绝生成。90 秒超时；不自动重试收费调用。服务重启或超过 120 秒未结束的生成会显示失败，保留已有记录，由用户主动重试。本版按本地现有单 worker 服务运行，横向多 worker 前需把生成租约改为跨进程共享。

LightTick 原生接口唯一合同源仍为 `Zook/api-contracts/openapi/lighttick`。这些 Grow 私有接口不作为原生公共合同；统一接管前 Grow 新计划与 Zook 原任务各只有自己的唯一写入方。

```sh
.venv/bin/python -B 知行成长/server/tests/run_isolated_checks.py --pattern 'test_action_reviews.py'
node 知行成长/server/tests/test_action_plan_client.cjs
```
