# 日常节奏：14 天使用验证计划

编制：2026-10-24。状态：**计划已整理，真实观察尚未由本次工作启动**。适用：行动归属 Grow、日常节奏合同受支持的网页账号；先以项目拥有者本人一名参与者验证。

当前代码与专项结果见[版本核查](../../docs/verification/current-state-2026-10-24/README.md)。能力和历史验收见[首版交付说明](daily-rhythm-v1-delivery.md)。本计划复用现有功能，不新增模型调用、推送、第二套任务或复盘系统。

后续[D0启动检查](../../docs/verification/d0-startup-2026-10-24/README.md)已走通隔离环境流程并修复设置初始化竞态；原个人实例尚缺启动配置，真实观察未由本轮启动。请先按检查记录解除实际实例的阻塞，再入组。

## 1. 这两周要回答什么

1. 打开平台后，是否容易知道现在能做哪一步？
2. 做过的事、卡点和下一步是否容易保存及找回？
3. 忙碌或中断后，能否继续，而不用补齐过去？
4. 第一次回顾选择的一项调整，后来是否真的尝试，是否帮助现实问题？

这是个人可用性观察，不验证认知能力是否在两周内提高，也不把一个人的比例包装成多用户留存或因果结论。

## 2. D0：启动前准备

由实际使用者在准备开始时填写，不默认以文档编制日作为D1。

| 项目 | 启动时记录 |
|---|---|
| 实际使用地址与设备 | 待填写；同一站点、主要浏览器优先 |
| 实际运行代码版本 | 待核对；不能只填仓库HEAD或接口合同版本 |
| 观察时区 | Asia/Shanghai；以入组保存的时区为准 |
| 入组时间／D1／D7／D14 | 入组后照界面区间填写；D7=D1+6天，D14=D1+13天 |
| 当前真实问题 | 用一句话描述，例如“把下次工作建议讲清楚” |
| 可观察结果 | 例如“形成一段建议及依据，并在一次真实沟通后留反馈” |
| 日常目标与提醒 | 默认每周3天；提醒先保持关闭，之后如自愿开启，记录变化 |

启动前在目标实例确认：登录账号正确；「设置 → 日常节奏」入口存在且支持；课程或普通行动可打开、保存后刷新仍在；完成状态符合本人操作；执行记录可重新打开；周成果及导出可用。初次核对可直接使用有价值的真实事项，入组前的尝试不进入本轮指标。

运行版本的确认方式：本地实例记录实际启动目录、该目录的提交和启动时间；线上实例核对部署控制台的实际部署提交及完成时间，再检查对应页面入口。无法确认时注明“版本未知”，先补齐实例识别；不要仅因浏览器打开了旧域名就填写当前仓库提交。

当前版本专项中的未解决失败见版本核查。若在目标实例仍不能走通关键路径，先记为“待排障”，暂不入组；记录缺失、重复完成或保存内容丢失，应优先处理。仅修改文档不能解除启动检查。

准备就绪后：

1. 「设置 → 日常节奏」开启功能，确认时区、每周目标及回顾星期，点击「保存节奏设置」。首次设置立即生效；后续目标、时区、回顾星期下周生效。
2. 点击「两周试用与问卷 → 加入两周试用」，核对界面显示的观察区间。开启功能和加入试用是两步。
3. 使用前先加入试用，再选择今日一件事并行动，避免首日事实发生在入组之前。晚间入组的D1只有当天剩余时间，结果须注明。

同一账号同一轮 `daily-rhythm-v1` 不重复入组。若已有本轮记录，沿用原窗口；不要删除记录或修改入组时间制造新首日。另开观察可先用人工日期记录，新的正式轮次支持再单独评估。

## 3. 一次实际使用怎么做

### 普通一天

1. 在「今日」选一项与真实问题有关的行动。课程或文章可先从学习列表安排到今日，再选为「今日一件事」；普通待办可在选择窗口新建，计时任务可走完整新建行动。
2. 在行动前设为今日一件事。完成标准和第一步都可选填，例如“先写出一句建议”。如果行动之后才选择，已有行动仍保留，但不追补成主任务闭环。
3. 实际执行。计时任务确认真实分钟；课程在原内容入口明确确认学完；勾选任务在做完后完成。打开页面、保存笔记、计时器运行本身不算完成。
4. 结束后愿意的话留一句“做出了什么／卡在哪里”，以及可选下一步。可以先保存行动，稍后在「行动 → 执行记录」补总结；无需另写一份四问复盘。
5. 下次打开时查看「上次下一步」，自主选择或新建今天的行动。它不会自动创建任务或改期旧安排。

一句总结示例：“建议已写出，但缺成本依据；下一步先核对一项成本。”它比“今天很努力”更能支持后续调整；不用每次写成长文。

### 忙碌、低状态和中断

- 选择「今天轻一点」，确认一个实际能尝试的最小步骤。普通待办要在做过后点击确认最小一步，完整待办仍可未完成，记录不伪造分钟。
- 课程只做一小段时，记录投入或中断；确实学完才确认课程完成。
- 可以休息，已有事实保留，不新增行动日；有进行中执行时先保存投入。
- 自然中断后，查看原下一步，继续、改期或归档旧安排，无需补打卡。没有自然中断就记“未观察”，不用刻意离开来制造恢复率。
- 保存失败时保留输入，使用原提交恢复或核对入口；不要为凑记录连续新建。课程完成已保存而安排同步失败时，先核对完成，不反复确认来源。

## 4. 14 天安排

这是观察重点，不是每日必做清单；可休息，不补造缺失事实。

| 日期 | 怎么用 | 观察重点与保留证据 |
|---|---|---|
| D1 | 入组后选一个真实小行动，尝试并按意愿总结 | 能否独立走通；第一步是否清楚；刷新能否找到结果 |
| D2–D3 | 沿用上次下一步；需要时把一课／一篇文章加入今日 | 有无重复创建、来回找入口；课程完成与安排是否一致 |
| D4–D6 | 按真实状态继续、缩小步骤或休息；尝试把所学用于现实问题 | 最小步骤是否降低负担；中断能否接续；保留一条练习／应用结果 |
| D7 | 填两道问卷；回看相关自然周成果；选一项调整并关联D8或之后的行动；导出一次 | 哪一步最费力；调整依据来自哪条记录；D7当天结束前确认调整 |
| D8–D10 | 实际尝试已关联的那项调整，记录结果 | 是否真正执行；困难有无变化；未尝试则如实注明 |
| D11–D13 | 继续正常使用，找回一次旧记录；观察自然发生的恢复场景 | 查找或接续是否节省精力；同一阻碍是否再次出现 |
| D14 | 当天填写问卷，核对成果、未完成与负担；可以先导出检查 | “下一步更清楚”“更有进展”各自评分；是否愿意继续使用 |
| D15或以后 | 在D14结束后再导出最终数据，确认已满14天；完成下述决策记录 | 最终计数、具体帮助/阻碍案例与下一次唯一改造候选 |

「成长 → 周期复盘 → 周/月汇总」顶部的周成果按当地周一至周日组织，D1–D7与D8–D14是入组周，两者可能错位。D7、D14回看必要的相邻自然周，不把单张周卡当作完整七天试验数据。

D7在周成果中最多选三条已有成果，写一项调整，选择今天或未来的具体行动并确认。为检验第二周尝试，优先关联D8之后的行动。确认文字或建立关联只说明“计划尝试”，后续事实和本人结果反馈才能说明是否做过、有没有帮助。

## 5. 观察什么，怎样少记一点

行动、总结和周卡保留业务事实。只有遇到卡点、明显帮助或改变设置时，再额外留一条观察；不设每日填表要求，单条尽量半分钟。可用私人日常记录，以“节奏验证”开头；不把个人正文提交到源码仓库。

| 观察维度 | 看什么 | 记录方式 |
|---|---|---|
| 开始 | 能否选出当前一步，入口是否好找 | 大致步骤／用时；若拿不准便记“不确定” |
| 保存与一致性 | 刷新/重进后内容是否存在，课程与行动是否一致 | 日期、入口、预期、实际、可回看的记录ID或私人截图 |
| 操作负担 | 选择、总结、周回顾是否打断真正做事 | 哪一步想跳过；是否因表单而放弃 |
| 接续 | 能否找到上次下一步，中断回来是否要重新规划 | 有／无发生机会；实际采取什么 |
| 现实帮助 | 练习或学习是否用于当前问题 | 一段作品、实际案例或反馈的私人引用 |
| 调整效果 | D7的一项调整是否在第二周尝试 | 尝试事实、结果与“有帮助／无帮助／未知”的理由 |

可直接使用这一行模板：

`日期｜版本/设备变化（如有）｜场景/记录引用｜想做什么｜实际结果/卡点｜是否影响继续｜下次可怎样验证`

无日志只代表没留下观察，不能推断没有困难或没有学习。测试样本、自动生成内容和本人真实行为分别标识。

## 6. 现有指标怎样解读

| 指标 | 现有口径 | 使用边界 |
|---|---|---|
| 行动日 | 一天至少一个有效、未撤销的确认事实 | 计划/浏览/保存总结不制造新行动；休息不计行动日 |
| 完整闭环日 | 有行动前选定的主任务关联，且同一行动同日单位有非空总结 | 没写总结不等于没行动，不强迫补写 |
| 总结覆盖 | 有总结的行动单位／全部行动单位；同一行动同日合并投入与来源完成 | 与行动次数、课程数量分开，不重复要求两份总结 |
| W2持续 | 已满窗参与者中，D8–D14有至少3个闭环日；另列行动日版 | 这是现有汇总定义；个人计划可更低，不作为个人合格线 |
| 调整已尝试 | 首七天确认的周卡调整关联到行动，第二周该行动有后续有效事实 | 不自动证明改变有益，须看本人结果 |
| 中断恢复 | 系统按两天无行动及后续观察机会计算 | 没发生合格中断记“不适用”，不算失败 |
| 主观反馈 | D7/D14“下一步是否更清楚”“是否更有进展感”，各1–5分 | 当前表单预填4分，请主动选择真实分数；未提交是缺失，不是满意 |
| 操作负担 | 现有表单事件的操作时长、取消与错误；用案例补充 | 是表单前台操作时间，不是学习时长；事件可能缺失 |

入组当日为D1，按入组时区固定到D14日末，入组前事实排除；D14当天还未满窗，D15再导出最终结果。D14问卷应在当天提交，之后补答会保留但不进入截止时刻的正式评分。补总结不更改原行动日期，截止后的总结不能回填成首日或最终窗口内结果。

同一参与者保留一份最新的完整导出；D7导出用于对照，不与D15导出重复合并。默认文件名为 `grow-rhythm.json`，下载后可自行改名并保存在私人目录。导出含私人行动与总结，不上传公开仓库。它不是整站备份。

可选在仓库根目录用已有环境只读汇总最终导出：

```sh
.venv/bin/python 知行成长/server/tools/rhythm_trial_report.py /absolute/private/path/grow-rhythm-final.json
```

该命令只读本地导出，不连接数据库、GitHub或模型。一个人报告直接写“行动X/14天、闭环Y/14天、第二周Z/7天”及案例；没有分母或机会时写未知/不适用，不沿用多人百分比门槛。

## 7. 如何决定下一步改造

先判断数据是否可信、路径是否可用，再判断新增能力。下面是改造触发信号，不是统计显著性标准。

| 观察结果 | 下一步 | 最小改造验收 |
|---|---|---|
| 出现正文丢失、重复创建、完成误判、账号串读 | 立即进入可靠性排障，必要时暂停受影响路径；保留已存内容 | 同一复现路径和恢复路径通过，再继续观察 |
| 同一入口/表单至少两次阻碍继续，或一次导致放弃且能复现 | 优先减少步骤、必填或重复确认 | 用原案例复测，保留输入和完成语义；操作负担降低 |
| 有接续机会，但反复找不到上次下一步 | 改善今日卡、定位原记录或接续入口 | 能找到来源并选择今天的行动，不自动改期或复制积压 |
| 能执行，却多次不知学什么/为什么学 | 补当前目标与下一步的轻量联系 | 选一个阶段/现实问题，能确认并安排下一步，复用现有行动 |
| 学完能回流，但难以留下练习、应用或成果 | 补一条问题—材料—行动—结果引用 | 从结果回到材料和记录，不把学完当掌握 |
| 事实与卡点已明确，周回顾仍难选调整，且本人希望辅助 | 试点有来源的一张建议卡 | 展示依据/日期/缺失，能采用、忽略，并回看尝试结果 |
| 入口可用、调整有帮助、负担可接受 | 保持现有功能，继续观察 | 不因“还能增加功能”而安排开发 |
| 样本很少、关键场景未发生、问卷缺失或版本中途变化 | 明确未知，补足对应场景或另记观察期 | 保留原14天窗口与版本变化，不重置或改写结果 |

高频打扰、全量自动排课、登录自动调用模型均不作为默认答案；先核对现有前台提醒是否被本人需要。任何新模型建议还需补充证据粒度，不能仅凭周期总量判断“下滑”或“过度自信”。

本轮只选一个主要改造候选。D7的一项个人做法调整可以继续；产品版本尽量稳定，必要修复时记录提交、日期和受影响场景，将前后结果分开解释。

## 8. D15决策记录模板

- 实际版本/设备、入组区间、期间变更：待填写。
- 行动日／14、闭环日／14、第二周行动日／7；数据缺失：待填写。
- D7/D14两项评分及是否本人主动选择：待填写。
- 一个帮助案例、一个阻碍案例；未发生则注明：待填写。
- D7调整 → 关联行动 → 第二周尝试 → 结果依据：待填写。
- 中断恢复：发生／未发生；有无机会观察：待填写。
- 决策：保持／修可靠性／简化入口／改善接续／补实践关联／试点建议／证据不足。
- 唯一改造候选：用户问题、对应案例、预期变化、复用能力、最小验收及回退方式。

开启、入组、每日真实使用与问卷由参与者在实际实例操作。本次工作不代填个人事实，不启动14天计时或自动提醒；完整观察结论在窗口结束后依据真实材料填写。
