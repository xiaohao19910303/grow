# 浏览器 AI 配置与云端存储验收

日期：2026-10-17。以下为本地隔离验证结果，尚未部署到线上。测试只使用临时数据库、模拟 GitHub 和测试密钥，没有调用真实付费模型，也没有写入个人数据库或内容仓库。

## 配置与调用合同

- 设置页的 Base URL、API Key、模型名称仅存于当前站点浏览器的 `localStorage`，键名为 `zhixing-ai-config-v1`。刷新可回读，换浏览器或清除站点数据后需重新填写。
- 三项配置必须齐全才能生成。浏览已有资料、读取已完成的生成任务、记录个人反馈不要求配置 AI。
- 测试和生成通过 HTTPS 请求将配置临时传给后端。后端以本次配置调用用户指定的兼容接口，不写入数据库、文件、发布日志或 GitHub，不读取 `QWEN_*` 作为回退。
- Base URL 接受兼容接口根地址（如 `https://provider.example/v1`）或完整 `/chat/completions` 地址，要求 HTTPS。服务商仍需提供 OpenAI Chat Completions 兼容协议。
- 所有生成入口均采用同一合同：新规划、课程生成及调整、旧认知课程、阅读导读/总结/英语学习、日常复盘追问/整理。旧模块在云端的可用性另见下表。
- `GET /api/copilot/settings` 只返回浏览器存储模式，不返回服务端 Base URL、模型或掩码密钥。旧 `PUT` 设置接口返回 410。
- 请求字段校验和连接失败不会将密钥回显在响应中。任务只保留实际使用的模型名称等运行元数据，不保存密钥或 Base URL。
- 新版本启动时删除 `copilot_settings` 中旧的 API 地址、密钥、模型及价格字段，支持已有 key/value 与 id/data 两种表形态，保留超时等运行设置。不改写历史备份；部署环境中旧 AI 变量虽不再使用，也可在部署后移除。
- localStorage 可由本站点 JavaScript 读取；本方案实现用户配置隔离，不宣称客户端存储能抵御任意脚本注入。

## 数据与迁移边界

| 模块 | 当前实现与验证结果 |
|---|---|
| 新学习计划 | 任务、草稿、个人反馈保存 PostgreSQL；正式规划、课程、参考资料和目录原子提交 GitHub，按 commit SHA 读取；保留发布恢复机制 |
| 旧首页记录 | 修复 `rowid` 排序、SQLite 写锁语法、缺失批量执行适配；PostgreSQL 事务内串行校验快照修订，稳定记录 ID，拒绝过期页面覆盖 |
| 日常复盘 | GitHub 模式下原文、版本、AI 建议及操作日志仅存 PostgreSQL；数据库事务保存，数据库锁协调，不再依赖临时磁盘或向公开仓库写个人复盘；可按需导出 Markdown |
| 行为应用、错误记录、行为报告 | 修复 SQLite 自增语法和时间默认值的 PostgreSQL 转换，以及自增 ID 返回；旧表已有约束不会被自动重建 |
| 股票复盘 | 继续存 PostgreSQL，已验证列表入口正常 |
| 旧认知课程 | 历史文件尚未迁入 GitHub 的发布协议；云端明确返回 `legacy_content_migration`，阻止正式课程落到临时磁盘；可使用新学习计划生成课程 |
| 旧认知阅读 | 正文、导读、笔记、阅读偏好仍依赖文件镜像与文件恢复协议，尚未完成 GitHub/数据库职责拆分；云端明确暂停该入口，原数据保留 |
| 英文、表达历史资料 | 仍读取随代码打包的只读历史资料；没有宣称已迁入 GitHub 动态发布协议 |

本地旧备份模块原有连接语法损坏已修复：离线 SQLite 归档使用明确的文件连接，校验和恢复读取指定归档文件；PostgreSQL 拒绝冒充 SQLite 快照，云端仍分别备份数据库与 GitHub。

新增已认证的 `GET /api/storage-status` 返回存储模式、AI 配置规则及各模块就绪状态；公开健康检查合同保持不变。

旧认知课程后续需处理文件扫描身份、课次和学习记录的关联、文件冲突及 GitHub 发布日志；认知阅读需先把个人笔记/阅读状态和可发布资料分开，再迁移导出和恢复协议。现有资料不会自动上传或清表重建。另发现旧 `server/create_tables.py` 为行为、错误、行为报告、知识关联等建立了与当前业务代码不一致的 id/data 表。已有这种结构时，`CREATE TABLE IF NOT EXISTS` 不会修复它；需要逐表核对并做保留原数据的迁移，不能把空库测试通过理解为这些旧表已经转换。启动检查失败的行为/错误/行为报告接口返回 503，避免继续向不匹配的表写入。

旧 `pending_sync.json` 导入脚本仍含 SQLite 专用语法，本次未将其自动转换或执行；云端不要启用该文件导入工作流。

## 验证

- 5 项浏览器配置后端测试：无服务端回退、7 个生成路由拒绝缺失配置、旧设置不读写远端值、错误不回显密钥、旧字段清理、任务和草稿不持久化密钥。
- 29 项 GitHub 生命周期测试，包含隔离 PostgreSQL：生成、发布、重读、故障恢复、提交冲突和私密反馈边界。
- 真实应用在隔离 PostgreSQL 启动：旧记录保存/修改/ID 保留、过期快照拒绝、日常复盘创建和更新、新实例读回、复盘 AI 使用本次密钥且不持久化、行为记录自增 ID、存储状态；正式课程仍经模拟 GitHub 发布。
- Chromium：实际设置表单保存、刷新回读、清除配置、独立浏览器上下文隔离；生成规划和首课、发布、读取参考资料及刷新后阅读。使用测试密钥和模拟模型，无 JavaScript 错误。
- 2 项生成响应性测试、3 项云端认证测试、2 项离线备份边界测试及前端任务观察器/旧记录保存协议检查通过。
- 隔离审计：真实工作区数据库访问和工作区写入计数均为 0。既有个人 `data.db` 修改未纳入本次提交。

上线后需重新配置浏览器自己的 AI 参数，并以实际服务商完成一次连接测试；本次测试不代表任意服务商网络或模型权限已验收。GitHub 内容仓库和 PostgreSQL 数据库仍需分别备份。
