# 知行成长 · 终生个人成长平台演进规划

> 更新日期：2026-10-15。
> 本文定义平台定位、演进顺序与阶段验收，替代此前以复盘同步为中心的演进规划。现状依据为当前工作区的文档、代码及数据库只读核查；代码存在不等于真实使用已验收。本文中的“新增、补齐、应当”均为规划，不代表已经交付。

## 1. 平台定位：陪伴一个人长期学习、记录与成长

**知行成长是一个由本人掌握数据、能够随人生阶段变化持续使用的个人平台，帮助自己留下经历、积累知识、解决现实问题，并看见认识与能力的变化。**

平台面向一个人的长期生活。学习、工作、个人项目、生活感受，以及本人选择关注的健康、关系、投资等主题，可以进入同一条个人经历线；不要求为每个领域建设一套专用系统。

平台应持续回答四个问题：

1. 今天是否容易留下值得保存的东西？
2. 以后是否能找到，并理解当时的自己？
3. 学习是否帮助解决了现实问题？
4. 人生节奏变化或长期中断后，是否还能继续使用？

共同使用路径是：**随手留下 → 需要时找回 → 按需关联学习、目标与行动 → 回看变化。**

记录本身有价值。开心的小事、尚未想清楚的困惑、阅读感受，都可以独立存在。决策、预测、四问复盘和AI追问是可选的深入方式；不把每条记录都转化成任务，也不要求每天证明成长。

### 1.1 长期原则

- **低负担**：一句话即可保存，标签、总结、关联和行动均可后补。
- **可中断**：允许休息、暂停、归档和重新开始，历史积累不因断更失效。
- **可找回**：保留时间、来源、上下文和关系，让过去的内容在需要时重新有用。
- **能实践**：学习可以连接现实问题、练习与成果，不用课程数量代替能力提升。
- **本人掌控**：保留原始表达；AI建议与本人采用的结论可区分；数据可以导出、迁移和恢复。
- **渐进演进**：复用现有模块和目录，先打通用户路径，再按真实需要增强。

### 1.2 范围与边界

个人终生平台不意味着立即覆盖生活的一切。优先服务已有的学习与记录需求，再按真实使用扩展主题。暂不以团队协作、社交排行、全自动人生评分、完整交易系统或覆盖所有生活事务为建设目标。

“终生”是一项持续维护责任：格式可读、数据可迁移、备份可恢复、语义可理解。Markdown和SQLite是合适的基础，但不能据此承诺自动保存50年。

## 2. 当前系统：已有基础与实际缺口

### 2.1 能力盘点

| 领域 | 当前已有能力 | 演进时需要补齐或验证 |
|---|---|---|
| 日常入口 | 今日学习、待办、日期切换、明日安排 | 简单记录入口是否足够直接；中断后如何继续；已有事项如何清理 |
| 学习 | 固定模块课程、学习计划、课程草稿与调整、本人确认完成、认知阅读与笔记 | 从内容消费到练习、实际应用和成果的联系；计划暂停与阶段切换 |
| 记录 | 旧复盘四问、决策、预测、洞察、自定义记录；新日常记录支持原文、版本、文件镜像和AI辅助 | 多条记录链路的来源与边界；统一查找；外部文件更新与冲突处理 |
| 关联与回顾 | 知识节点扫描、知识图谱、周报、行为应用、错误追踪与AI报告代码 | 跨模块关联、稳定身份、原始依据与样本边界；真实使用效果 |
| 专题扩展 | 当前工作区已有日常记录标签字段、股票复盘后端及前端接入代码 | 端到端可用性、标签筛选与跨模块复用、专题数据导出；不能仅依实施总结认定完成 |
| 数据保存 | 本地Markdown与SQLite；学习模块完整备份、整库快照、校验清单及离线恢复实现 | 备份目录和扩展名覆盖边界、工作区根目录文档与新增资产覆盖、异地副本、恢复演练、通用可读导出 |

现有备份能力应继续复用，不能重新从零建设；但学习备份的白名单并不等于整个个人工作区。旧JSON导出也不等同于包含所有模块和资料的完整备份。

### 2.2 数据快照与判断边界

| 旧复盘、决策、预测、洞察、打卡、时长 | 各0 | 对应表暂无记录，不能推断整个平台未运转 |

这是核查时刻的快照，后续以重新查询为准。数据应区分本人真实使用、测试样本与自动生成内容，不靠增加记录数证明价值。

### 2.3 已确认的关键问题

1. **旧复盘导入存在摩擦**：旧脚本扫描日期文件生成中转JSON，再由服务启动导入。新日常记录采用另一套目录和格式，不能用旧解析器直接覆盖。
2. **记录、学习与行动尚未连贯**：各模块有独立入口与数据，但还缺少贯穿个人经历的查找和关联路径。
3. **重复导入与身份稳定性需要补齐**：旧复盘表只有自增ID，现有导入的`INSERT OR REPLACE`不能保证按来源去重；知识刷新先清表重建，节点ID不适合作为长期关联依据。
4. **长期可持续性没有形成统一产品规则**：休息、暂停、恢复、任务积压和连续打卡之间的关系尚不清晰。
5. **耐久能力已有实现，但范围与验证不足**：需要说明哪些内容已备份、哪些未覆盖，以及离开当前应用后能否读懂和恢复。

因此，当前主要任务是完善可靠、低负担、可关联的个人使用路径。不能仅以空表推断所有高级能力都没有价值，也不能仅以功能代码存在宣称系统成熟。

## 3. 演进总顺序

| 优先级 | 阶段 | 核心结果 |
|---|---|---|
| P0 | 可靠留下，轻松回来 | 记录与学习状态不丢、不重复；基础备份可恢复；允许中断后继续 |
| P1 | 找回并连接个人经历 | 跨模块查找、时间线、轻量关联；过去的内容能用于今天 |
| P2 | 让学习进入现实 | 围绕真实问题串起目标、学习、实践、反馈与成果 |
| P3 | 随人生阶段持续变化 | 计划可暂停与重启，长期主题与历史理解可延续 |
| 按需增强 | AI与检索等能力 | 根据使用问题增加能力，持续维护耐久与质量 |

以上是依赖顺序，不是固定月份。P0内先处理可靠保存与备份底线，再完成低负担入口和恢复使用体验。后续阶段可做小范围探索，正式接入依赖前序相关路径通过验收。

无需等待三个月才建立项目关联，也不以500个节点作为引入向量检索的门槛。是否建设取决于具体问题、可验证收益和维护成本。

## 4. P0：可靠留下，轻松回来

### 4.1 范围与复用方式

**记录入口**：优先复用新日常记录的原文、稳定编号、版本和文件镜像能力，提供一句话保存。保留旧复盘入口及历史内容，通过统一列表或来源链接连接，不要求立即合并表或批量迁移。

**导入与一致性**：补齐旧Markdown复盘的来源标识、内容变更识别和幂等导入；明确支持的文件格式。服务运行期间提供自动发现变化的机制及手动重试入口，说明发现时机。启动导入只是其中一个触发点。无法解析的内容保留原文并提示，不静默丢弃。

**长期身份**：为需要关联的对象保留稳定身份与来源。旧数据可增量补映射，不按标题或显示名称确定身份，不沿用“清表重建”的个人记录同步方式。

**数据权威与写入边界**：为每类资产明确主数据、镜像与可重建索引。新日常记录沿用当前应用管理方式；旧外部Markdown先作为导入来源。网页与外部文件均修改时，停止覆盖并显示差异，不能简单按最后修改时间吞掉一方。保留现有写入锁和恢复日志机制，逐步协调外部写入者。

**恢复使用**：首页允许直接记录或继续当前学习；无记录日保持中性。暂停期间的事项不自动滚动复制，不伪造打卡；回来后可继续、改期或归档积压事项。连续天数可保留为辅助信息，不作为全平台完成条件。

**基础耐久**：复用现有完整学习备份和整库恢复，列出全部资产及覆盖情况，补齐必须保存的个人内容。备份范围应包括数据库中的专题记录与文件资料，敏感配置按明确规则排除。提供最近成功备份、覆盖范围及失败状态，支持复制到独立位置；先在隔离目录恢复验证。

### 4.2 验收标准

- **简单记录**：从首页进入记录，填写一句话，不填标签、总结和行动也能保存；刷新与服务重启后原文、日期和编号一致。
- **幂等同步**：同一旧复盘连续同步三次，只保留一份对应来源记录；修改原文件后更新对应版本，不新增伪重复，也不自动重复增加打卡。
- **运行中发现变化**：不重启服务，新增或修改受支持的外部复盘文件，在约定发现周期内可见；失败原因和重试入口可见。
- **冲突与失败**：用隔离样本验证文件和网页并发修改、不可解析文件及写入失败；既有原文不被覆盖，页面不误报已保存，故障后可恢复。
- **中断回归**：模拟中断七天，回来后无需补齐历史打卡即可记录和继续学习；旧待办可一次整理，历史学习记录不清零。
- **语义保持**：一句话记录不自动代表完成课程；休息不写成完成；`checkins.level`现有完成度含义不被改作精力或记录强度。
- **备份恢复**：使用含旧复盘、新记录、课程笔记、专题记录和附件的样本，在隔离目录恢复；核对内容、身份与关联，明确未覆盖项。验证独立副本可用，不在真实数据上试恢复。

**阶段完成条件**：上述场景有操作证据和结果，真实使用与测试样本可区分。数据表非零和周报非零不能替代验收。

## 5. P1：找回并连接个人经历

### 5.1 范围与复用方式

在现有导航与模块上增加统一查找和时间线，不为此推翻现有架构。第一批覆盖课程及阅读元信息、个人笔记、旧复盘、新日常记录、决策与洞察；专题记录通过适配逐步接入，界面说明实际覆盖范围。

先提供关键词、日期、类型和标签过滤。区分事件发生日期与创建、修改日期，支持补记。搜索结果显示原文片段、来源和打开入口；缺失资料说明原因，不用AI补写冒充。

复用已有标签字段，补齐输入、展示、筛选和改名规则。标签适合分类，但“属于哪个项目、应用了哪条知识”需要明确关联。建立轻量引用，使一条记录可以关联课程、文章、长期主题或一个现实问题。现实问题先用标题、说明和稳定编号表达，不要求先建设完整项目模块。

时间回看先支持昨天、上周、按时间筛选和本人指定内容。有一年数据再自然出现“那年今日”，不把跨年展示当作时间回顾的前提。

### 5.2 验收标准

- **跨模块找回**：在含中文正文、标题、标签和补记日期的隔离样本中，按预设关键词找回对应内容，打开后能核对原文；明确哪些资料仅检索元信息。
- **实际使用任务**：选择三个本人真实问题，例如“上次类似困惑怎样处理”“某个概念在哪次实践用过”“某阶段读过哪些相关资料”，无需逐个目录翻找即可取得相关证据；记录耗时和漏检项。
- **关联稳定**：将课程、日常记录与同一现实问题关联；修改标题或显示名称后引用仍有效。归档和删除时能区分有效、已归档、来源缺失状态。
- **时间准确**：补记和跨日期内容按事件日期显示，创建时间仍可查；无历史的时间段不伪造活动。
- **用户可控**：普通记录无需先分类即可进入查找；AI不可用时检索、过滤和原文访问仍可使用。

**阶段完成条件**：能在真实问题中找回并重新使用过去的内容，覆盖范围与不足有明确记录；不以搜索结果数量或图谱节点数量验收。

## 6. P2：让学习进入现实

### 6.1 范围与复用方式

在P1轻量关联之上增加目标与项目视图。目标描述希望发生的变化，项目描述有限范围内要完成的事情，长期主题承载持续关注的领域。三者按需使用，不要求每条笔记拥有完整层级。

复用学习计划、待办、行为应用、错误记录和复盘能力，允许把材料、练习、行动与成果挂到一个现实问题上。项目最小字段为目的、预期成果、状态和下一步，避免先做复杂管理工具。

明确区分“已生成、已阅读、已完成练习、已在现实中应用、有成果证据”。保留本人确认完成的语义，不通过停留时间和课程数量自动判定掌握。

决策与预测到期回看纳入本阶段，可按实际需要提前试点。支持本人选择日期、延期、关闭或放弃；区分原预期、实际结果与当前解释，历史判断不被结果回填覆盖。复盘的下一步可关联到待办，并能在后来记录结果；仅保存一条改进建议不算行动闭环。

股票复盘等专题复用查找、标签、关联和回顾能力，保留必要的专业字段。专题记录可作为个人判断与实践的材料，其统计不代表全平台成长水平。

### 6.2 验收标准

- **真实项目链路**：选择一个真实问题，串起目标或项目、学习材料、一次练习、实际行动、结果证据与复盘，能够从成果回到当时依据。
- **成果可解释**：项目可用作品、案例、交付或本人明确描述的变化验收；未达到目标也能如实保留失败与未知，不强制标记成功。
- **行动有回流**：复盘中选择一条下一步，关联待办；执行后记录结果，回到原复盘可见。无需把所有感想转成任务。
- **学习状态独立**：读完课程不自动标为掌握；项目完成不自动标记其关联的所有课程完成。
- **决策可回审**：用可控日期验证到期、延期、关闭与放弃；原始预期保留。缺乏样本或结果时，分析明确显示未知和样本范围。
- **专题可整合**：一个专题记录能通过共同查找与关联被找到，专业字段仍可读取，不必复制正文到另一套记录中。

**阶段完成条件**：至少一条真实的学习—实践—反馈路径完成，并由本人判断其是否减少了重复学习、帮助行动或改进认识；不能仅凭新增项目表验收。

## 7. P3：随人生阶段持续变化

### 7.1 范围与复用方式

为现有学习计划、目标和项目补齐必要的暂停、结束、归档与恢复规则，保留历史版本及当时上下文。调整方向时可以保留旧阶段并开启新阶段，不要求把旧计划做完。

允许本人定义长期主题与阶段，如“转岗准备”“表达能力”“新手父母阶段”。阶段划分可后补，不强制赛季长度或三档状态机。固定课程完成一轮后，应提供归档、继续练习或选择新方向的路径，不直接把旧课次无限累加。

提供按需月度、季度和年度回顾：本人选择关注内容，系统组织事实、原文与变化。AI解释属于建议，可以修改、拒绝；不凭记录稀疏推断心理状态或人格结论。

持续完善通用导出和环境迁移：保留正文、时间、稳定编号、来源、关联与必要版本，携带数据说明和格式版本。新的资产类型必须进入保存与迁移清单，不能等年度回顾时才发现无法导出。

### 7.2 验收标准

- **阶段切换**：暂停旧计划、归档项目并开始新方向；旧阶段记录、成果和当时规划仍可查，新阶段预算不继续计算已暂停任务。
- **长期中断**：模拟离开三个月后恢复，首页能看懂之前进行到哪里，选择继续或重建安排，不要求补齐积压课程和复盘。
- **回顾可核验**：每项事实可回到来源；当时想法与后来解释可区分；无数据部分标记缺失，AI内容可拒绝。
- **脱离应用可读**：导出后不用当前网页，也能阅读代表性的课程笔记、日常记录和专题记录，并按说明解析时间、编号与关系。
- **迁移可验证**：在隔离的新路径或新环境恢复代表性资料，关键引用有效；旧格式按迁移说明可读取，迁移失败可回退。

**阶段完成条件**：一次完整的阶段切换和隔离迁移演练通过。无需等待真实度过一年，但仍需在后续真实使用中复核长期体验。

## 8. 按需增强与持续维护

| 能力 | 启动条件 | 收益与验收方向 |
|---|---|---|
| 语义检索、向量索引 | 已有代表性查询被关键词检索漏掉，且本人确实需要找回 | 用同一组查询比较找回质量、延迟和维护成本；保留无模型查找路径 |
| AI追问、反方分析 | 有具体困惑或决策，且本人希望得到辅助 | 基于所选材料提出可核对建议，保留原文与采用状态；不要求先积累大量决策 |
| AI跨期分析 | 有足够相关样本并存在明确回顾问题 | 显示来源与样本边界，允许纠正，不将相关性当因果 |
| 知识图谱增强 | 关联确实帮助解释知识与应用关系 | 能沿关系找到案例与来源；稳定身份不因扫描重建而断裂 |
| 多设备与离线写入 | 当前本机或局域网使用反复阻碍记录 | 先确定实际设备和使用场景，再验证保存、同步与冲突；不把现有本地部署等同于离线网页编辑 |
| 生活主题扩展 | 有持续记录需求，通用记录与模板已经不足 | 优先增加模板与专业字段，继续接入共同的查找、回顾和导出 |

备份、恢复验证、格式兼容、失效引用检查和依赖维护贯穿所有阶段。保护个人记录、AI发送范围及凭证排除规则也属于持续维护；新增能力必须沿用这些边界。

## 9. 产品结构与度量

继续使用“今日—学习—记录—成长—设置”，通过现有页面渐进完善：

- **今日**：快速记录、主动选择的当前事项、继续学习，以及整理积压事项。
- **学习**：课程、阅读、笔记、练习及其现实应用。
- **记录**：自由记录、复盘、决策、洞察和专题记录的查找与连接。
- **成长**：按主题、项目和阶段看成果与认识变化，回到原始依据。
- **设置**：数据范围、备份恢复、导出、AI配置与迁移说明。

不增加统一“成长分”。连续天数、时长、课程数和节点数保留为辅助信息。主要观察：

| 观察维度 | 证据 | 使用方式 |
|---|---|---|
| 留下是否容易 | 实际保存步骤、耗时、失败与冲突 | 发现摩擦并减少必填，不设每日记录配额 |
| 过去是否有用 | 真实问题的检索耗时、漏检和再次引用案例 | 优化覆盖与上下文，不以检索次数排名 |
| 学习是否进入现实 | 练习、应用、成果及反馈案例 | 看具体变化，不从阅读时长推断掌握 |
| 中断后能否继续 | 暂停与恢复任务是否完成、积压处理负担 | 验证恢复路径，不把休息算失败 |
| 数据是否可信可持续 | 保存完整性、备份覆盖、恢复与迁移结果 | 作为发布与维护底线 |

先以少量真实案例人工核对这些证据，明确有用后再建设统计面板，避免为了度量新增大量录入工作。

## 10. 近期执行切片与交付规则

下一轮实施按以下顺序形成可独立验收的小切片：

1. **盘点并明确数据边界**：列出新旧记录、课程笔记、专题记录、根目录文档与附件的身份、主数据、镜像、备份覆盖和外部写入方式；更新过时路径说明。
2. **先保护已有数据**：核对现有备份，补齐重要遗漏，在隔离目录验证恢复；确定来源去重、冲突和版本规则。
3. **完成一个日常使用入口**：复用日常记录实现一句话保存与无压力回归，不增加新的打卡强度模型。
4. **修通一条旧记录路径**：以已有日期复盘文件为代表，完成运行中同步、重复执行、外部修改与冲突验收；不直接推广到未知格式。
5. **开始最小找回与关联试点**：选三个真实查找问题和一个现实学习问题，在P0相关路径可靠后验证P1，不先做完整知识重构。

每个切片应记录：具体用户问题、复用能力、实际变更、验收结果、剩余限制，以及数据变更时的回退方式。示例与测试优先使用隔离目录和临时数据库；真实模型、实际设备体验与长期使用效果另行记录，不能用模拟测试替代。

本规划只更新方向与验收要求，不自动授权修改历史内容、删除数据、恢复真实数据库、迁移目录、运行外部自动任务或调用付费模型。进入具体实施时，按当次任务范围执行。

## 11. 相对旧规划的主要取舍

| 旧判断 | 本次调整 | 原因 |
|---|---|---|
| 复盘未入库等于系统尚未发动 | 分开评估学习、阅读、记录与导入链路 | 当前已有部分业务数据，单看旧表会遗漏使用路径 |
| 决策预测是唯一高价值核心 | 将其作为个人成长的一种深入路径 | 记录、学习、经历与成果同样有独立价值 |
| 低负担使用在P2 | 纳入P0，与保存可靠性共同建设 | 持续使用需要从第一天支持忙碌与中断 |
| 耐久规范放在长期P4 | 基础保存与恢复进P0，迁移持续增强 | 个人数据从第一天开始积累 |
| 项目关联和时间回顾等待三个月 | P1轻量关联，P2实践闭环，按已有历史回看 | 这些能力的价值取决于实际问题，而非固定等待期 |
| 直接复用打卡level表示极简/完整 | 保留完成度语义 | 避免历史数据含义改变与统计混淆 |
| 统一三层重构砍掉后不再考虑长期结构 | 不做大重构，保留目标、项目、主题与阶段的轻量演进 | 控制工程规模，同时支持长期变化 |
| 以表非零、统计增长验收 | 以保存、找回、实践、恢复与迁移场景验收 | 数据流动是基础，个人使用价值才是演进依据 |
