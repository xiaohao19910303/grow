## 第二十六课：工具组合策略（3天）

### 26.1 为什么需要工具组合

真实世界的问题往往是复杂的、多维的，单一工具难以全面解决。

**类比**：木匠不只是用锤子——他有一整套工具箱，根据任务选择合适的工具。

**核心原则**：
- 工具是手段，不是目的
- 问题的性质决定工具的选择
- 工具之间可以互补和叠加

### 26.2 经典组合方案

#### 组合 1：解决复杂问题

**流程**：5 Whys → 鱼骨图 → 逻辑树 → 行动方案

```
Step 1：5 Whys 找到根因方向
Step 2：鱼骨图系统列出所有可能原因
Step 3：逻辑树拆解问题，找到可行动的点
Step 4：制定行动方案
```

**案例**：客户满意度下降

```
5 Whys：
→ 为什么满意度下降？因为响应慢
→ 为什么响应慢？因为工单太多
→ 为什么工单多？因为产品 bug 多
→ 为什么 bug 多？因为测试不充分
→ 为什么测试不充分？因为上线压力大，压缩测试时间

鱼骨图（按 6M 分类）：
- 人：测试人员不足
- 机：自动化测试覆盖率低
- 料：需求变更频繁
- 法：测试流程不完善
- 环：上线压力大

逻辑树（解决方案）：
如何提升测试充分性？
├── 增加测试资源
│   ├── 招聘更多测试人员
│   └── 培训开发做单元测试
├── 提升测试效率
│   ├── 引入自动化测试
│   └── 优化测试用例
└── 减少测试压力
    ├── 调整上线节奏
    └── 增加灰度发布

行动方案：
1. 短期：调整上线节奏，给测试留足时间
2. 中期：引入自动化测试框架
3. 长期：建立质量文化，全员为质量负责
```

#### 组合 2：制定战略

**流程**：PESTEL → SWOT → 商业模式画布 → OKR

```
PESTEL：分析外部环境
    ↓
SWOT：结合自身情况
    ↓
商业模式画布：梳理商业逻辑
    ↓
OKR：制定目标和关键成果
```

#### 组合 3：产品设计

**流程**：用户旅程图 → 定义问题 → 头脑风暴 → 原型 → 测试

```
用户旅程图：找到痛点
    ↓
设计思维 Step 2：定义问题
    ↓
设计思维 Step 3：头脑风暴/SCAMPER
    ↓
设计思维 Step 4：做原型
    ↓
设计思维 Step 5：测试迭代
```

#### 组合 4：决策分析

**流程**：六顶思考帽 → 决策矩阵 → 成本收益分析

```
六顶思考帽：全面审视（避免盲点）
    ↓
决策矩阵：多选项量化比较
    ↓
成本收益分析：判断值不值得做
    ↓
做出决策
```

#### 组合 5：系统诊断

**流程**：冰山模型 → 因果循环图 → 杠杆点干预

```
冰山模型：从事件深入到心智模型
    ↓
因果循环图：画出关键变量和回路
    ↓
识别杠杆点：哪里的小改变可以带来大的改善
    ↓
制定干预方案
```

### 26.3 工具选择的决策树

面对一个问题时，如何选择工具？

```
问题是什么类型？
│
├── 需要理解问题
│   ├── 问题模糊 → 5W1H、思维导图
│   ├── 问题复杂 → 逻辑树、MECE
│   └── 需要找根因 → 5 Whys、鱼骨图
│
├── 需要做决策
│   ├── 多选项比较 → 决策矩阵
│   ├── 需要全面审视 → 六顶思考帽、SWOT
│   └── 判断值不值得 → 成本收益分析
│
├── 需要创新方案
│   ├── 以人为本 → 设计思维
│   ├── 改进现有 → SCAMPER
│   └── 产生大量想法 → 头脑风暴
│
├── 需要看全局
│   ├── 多层分析 → 冰山模型
│   ├── 动态关系 → 因果循环图
│   └── 相关方分析 → 利益相关者地图
│
└── 特定领域
    ├── 商业 → 波特五力、商业模式画布
    ├── 产品 → 用户旅程图、KANO
    ├── 项目 → WBS、甘特图
    └── 个人 → GTD、费曼学习法
```

### 26.4 实战练习

**练习 1：选择一个真实复杂问题，设计工具组合方案**

要求：
- 画出工具组合流程图
- 说明为什么选择这些工具
- 预估每个步骤的时间

**练习 2：回顾过去的一个决策，分析可以如何改进**

- 当时用了什么工具（可能是无意识的）？
- 如果重来，可以用什么工具组合？
- 结果会有什么不同？

## 第二十七课：建立个人思维工具箱（持续）

### 27.1 为什么要建立个人思维工具箱

- 工具太多，记不住 → 需要一个随时可查的系统
- 每个工具都有适用场景 → 需要快速匹配
- 实践中会积累经验 → 需要记录和复盘

### 27.2 工具箱的内容

#### 工具速查卡

为每个工具创建一张"速查卡"：

```
┌─────────────────────────────────┐
│ 工具名称：SWOT 分析              │
├─────────────────────────────────┤
│ 一句话描述：                     │
│ 从优势/劣势/机会/威胁四个维度评估 │
├─────────────────────────────────┤
│ 适用场景：                       │
│ • 战略规划                       │
│ • 职业决策                       │
│ • 竞品分析                       │
├─────────────────────────────────┤
│ 使用步骤：                       │
│ 1. 列出 S/W/O/T                  │
│ 2. 交叉分析形成策略              │
│ 3. 选择策略方向                  │
├─────────────────────────────────┤
│ 注意事项：                       │
│ • 一定要做策略矩阵，不只是列清单 │
│ • 区分内部/外部因素              │
├─────────────────────────────────┤
│ 我的使用心得：                   │
│ （记录你的实践经验）              │
└─────────────────────────────────┘
```

#### 场景-工具匹配表

| 我想… | 推荐工具 |
|-------|---------|
| 整理思路 | 思维导图、金字塔原理 |
| 拆解问题 | 逻辑树、MECE、5 Whys |
| 找根因 | 5 Whys、鱼骨图 |
| 做决定 | 决策矩阵、SWOT、六顶思考帽 |
| 想创意 | SCAMPER、头脑风暴、水平思维 |
| 理解全局 | 冰山模型、因果循环图 |
| 规划项目 | WBS、甘特图、PDCA |
| 管理任务 | GTD、番茄工作法 |
| 深度学习 | 费曼学习法、复盘法 |

### 27.3 工具箱的载体

**数字工具**：
- Notion：数据库 + 模板，适合系统管理
- Obsidian：双向链接，适合知识网络
- 飞书文档：协作方便

**纸质工具**：
- 活页本：灵活增删
- 卡片：一张工具一张卡，随身携带

### 27.4 实践与迭代

**每次使用工具后，记录**：
- 日期和场景
- 用了什么工具
- 效果如何（1-5 分）
- 有什么改进

**每周回顾**：
- 本周用了哪些工具？
- 哪些用得好？哪些没用？
- 下周计划用哪些工具？

## 第二十八课：团队引导与协作（持续）

### 28.1 在团队中引入思维工具

**挑战**：
- 团队成员不熟悉工具
- 觉得"又是新花样"
- 不知道如何引导

**策略**：

1. **从小处开始**
   - 不要一次引入所有工具
   - 选一个最合适的场景
   - 先做 15 分钟的微型工作坊

2. **让工具隐形**
   - 不要强调"我们在用 SWOT"
   - 直接说"我们从四个角度来看看"
   - 工具是手段，解决问题是目的

3. **以身作则**
   - 自己在会议中使用工具
   - 展示效果
   - 让团队主动问"怎么做的"

### 28.2 会议引导技巧

**会前**：
- 明确目标（用金字塔原理整理议题）
- 选择合适的工具
- 准备材料（白板、便签、计时器）

**会中**：
- 开场说明目标和规则（2 分钟）
- 引导使用工具（解释步骤，不解释理论）
- 控制时间（每个环节设定时间盒）
- 记录产出（可视化，让所有人看到）

**会后**：
- 总结结论和行动计划
- 发送会议纪要（用金字塔结构）
- 跟踪执行

### 28.3 常用团队工具组合

| 场景 | 工具组合 | 时间 |
|------|---------|------|
| 问题复盘 | 5 Whys + 鱼骨图 | 60 分钟 |
| 方案策划 | 设计思维 + 头脑风暴 | 90 分钟 |
| 决策讨论 | 六顶思考帽 + 决策矩阵 | 60 分钟 |
| 战略规划 | SWOT + PESTEL | 120 分钟 |
| 项目启动 | WBS + 甘特图 | 90 分钟 |

## 第二十九课：持续精进之路（持续）

### 29.1 学习的四个阶段

```
不知道自己不知道（无意识无能）
        ↓
知道自己不知道（有意识无能）
        ↓
知道自己知道（有意识有能）
        ↓
不知道自己知道（无意识有能）
```

你现在的位置？
- 学完本教程 → 至少到了"知道自己不知道"
- 经过大量练习 → 可以达到"有意识有能"
- 内化为本能 → 达到"无意识有能"

### 29.2 精进的三个层次

**层次 1：掌握工具**
- 知道每个工具是什么、怎么用
- 能在指导下使用

**层次 2：灵活应用**
- 能在真实场景中选择合适的工具
- 能组合多个工具解决复杂问题

**层次 3：内化为本能**
- 不需要刻意选择，自然而然地用对的方式思考
- 能创新和发展工具
- 能教别人

### 29.3 持续学习的方法

**1. 刻意练习**

- 每周至少刻意使用 2-3 个工具
- 每次使用后记录心得
- 定期回顾和复盘

**2. 教是最好的学**

- 教同事/朋友使用思维工具
- 写文章分享经验
- 在团队中引导工作坊

**3. 跨领域学习**

- 阅读不同领域的书籍
- 参加不同类型的培训
- 和不同背景的人交流

**4. 建立反馈循环**

- 找导师或学习伙伴
- 定期请教和讨论
- 接受反馈并改进

**实践社区**：
- 思维工具实践小组

### 29.5 思维工具使用伦理

**提醒**：
- 工具是手段，不是目的——为了解决问题，不是为了炫技
- 尊重他人——不要用工具"操控"他人
- 保持谦逊——工具不是万能的，有其局限
- 持续迭代——没有最好的工具，只有更合适的工具

## 阶段综合实战项目

### 项目 1：个人年度规划

**流程**：
1. **复盘过去**：用金字塔原理 + 复盘法
2. **分析现状**：用 SWOT + 冰山模型
3. **设定目标**：用 OKR
4. **拆解路径**：用逻辑树 + WBS
5. **时间规划**：用甘特图
6. **执行管理**：用 GTD + 番茄工作法
7. **季度回顾**：用 PDCA

### 项目 2：解决一个真实复杂问题

选择一个你生活或工作中的复杂问题（如：职业发展、团队管理、产品设计…），走完完整流程：

1. **定义问题**：5W1H + 金字塔原理
2. **分析根因**：逻辑树 + 5 Whys + 鱼骨图
3. **系统理解**：冰山模型 + 因果循环图
4. **利益相关方**：利益相关者地图
5. **产生方案**：设计思维 + SCAMPER + 头脑风暴
6. **评估方案**：决策矩阵 + 成本收益分析
7. **制定计划**：WBS + 甘特图
8. **执行跟踪**：PDCA + 复盘

### 项目 3：团队工作坊设计与引导

设计并引导一次 2 小时的团队工作坊：

1. 确定主题和目标
2. 设计流程（选择合适的工具组合）
3. 准备材料
4. 引导实施
5. 收集反馈
6. 复盘改进

## 终极心法

### 关于工具

- **工具是仆人，不是主人**——你使用工具，不是工具使用你
- **少即是多**——精通 5-10 个工具，胜过了解 100 个工具
- **合适即最好**——没有最好的工具，只有最合适的工具
- **组合创新**——真正的创新往往来自工具的组合

### 关于思考

- **先慢后快**——刚开始刻意练习会很慢，熟练后会变成本能
- **反思比行动重要**——不停反思，才能不断进步
- **简单胜过复杂**——最简单的方案往往是最好的
- **以人为本**——所有工具的最终目的都是帮助人

### 关于学习

- **用中学**——光学不练等于没学
- **教中学**——教别人是最快的学习方式
- **错中学**——犯错是正常的，关键是快速改正
- **持续学**——思维能力的提升是一辈子的事
