# 第二阶段：分析与诊断工具

> 学习周期：2-3 周 | 目标：学会拆解复杂问题，找到根本原因
>
> 前置要求：已完成第一阶段（基础思维工具）

---

## 阶段目标

完成本阶段后，你将能够：
1. 用 5 Whys 层层追问找到问题根因
2. 用逻辑树将复杂问题拆解为可管理的子问题
3. 用鱼骨图系统梳理问题的可能原因
4. 用帕累托分析找出"关键的少数"

## 第五课：5 Whys 深度分析法（3天）

### 5.1 起源与原理

5 Whys 由丰田汽车创始人丰田佐吉创立，是丰田生产系统（TPS）的核心工具之一。

核心理念：**每个表面问题背后都有更深层的原因，连续追问"为什么"可以逐层深入，直到找到可以采取行动的根本原因。**

"5"不是精确数字——可能需要 3 次，也可能需要 7 次。关键是追到"你可以采取行动"的那一层。

### 5.2 经典案例

**案例 1：华盛顿纪念碑的腐蚀**

```
问题：纪念碑表面严重腐蚀
→ 为什么？因为经常用强力清洁剂冲洗
→ 为什么？因为上面有很多鸟粪
→ 为什么？因为很多燕子在上面筑巢
→ 为什么？因为那里有很多它们爱吃的虫子
→ 为什么？因为纪念碑的灯光在黄昏时吸引虫子
解决方案：推迟开灯时间
```

**案例 2：个人迟到**

```
问题：今天上班迟到了
→ 为什么？因为起晚了
→ 为什么？因为昨晚睡太晚
→ 为什么？因为失眠了
→ 为什么？因为睡前一直想工作的事情
→ 为什么？因为项目 deadline 临近但进度落后
→ 为什么？因为前期花太多时间在非核心任务上
根因：任务优先级管理不当 → 行动：学习时间管理方法
```

### 5.3 操作步骤

**Step 1：明确问题**
- 用一句话说清楚问题是什么
- 确保问题是具体的、可观察的（不是模糊的感觉）

**Step 2：写下第一个"为什么"**
- 为什么会出现这个问题？
- 答案要基于事实，不是猜测

**Step 3：追问下一个"为什么"**
- 对上一个答案再问"为什么"
- 层层深入

**Step 4：判断是否到达根因**
- 根因特征：你可以针对它采取行动
- 如果答案是"我没办法"，说明可能还没到根因，或者方向不对

**Step 5：制定对策**
- 针对根因制定解决方案
- 思考：如何防止问题再次发生？

### 5.4 高级技巧

#### 技巧 1：区分"原因"和"借口"

```
问题：报告没按时交
借口：因为太忙了（无法行动）
原因：因为时间预估不足，低估了数据收集的时间（可以改进）
```

#### 技巧 2：多线追问

一个问题可能有多条因果链：

```
问题：客户投诉产品有缺陷
├── 为什么？→ 质检没发现 → 为什么？→ 质检流程有漏洞 → ...
└── 为什么？→ 生产时参数设错了 → 为什么？→ 操作员培训不足 → ...
```

#### 技巧 3：5 Whys + 逻辑树

先用逻辑树拆解问题的维度，再对每个维度做 5 Whys。

### 5.5 常见错误

| 错误 | 示例 | 改进 |
|------|------|------|
| 停在表面 | "因为他不负责任"（贴标签） | 继续追问：什么导致他表现出不负责任？ |
| 归咎于人 | "因为小王粗心" | 问：系统/流程为什么允许粗心导致出错？ |
| 因果跳跃 | "因为天气不好" | 确认因果关系是否成立 |
| 只追一次 | "因为时间不够"（不再追问） | 继续追问为什么时间不够 |

### 5.6 实战练习

**练习 1：个人问题**
- 选一个你最近遇到的困扰（如：总是熬夜、存不下钱、拖延症）
- 做 5 Whys 分析，找到根因
- 针对根因写一个行动方案

**练习 2：工作/学习问题**
- 选一个工作/学习中的问题
- 做 5 Whys 分析
- 区分"人的原因"和"系统/流程的原因"

**练习 3：社会现象**
- 选一个社会现象（如：交通拥堵、房价高）
- 做 5 Whys 分析（允许有多个因果链）

## 第六课：逻辑树 / 问题树（3天）

### 6.1 什么是逻辑树

逻辑树（Logic Tree / Issue Tree）是将一个复杂问题像树枝一样层层拆解的思维工具。

它帮助你：
- 把大问题变成小问题
- 确保不遗漏任何方面
- 找到可以行动的具体点

### 6.2 逻辑树的类型

#### 类型一：议题树（Issue Tree）

把一个议题拆成子议题。

```
如何提高利润？
├── 提高收入
│   ├── 提高单价
│   │   ├── 提价
│   │   └── 增加附加值
│   └── 增加销量
│       ├── 开发新客户
│       └── 增加老客户复购
└── 降低成本
    ├── 降低固定成本
    │   ├── 减少租金
    │   └── 减少设备投入
    └── 降低可变成本
        ├── 降低原材料成本
        └── 提高生产效率
```

#### 类型二：假设树（Hypothesis Tree）

提出假设，再找证据验证。

```
"销售额下降是因为竞争对手推出了更好的产品"
├── 假设 1：竞争对手确实推出了新产品
│   → 验证：调查竞品动态
├── 假设 2：新产品确实比我们好
│   → 验证：对比产品参数和用户评价
└── 假设 3：客户因为我们产品不如竞品而流失
    → 验证：客户调研
```

#### 类型三：是否树（Yes/No Tree）

用二选一的判断逐步缩小范围。

```
这个功能要不要做？
├── 用户是否需要？
│   ├── 是 → 继续判断
│   └── 否 → 不做
├── 技术上是否可行？
│   ├── 是 → 继续判断
│   └── 否 → 不做
└── 商业上是否划算？
    ├── 是 → 做
    └── 否 → 不做
```

### 6.3 逻辑树的构建原则

1. **MECE**：每一层拆解满足不重不漏
2. **可操作**：最终的子问题应该具体到可以找答案/做行动
3. **聚焦**：不要拆得太细，一般 3-5 层足够
4. **有依据**：每个拆分维度要有逻辑依据

### 6.4 构建步骤

**Step 1**：明确核心问题（写在最左边/最上面）

**Step 2**：确定第一层拆分维度
- 问自己："这个问题可以从哪几个维度来看？"
- 常用维度：
  - 公式拆分：利润 = 收入 - 成本
  - 流程拆分：获客 → 转化 → 留存
  - 人群拆分：新用户 / 老用户
  - 时间拆分：短期 / 中期 / 长期

**Step 3**：逐层细化
- 对每个子问题继续拆分
- 直到子问题足够具体、可以行动

**Step 4**：检验
- 是否 MECE？
- 是否遗漏了重要维度？
- 最底层的子问题是否可以回答/行动？

### 6.5 逻辑树 vs 思维导图

| 对比维度 | 逻辑树 | 思维导图 |
|---------|--------|---------|
| 结构 | 严格层级、MECE | 自由发散、联想 |
| 关键词 | 完整的问题或命题 | 单个关键词 |
| 目的 | 分析、拆解、论证 | 联想、创意、记忆 |
| 方向 | 通常从左到右或从上到下 | 从中心向四周 |
| 严谨度 | 高（需要逻辑支撑） | 低（自由发挥） |

### 6.6 实战练习

**练习 1：拆解一个商业问题**
- 问题："如何提升我们APP的用户活跃度？"
- 画出逻辑树，至少 3 层

**练习 2：拆解一个个人问题**
- 问题："如何提升个人竞争力？"
- 画出逻辑树

**练习 3：拆解一个学习问题**
- 问题："如何在 3 个月内通过 XX 考试？"
- 画出逻辑树

## 第七课：鱼骨图（因果图）（3天）

### 7.1 什么是鱼骨图

鱼骨图（Fishbone Diagram）又称石川图（Ishikawa Diagram），由日本质量管理大师石川馨在 1960 年代发明。

它用鱼骨架的形状，把一个问题的所有可能原因按类别系统排列，帮助你全面、结构化地分析因果关系。

### 7.2 鱼骨图的结构

```
  人员          方法           材料
   \            |              /
    \           |             /
     \          |            /
      ————————————————————————→ 问题（鱼头）
     /          |            \
    /           |             \
   /            |              \
  设备          环境           测量
```

- **鱼头**（右边）：问题/结果
- **大骨**：主要原因类别
- **中骨**：每个类别下的具体原因
- **小骨**：更细致的原因

### 7.3 常用分类框架

#### 制造业（6M）

| 类别 | 含义 |
|------|------|
| Man（人） | 操作者的技能、态度、状态 |
| Machine（机器） | 设备状况、维护保养 |
| Material（材料） | 原材料质量、规格 |
| Method（方法） | 操作流程、工艺方法 |
| Measurement（测量） | 检测方法、仪器精度 |
| Mother Nature（环境） | 温度、湿度、照明 |

#### 服务业（4P）

| 类别 | 含义 |
|------|------|
| Policies（政策） | 公司政策、流程规范 |
| Procedures（程序） | 操作步骤、标准流程 |
| People（人员） | 员工能力、态度 |
| Plant/Place（场所） | 物理环境、设施 |

#### 通用（4S）

| 类别 | 含义 |
|------|------|
| Surroundings（环境） | 周围环境因素 |
| Supplier（供应商） | 外部供应方 |
| System（系统） | 系统/流程/制度 |
| Skill（技能） | 人员能力 |

### 7.4 绘制步骤

**Step 1**：明确问题，写在右边画鱼头

**Step 2**：画主骨（一条水平线连接鱼头和鱼尾）

**Step 3**：确定主要原因类别，画大骨
- 选择合适的分类框架（6M / 4P / 4S / 自定义）
- 一般 4-6 个类别

**Step 4**：头脑风暴每个类别下的具体原因
- 每个类别下想出可能的原因
- 画成中骨

**Step 5**：深入追问
- 对每个中骨问"为什么"
- 画成小骨（可以结合 5 Whys）

**Step 6**：分析和筛选
- 从所有原因中找出最可能的 3-5 个根因
- 用圈标出

### 7.5 鱼骨图实战案例

**问题：为什么项目总是延期？**

```
    需求不清        经验不足       资源不足
      |               |             |
   需求频繁变更    新手多       人手不够
      |               |             |
    沟通不足        培训不够      同时接多个项目
      \              |             /
       \             |            /
        ———————————— 项目延期
       /             |            \
      /              |             \
  评估不准       工具落后        流程问题
      |               |             |
  过于乐观       没有项目管理    没有里程碑
      |          软件             |
  没考虑风险      |             审批流程长
                 手工跟踪
```

最可能根因：需求频繁变更、人手不够、没有里程碑

### 7.6 鱼骨图 vs 5 Whys vs 逻辑树

| 工具 | 适用场景 | 特点 |
|------|---------|------|
| 5 Whys | 单一问题的深度追问 | 纵向深入，找一条因果链 |
| 逻辑树 | 复杂问题的结构化拆解 | 横向展开，确保 MECE |
| 鱼骨图 | 问题的多因归类分析 | 按类别组织，适合团队 |

**最佳实践**：三者结合使用
1. 先用鱼骨图列出所有可能原因（广度）
2. 对最可能的原因用 5 Whys 深入（深度）
3. 用逻辑树组织解决方案

### 7.7 实战练习

**练习 1：工作问题**
- 问题："客户满意度下降"
- 画鱼骨图（用 4P 分类）

**练习 2：个人问题**
- 问题："为什么总是没时间学习？"
- 画鱼骨图（自定义分类）

**练习 3：团队练习**
- 找一个真实问题，组织 3-5 个人一起画鱼骨图
- 练习引导头脑风暴和归类

## 第八课：帕累托分析（80/20 法则）（2天）

### 8.1 什么是帕累托分析

帕累托分析基于帕累托法则（80/20 法则），由意大利经济学家帕累托提出：

**80% 的结果往往来自 20% 的原因。**

帕累托分析帮助你从众多因素中找到最关键的 20%，优先解决它们就能获得最大的效果。

### 8.2 经典案例

- 80% 的销售额来自 20% 的客户
- 80% 的投诉来自 20% 的问题
- 80% 的利润来自 20% 的产品
- 80% 的延误来自 20% 的原因
- 80% 的价值来自 20% 的功能

### 8.3 帕累托分析步骤

**Step 1**：确定分析对象
- 要分析什么？（问题类型、客户、产品等）

**Step 2**：收集数据
- 列出所有因素及其对应的数值（频次、金额、时间等）

**Step 3**：排序
- 按数值从大到小排列

**Step 4**：计算累计百分比

**Step 5**：找出"关键的少数"
- 累计占比约 80% 的那些因素就是关键因素

### 8.4 实战案例

**场景：分析客户投诉**

某公司上月收到 50 条客户投诉，分类统计：

| 投诉类型 | 数量 | 累计 | 累计百分比 |
|---------|------|------|-----------|
| 发货延迟 | 18 | 18 | 36% |
| 产品质量 | 12 | 30 | 60% |
| 客服态度 | 8 | 38 | 76% |
| 包装破损 | 5 | 43 | 86% |
| 价格问题 | 4 | 47 | 94% |
| 其他 | 3 | 50 | 100% |

**结论**：前 3 类问题（发货延迟、产品质量、客服态度）占投诉总量的 76%（接近 80%）。
**行动**：优先解决这 3 个问题。

### 8.5 帕累托分析的应用场景

| 场景 | 分析什么 | 80/20 洞察 |
|------|---------|-----------|
| 时间管理 | 各项活动花费的时间 | 20% 的活动产出 80% 的价值 |
| 学习 | 各知识点的学习时间 | 20% 的核心概念覆盖 80% 的考题 |
| 销售 | 各客户/产品的贡献 | 20% 的客户贡献 80% 的业绩 |
| 质量 | 各类缺陷的频次 | 20% 的缺陷类型占 80% 的问题 |
| 人际 | 各类社交活动 | 20% 的关系带来 80% 的快乐 |

### 8.6 帕累托图（柱状图 + 折线图）

帕累托图是可视化帕累托分析的工具：

```
数量 ↑                          累计百分比
18 |■■                                          100%
   |■■                                           90%
12 |■■ ■■                                        80%
   |■■ ■■                                        70%
 8 |■■ ■■ ■■                                     60%
   |■■ ■■ ■■                                     50%
 5 |■■ ■■ ■■ ■■                                  40%
   |■■ ■■ ■■ ■■                                  30%
 4 |■■ ■■ ■■ ■■ ■■                               20%
   |■■ ■■ ■■ ■■ ■■                              10%
 3 |■■ ■■ ■■ ■■ ■■ ■■                            0%
   ——————————————————————————
    发货延迟  产品质量  客服态度  包装破损  价格  其他
```

- 柱状图：各因素的数量（从高到低排列）
- 折线图：累计百分比

### 8.7 实战练习

**练习 1：时间帕累托分析**
- 记录一周的时间花费（各项活动的时间）
- 按时间从多到少排列
- 计算累计百分比
- 找出花费最多时间的 20% 活动
- 反思：这些高时间活动是否产出了高价值？

**练习 2：学习帕累托分析**
- 列出你正在学习的科目的所有章节/知识点
- 估算每个知识点在考试/实践中的权重
- 找出权重最高的 20% 知识点
- 优先深入学习这些核心内容

**练习 3：问题帕累托分析**
- 列出你目前面临的所有问题/困扰
- 按"影响程度"（1-10 分）给每个问题打分
- 从高到低排列
- 找出影响最大的 20% 问题
- 集中精力先解决这些问题

### 阶段综合练习

**任务：分析一个真实复杂问题**

选择一个你生活或工作中遇到的复杂问题，综合运用本阶段所有工具：

1. **用逻辑树拆解问题**：把大问题拆成 3-5 个子问题
2. **用鱼骨图分析原因**：对最关键的子问题画出鱼骨图
3. **用 5 Whys 深入根因**：对鱼骨图中最可能的 3 个原因做 5 Whys
4. **用帕累托分析确定优先级**：把所有原因按影响程度排序，找出关键的少数
5. **制定行动方案**：针对关键根因制定具体行动计划

**交付物**：一份完整的问题分析报告（包含上述 4 个工具的产出）

### 工具选择指南

| 当你需要… | 使用工具 |

| 快速找到一个问题的大致根因 | 5 Whys |

| 在团队中讨论问题原因 | 鱼骨图 |
| 确定优先解决哪些问题 | 帕累托分析 |
| 组合使用 | 逻辑树 → 鱼骨图 → 5 Whys → 帕累托 |
