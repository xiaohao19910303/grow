## 第二十一课：商业管理工具（持续）

### 21.1 波特五力分析（Porter's Five Forces）

**用途**：分析一个行业的竞争格局和吸引力。

**五个力量**：

```
                 新进入者的威胁
                      ↓
  供应商 ──→ 行业内竞争 ←── 买方
  议价能力     现有企业       议价能力
                      ↑
                 替代品的威胁
```

| 力量 | 分析要点 |
|------|---------|
| 行业内竞争 | 竞争对手数量、行业增速、产品差异化程度、退出壁垒 |
| 新进入者威胁 | 进入壁垒高低、规模经济、品牌忠诚度、资本需求 |
| 替代品威胁 | 替代品数量、性价比、用户转换成本 |
| 供应商议价能力 | 供应商集中度、转换成本、供应品差异化 |
| 买方议价能力 | 买方集中度、购买量、产品标准化程度 |

**使用方法**：
1. 逐一分析五个力量的强弱
2. 综合评估行业吸引力
3. 确定竞争策略

### 21.2 BCG 矩阵（波士顿矩阵）

**用途**：管理产品组合，决定资源分配。

```
              高增长
                │
   问号         │      明星
  （Question Mark）│   （Star）
  低份额 ────────┼──────── 高份额
   瘦狗         │      金牛
  （Dog）       │   （Cash Cow）
                │
              低增长
```

| 类型 | 特征 | 策略 |
|------|------|------|
| 明星 | 高增长 + 高份额 | 加大投资，保持领先 |
| 金牛 | 低增长 + 高份额 | 维持现状，收割利润 |
| 问号 | 高增长 + 低份额 | 选择性投资，或退出 |
| 瘦狗 | 低增长 + 低份额 | 考虑退出或剥离 |

### 21.3 商业模式画布（Business Model Canvas）

**用途**：梳理和分析一个商业模式。

**9 个模块**：

```
┌──────────┬──────────┬──────────┬──────────┬──────────┐
│ 关键合作  │ 关键活动  │ 价值主张  │ 客户关系  │ 客户细分  │
│          │          │          │          │          │
├──────────┼──────────┤          ├──────────┼──────────┤
│ 关键资源  │          │          │ 渠道通路  │          │
│          │          │          │          │          │
├──────────┴──────────┼──────────┴──────────┴──────────┤
│     成本结构         │          收入来源               │
└─────────────────────┴──────────────────────────────────┘
```

| 模块 | 问题 |
|------|------|
| 客户细分 | 我们服务哪些客户群体？ |
| 价值主张 | 我们为客户创造什么价值？ |
| 渠道通路 | 我们通过什么渠道触达客户？ |
| 客户关系 | 我们与客户建立什么关系？ |
| 收入来源 | 客户愿意为什么付费？ |
| 关键资源 | 我们需要什么核心资源？ |
| 关键活动 | 我们需要做哪些关键活动？ |
| 关键合作 | 我们的合作伙伴是谁？ |
| 成本结构 | 我们的成本有哪些？ |

### 21.4 OKR（Objectives and Key Results）

**用途**：目标管理，对齐团队方向。

**结构**：
- **Objective（目标）**：定性的、鼓舞人心的方向
- **Key Results（关键成果）**：定量的、可衡量的指标（2-5 个）

**示例**：
```
O：成为用户最爱的外卖平台
  KR1：用户满意度从 4.0 提升到 4.5
  KR2：订单准时率从 85% 提升到 95%
  KR3：用户投诉率降低 50%
```

**OKR vs KPI**：

| 维度 | OKR | KPI |
|------|-----|-----|
| 目的 | 突破性目标 | 日常运营指标 |
| 难度 | 挑战性（完成 70% 算成功） | 可实现（完成 100% 是正常） |
| 频率 | 季度/月度 | 持续跟踪 |
| 公开性 | 全公司公开 | 通常部门内部 |

### 21.5 PESTEL 分析

**用途**：分析宏观环境。

| 维度 | 分析要点 |
|------|---------|
| Political（政治） | 政策法规、政府稳定性、贸易政策 |
| Economic（经济） | GDP 增速、利率、汇率、通胀 |
| Social（社会） | 人口结构、消费习惯、文化趋势 |
| Technological（技术） | 技术变革、创新速度、数字化程度 |
| Environmental（环境） | 环保法规、气候变化、可持续发展 |
| Legal（法律） | 劳动法、知识产权、数据保护 |

## 第二十二课：产品与设计工具（持续）

### 22.1 用户旅程图（User Journey Map）

**用途**：可视化用户体验的全流程，发现痛点。

**结构**：

```
阶段    │ 发现    │ 考虑    │ 购买    │ 使用    │ 推荐
────────┼────────┼────────┼────────┼────────┼────────
用户行为 │ 搜索产品│ 比较选择│ 下单付款│ 使用产品│ 分享给朋友
触点    │ 广告    │ 官网    │ App    │ 产品    │ 社交媒体
情绪    │   😐    │   😟    │   😊    │   😡    │   😄
痛点    │ 找不到  │ 信息不清│ 流程复杂│ 功能bug │ 没有引导
机会    │ SEO优化 │ 简化信息│ 一键购买│ 快速修复│ 激励机制
```

### 22.2 人物画像（Persona）

**用途**：构建典型用户模型，指导产品决策。

**模板**：

```
姓名：小明
年龄：28 岁
职业：互联网产品经理
照片：[头像]

目标：
- 提高工作效率
- 获得职业晋升

痛点：
- 会议太多，没时间深度工作
- 信息分散在多个工具

场景：
- 每天处理 50+ 条消息
- 每周参加 10+ 场会议

引用：
"我希望有一个工具能帮我整合所有信息"
```

### 22.3 KANO 模型

**用途**：分类用户需求，指导优先级。

**需求分类**：

| 类型 | 含义 | 示例 |
|------|------|------|
| 基本需求（Must-be） | 没有会不满，有了觉得正常 | 手机能打电话 |
| 期望需求（One-dimensional） | 有会更好，没有会不满 | 电池续航长 |
| 兴奋需求（Attractive） | 有了会惊喜，没有也不会不满 | 无线充电 |

**优先级**：基本需求 > 期望需求 > 兴奋需求

### 22.4 优先级排序

#### RICE 模型

| 因子 | 含义 | 评分 |
|------|------|------|
| Reach（影响范围） | 影响多少用户？ | 用户数 |
| Impact（影响程度） | 对每个用户影响多大？ | 3=大/2=高/1=中/0.5=低/0.25=极低 |
| Confidence（信心） | 对评估有多大把握？ | 100%=高/80%=中/50%=低 |
| Effort（工作量） | 需要多少人月？ | 人月数 |

**RICE 分数 = (Reach × Impact × Confidence) / Effort**

#### MoSCoW 方法

| 类别 | 含义 |
|------|------|
| Must have | 必须有，没有不能上线 |
| Should have | 应该有，但不上线也可以 |
| Could have | 可以有，时间充裕就做 |
| Won't have | 这次不做 |

## 第二十三课：项目管理工具（持续）

### 23.1 WBS（工作分解结构）

**用途**：把项目拆成可管理的任务。

**原则**：
- 100% 原则：下层之和 = 上层的全部内容
- 每个任务可交付一个成果
- 最底层任务可以在 80 小时内完成

**示例**：

```
网站改版项目
├── 规划阶段
│   ├── 需求调研
│   ├── 竞品分析
│   └── 项目计划
├── 设计阶段
│   ├── 信息架构
│   ├── 视觉设计
│   └── 交互设计
├── 开发阶段
│   ├── 前端开发
│   ├── 后端开发
│   └── 数据库设计
└── 上线阶段
    ├── 测试
    ├── 部署
    └── 上线后监控
```

### 23.2 甘特图

**用途**：可视化项目时间线和进度。

```
任务          │ W1 │ W2 │ W3 │ W4 │ W5 │
─────────────┼────┼────┼────┼────┼────┼
需求调研      │████│    │    │    │    │
设计          │    │████│████│    │    │
开发          │    │    │████│████│    │
测试          │    │    │    │████│    │
上线          │    │    │    │    │████│
```

### 23.3 PDCA 循环

**用途**：持续改进。

```
     Plan（计划）
       ↓
Do（执行）← Act（改进）
       ↑
     Check（检查）
```

| 阶段 | 内容 |
|------|------|
| Plan | 确定目标、制定计划 |
| Do | 执行计划 |
| Check | 检查结果、对比目标 |
| Act | 标准化成功经验、改进不足 |

### 23.4 看板（Kanban）

**用途**：可视化工作流程，限制在制品。

**基本列**：

```
待办 │ 进行中 │ 已完成
─────┼───────┼──────
任务1│ 任务3 │ 任务5
任务2│ 任务4 │ 任务6
任务7│       │ 任务8
```

**核心原则**：
- 可视化工作
- 限制在制品（WIP Limit）
- 管理流动
- 持续改进

## 第二十四课：个人效能工具（持续）

### 24.1 GTD（Getting Things Done）

**用途**：任务管理，清空大脑。

**5 个步骤**：

```
收集 → 处理 → 组织 → 回顾 → 执行
```

| 步骤 | 内容 |
|------|------|
| 收集 | 把所有待办事项记录下来（不留在脑子里） |
| 处理 | 判断：要不要做？下一步是什么？ |
| 组织 | 分类：下一步行动/项目/等待/将来也许 |
| 回顾 | 每周回顾所有清单 |
| 执行 | 根据情境、时间、精力选择当前任务 |

### 24.2 番茄工作法

**用途**：提升专注力。

**流程**：
1. 选一个任务
2. 设定 25 分钟计时
3. 专注工作，直到计时响起
4. 短休息（5 分钟）
5. 每 4 个番茄，长休息（15-30 分钟）

**关键**：一个番茄时间内只做一件事。

### 24.3 费曼学习法

**用途**：深度学习，检验理解。

**步骤**：
1. 选择一个概念
2. 用简单语言教给别人（假设对方完全不懂）
3. 发现卡壳的地方——这就是你不懂的地方
4. 回去学习，直到能流畅讲解

### 24.4 复盘法

**用途**：从经验中学习。

**4 步**：

| 步骤 | 问题 |
|------|------|
| 回顾目标 | 当初的目标是什么？ |
| 评估结果 | 实际结果如何？ |
| 分析原因 | 差距的原因是什么？ |
| 总结规律 | 学到了什么？下次怎么做？ |

### 24.5 习惯追踪

**用途**：建立和保持好习惯。

**方法**：
- 每日打卡（视觉化进展）
- 不连续断两次（允许偶尔失误）
- 环境设计（让好习惯容易，坏习惯难）
- 习惯叠加（在已有习惯后加新习惯）

## 第二十五课：战略与规划工具（持续）

### 25.1 情景规划（Scenario Planning）

**用途**：应对不确定性，推演多种未来。

**步骤**：
1. 确定决策焦点
2. 识别关键不确定性（2 个最重要的）
3. 构建 2×2 矩阵（4 个情景）
4. 对每个情景描述详细故事
5. 制定应对策略

**示例**：

```
              经济繁荣
                │
    乐观情景    │    稳健情景
   （高增长+开放）│  （高增长+保守）
              │
  技术开放 ────┼──── 技术保守
              │
    冒险情景    │    保守情景
   （低增长+开放）│  （低增长+保守）
              │
              经济衰退
```

### 25.2 蓝海战略

**用途**：寻找无竞争的新市场。

**ERRC 框架**：

| 动作 | 问题 |
|------|------|
| Eliminate（消除） | 哪些行业认为理所当然的因素可以消除？ |
| Reduce（减少） | 哪些因素可以减少到行业标准以下？ |
| Raise（提升） | 哪些因素可以提升到行业标准以上？ |
| Create（创造） | 哪些行业从未提供的因素可以创造？ |

### 25.3 反脆弱思维

**用途**：从不确定性中获益。

| 类型 | 特征 |
|------|------|
| 脆弱 | 受到冲击会受损 |
| 韧性 | 受到冲击能恢复 |
| 反脆弱 | 受到冲击反而变强 |

**反脆弱策略**：
- 杠铃策略：90% 极度保守 + 10% 极度冒险
- 小规模试错：快速失败、快速学习
- 冗余设计：保持一定的"浪费"

### 25.4 博弈论基础

**用途**：多方互动中的策略选择。

**经典模型**：

| 模型 | 场景 | 启示 |
|------|------|------|
| 囚徒困境 | 合作 vs 背叛 | 重复博弈中合作更有利 |
| 智猪博弈 | 大企业 vs 小企业 | 小企业可以"搭便车" |
| 零和博弈 | 一方所得 = 另一方所失 | 寻找双赢的可能 |
