# 旧模块云端迁移与验证

日期：2026-10-17。适用范围：旧认知课程、认知阅读、早期 PostgreSQL `id/data` 建表结果，以及本机旧 SQLite 记录。

## 存储合同

| 内容 | 权威存储 |
|---|---|
| 认知课程正文、参考资料、明确选定的备课摘要、课程主题规划、公开课程目录 | GitHub；数据库保存路径、哈希与不可变 commit SHA |
| 学习状态、复盘答案、学习总结、用时、个人学习记录 Markdown | PostgreSQL；完成反馈不再改写公开课程目录 |
| 阅读原文、已采用的中文导读、详细总结和英语学习资料 | GitHub；始终按发布时 commit SHA 读取 |
| 阅读笔记、收藏/已读/归档状态、生词复习、个人翻译及整理草稿、偏好和搜集日志 | PostgreSQL；不向 GitHub 提交这些文件或字段 |
| 生成任务、草稿、发布日志、迁移来源和原记录副本 | PostgreSQL |
| AI 配置 | 仍仅在浏览器；请求临时使用，无服务端密钥回退 |

保留原 `/api/copilot` 和 `/api/reading` 接口，云端适配器不依赖 Render 临时磁盘。阅读页面可打开相应 GitHub 原文。旧文件解析器通过只读文档接口访问 GitHub/数据库，不能把私人文件写到内容仓库。

## 保留数据的迁移协议

1. `legacy_schema.migrate()` 在当前账号的 PostgreSQL schema 中持有事务锁，先保存现有行到 `legacy_original_rows`。不兼容表改名为 `__legacy_v3`，原表原列原值保留；创建规范表并建立 `legacy_row_map`。不使用 DROP 清表迁移。
2. 规范化学习记录、草稿、阅读生词/复习、行为、错误、行为报告和知识关联等表。转换旧 ID 时保留映射及关联。JSON 无效、必填字段不足或关联不明的行保留在归档和映射中，报告 `needs_review`，不编造完成状态。
3. SQLite 通过只读连接、一致性读事务获取快照。每个来源行均存入 `sqlite_source_rows`；缺失记录进入远端活动表，已有不同版本保留远端版本并留存本地原文副本。知识节点按来源、类型和名称映射，避免扫描编号碰撞。密钥配置不导入。
4. 文件迁移先预览，返回绑定来源哈希、当前数据库记录、仓库绑定和 GitHub HEAD 的 token。执行时重新核对，变化则拒绝；不改写或删除来源文件。
5. 正式 Markdown 在同一次 GitHub 提交中发布，私人文档和相关数据库记录在最终数据库事务中保存；原始来源另存迁移映射。文章文件镜像不会覆盖已有个人状态和草稿。
6. 发布日志先保存候选 commit SHA，再更新分支。响应丢失或进程重启后通过提交祖先关系恢复；不会强制推送，也不会重复调用 AI。外部改动冲突时保留双方，已发布的旧版本仍可按原 SHA 阅读。

旧学习记录和文章元数据包含个人字段，不能作为公开课程目录直接上传。首次引入的旧密钥字段被清理，不写入迁移归档；其他原始记录完整保留。旧 SQLite 文件与原目录继续留在本机，不作为运行时主数据。

## 操作入口

服务端需配置 PostgreSQL 和 GitHub 内容仓库；使用 `PLAN_CONTENT_BACKEND=github`。先在本机隔离环境验证，再对目标数据库执行。迁移不需要 AI Key。

```bash
cd 知行成长/server
python -m create_tables
python -m legacy_sqlite /绝对路径/旧data.db
python -m legacy_sqlite /绝对路径/旧data.db --apply-token 上一步返回的token
python -m legacy_files --root /绝对路径/资料根目录
python -m legacy_files --root /绝对路径/资料根目录 --apply-token 上一步返回的token
```

`GET /api/migrations` 返回 schema 归档、文件迁移与待恢复发布摘要，不返回原始笔记正文。原数据所有者可调用 `POST /api/migrations/files/preview`、`/files/apply` 和 `/recover`；写请求须带 `X-Copilot-Request: 1`。HTTP 迁移只接受服务端配置的资料根目录，不能由浏览器提供任意磁盘路径。多账号环境不会导入其他账号的原目录。

SQLite 来源差异在 `sqlite_imports` 汇总，原文在 `sqlite_source_rows`，schema 原行在 `legacy_original_rows`。这些都是私密数据库数据，不属于公开内容仓库。恢复前应停止相关写入，依据来源映射和发布 SHA 核对，不能删除恢复日志或直接覆盖新记录。

## 验证范围

- 隔离 PostgreSQL：旧建表脚本的所有不兼容形态、原表保留、ID 与关联映射、重复迁移、无效行保留、SQLite 只读导入与远端差异保留。
- 实际 HTTP 接口：课程生成、正式发布、学习反馈、阅读导读生成、迁移摘要和所有者权限。
- GitHub HTTP 模拟：私密内容排除、不可变读取、外部编辑冲突、分支更新响应丢失及重启恢复。
- Chromium：旧课程生成和发布、本人确认完成、阅读笔记保存、AI 导读生成、刷新后读回；验证浏览器错误与失败请求。
- 真实资料隔离演练：读取 121 行 SQLite 来源记录、33 份文件（18 份正式 Markdown、15 份私人文档），恢复 5 节旧课程和 6 篇阅读资料；来源不变，课程扫描无阻塞。

真实远端执行结果另记录于本文件后续的执行记录；隔离测试不使用真实付费模型。

## 旧 SQLite 夹具收尾（2026-10-17）

旧课程、学习计划、阅读、状态同步与复盘的业务测试已统一使用隔离 PostgreSQL 和 GitHub HTTP 模拟器。`SQLitePlans` 运行时替身已移除；SQLite 只用于旧数据库只读导入、旧配置清理和 v1/v2 离线归档兼容测试，原数据与旧备份格式仍保留。

本轮还修复了夹具更新后暴露的实际迁移问题：

- 旧草稿族关系在一个事务内补齐，失败整批回滚并可重试；异常关系保留原文，不猜测父子关系。
- GitHub 发布重试返回持久化的完整结果，包括提交 SHA；远端存储不能误调用旧本地备份入口。
- 正式学习计划不再创建公开的个人学习记录 Markdown；旧备份两种配置表结构均移除过时 AI 设置，来源数据库不变。

- 模型生成统一受已持久化截止时间约束；浏览器自带 AI 配置仍为强制要求，不回退服务端密钥。
