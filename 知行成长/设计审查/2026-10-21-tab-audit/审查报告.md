# 五个 Tab 的功能分类与交互闭环审查

日期：2026-10-21（北京时间）  
对象：知行成长本地工作区的当前前端与后端实现。工作区有其他未提交改动；本文描述本轮捕获的状态，不代表线上部署版本。  
方式：内嵌浏览器实际操作、页面截图与 DOM 检查、独立 PostgreSQL 实例中的真实业务接口、源码核对。GitHub 和课程资料使用项目已有合成夹具，未使用真实账号、真实仓库、付费模型或个人学习数据。本轮只产出审查资料，未修改业务代码。

## 结论

五个主 Tab 的方向成立，建议保留「今日、行动、学习、记录、成长」。功能覆盖已经较广，但还不能判定分类和交互逻辑完整。主要短板是：跨模块完成状态不同步、记录不能可靠找回、统计口径不一致，以及新旧入口并存。

当前更需要补齐已存在功能的闭环，而不是继续增加主 Tab。建议先处理下面 5 项 P1，再整理二级导航。

## 确认的 P1 问题

### P1-01：两个“记几句”入口都打不开

复现：今日点击“记几句”；或者记录 → 每日复盘 → “记几句”。页面不出现编辑器，控制台为 `Cannot read properties of undefined (reading 'version')`。

原因：`openEditor(date, entryId)` 的调用把日期放到了第二个参数，导致日期被当作已有记录 ID，访问不存在的 `entryMap[entryId].version`。

位置：`server/static/index.html:343`、`:710`，`server/static/reflections.js:57`。

修复建议：新建时明确传日期、不传记录 ID；编辑时先检查目标记录是否存在。入口失败要有可见提示，保留现有列表。

验收：今日、历史日期、记录页三个入口都能新建；已有记录可以编辑；未知 ID 不导致静默异常。

### P1-02：全局搜索与时间线会把已有数据显示成没有数据

浏览器实测：已保存的“本轮体验验证”课程笔记，在全局搜索中返回零条。接口对照：合成决策在全部范围为 0 条，指定 `decision` 为 1 条；已保存复盘在全部时间线为 0 条，指定 `review` 为 1 条。

原因有两层：学习、反思仍指向 `custom_records`，没有接入真实课程完成/笔记与 `reflection_entries`；查询又使用该旧表没有的 `date` 字段。查询异常被吞掉，PostgreSQL 当前事务随后仍处于失败状态，连后续本来有效的模块也被当作空结果。

位置：`server/search_service.py:18`、`:160`；`server/timeline_service.py:20`、`:145`。

修复建议：为课程记录、笔记、日常记录、文章和行动记录建立明确的查询适配；每个模块故障隔离。区分“没有匹配内容”和“部分来源读取失败”，不要静默显示全空。

验收：同一关键词的全部结果包含各模块结果；任一来源故障不影响其他来源；搜索结果能打开准确的原记录。

### P1-03：学完后的状态不能立即贯通今日与行动

复现：安排课程到今日，从今日开始，暂存笔记并返回后重开，点击标记学完。阅读页已显示学完；返回今日仍是 0/1、正在进行，底部执行条还在。此时点击核对完成提示“计划已被另一页面更新”。进入行动后刷新恢复为已完成，执行条消失。

这是前端旧快照，不是已确认的后端记录丢失。源码中完成保存只刷新课程列表，行动状态通常等下一次读取或 30 秒轮询更新。

位置：`server/static/daily-learning.js:288` 附近；`server/static/action-plans.js:312`。后端 `with_content_completion` 已负责联动完成。

修复建议：源内容完成后刷新或合并行动快照，再更新今日摘要、执行条和历史。同步失败时显示“课程已保存，安排待同步”，核对先取得最新版本，不让用户遇到伪并发冲突。

验收：学完后立即显示完成且停止执行条；重新点击不重复完成；刷新、响应丢失、同步失败可恢复。

### P1-04：成长足迹和周报对同一次学习给出不同结论

对同一份隔离数据，自动足迹含 2026-10-21 的结构化表达完成；成长总览显示连续 1 天、今日 1/8。调用真实 `build_report(7)` 却得到记录天数 0、连续 0 天，结构化表达完成天数也为 0。

原因：前端足迹已合并自动完成来源；后端周报、连续天数及 AI 摘要仍主要读取旧 `checkins`、手工 `habits`。课程学习时长、行动本人确认投入、手工补记时长也是不同事实，不能不加说明地混称学习时长或直接相加。

位置：`server/app.py:378`、`:398`，`server/behavior_report/analyzer.py:11`。

修复建议：统一“完成/活动天数”的事实来源；明确三种时长的定义、补记规则和去重方式。周报需使用与足迹一致的数据口径。

验收：同一课在足迹、日历、总览、周报中的完成日期一致；暂存不计完成；一次投入不因多个来源重复累计。

### P1-05：AI 报告把生成失败保存成成功报告

真实接口在隔离数据库中返回 HTTP 201，保存的报告正文却是“AI 分析失败 / cannot import name call_ai”。当前 `copilot.core` 没有该导出；生成函数捕获异常后返回错误文本，路由继续把它作为成功报告存储。前端对正常 HTTP 响应会提示报告已生成。

位置：`server/behavior_report/analyzer.py:158`；`server/behavior_report/api.py:17`；`server/static/index.html` 的 `generateNewReport`。

修复建议：接入当前统一的用户 AI 配置与生成任务接口，失败保持明确失败状态，不写入成功报告列表。需要配置时给出设置入口，重试保留数据范围。

验收：配置缺失、模型失败、取消、重试和真正成功有不同且正确的状态；失败不产生成功报告。

## 功能分类建议

| 主 Tab | 应负责的用户问题 | 当前问题 | 建议收敛方式 |
|---|---|---|---|
| 今日 | 今天做什么，现在从哪开始 | 新增待办、计时行动、学习安排三种入口并列；课程返回文案与实际来源不符 | 保留当日安排与复盘，创建入口先选待办/计时/内容；返回按钮按来源命名。 |
| 行动 | 目标如何拆解，何时执行，做得如何 | 年月周日、长短期、状态、平铺/树形同时显露；执行记录重复 | 保留日程、目标与计划、执行回看；低频选项渐进展开，计划页只给近期记录摘要。 |
| 学习 | 学什么，怎么继续，怎样补充内容 | 我的课程、课程计划、课程管理边界不易理解；课程管理实际上是认知模块的学习副驾驶 | 我的课程负责学习；阅读负责文章；课程计划明确是课程大纲，区别行动计划。认知专用管理作为模块工具，或清楚标注范围。 |
| 记录 | 留下经历与思考，之后能找回来 | 9 个同级入口；每日复盘页同时叫日常记录和历史四问；实践、错误、决策各自孤立 | 日常记录统一承载自由记录与四问模式；应用/错误归为实践记录；决策/预测成组；投资、自定义作为低频入口。 |
| 成长 | 学习产生了什么变化，下一步调整什么 | 8 个同级入口；全局搜索在此重复出现；报告和多个学习历史视图分散 | 合并学习日历/足迹/时长为学习历史的视图；周月报与 AI 报告归为阶段报告；搜索保留顶栏全局入口。 |

同一份学习历史不必在多个位置建立独立数据模型；可以保留快捷入口，但指向同一页和同一组筛选。不要为了减少按钮而删除用户已有数据或让旧入口失效。

## 其他体验改进（P2）

1. **记录 → 下一次行动还缺少明确承接。** 四问的“下次怎么改”目前是一段文字，建议提供“转为行动”并预填内容，用户确认日期后创建；课程完成后也可提供“实践一次”的轻入口。不要自动把每条笔记变成任务。
2. **统一保存语义。** 课程笔记有本机暂存与云端同步，文章笔记需手动保存，旧四问经全量状态异步保存。各页面应持续显示正在保存/已保存/待同步/失败，离开前提供保存并离开、保留草稿、放弃三种清楚选择。
3. **学习日历样式与键盘操作需要补齐。** `learning-history.css:365` 局部跟随系统深色，主体仍为浅色，`.history-stats` 的文字颜色未同步。日期格为仅带 `onclick` 的 div（`learning-history.js:146`），应改用可聚焦按钮或完整日历网格语义，支持键盘选择和读屏播报。
4. **长页面降低信息密度。** 学习列表每一课都显示安排今日/明日/选日期，成长总览堆叠多套图表。优先显示继续/查看，安排收进一个入口；成长总览先给近期变化和可执行建议，图表放详情。
5. **补齐空态、失败态和状态解释。** “暂无记录”应说明范围与筛选，提供对应创建入口；请求失败应能重试。默认 8 个学习模块与当前可学习的 3 类内容也应解释，未启用模块可折叠。不要让“完成方式”“完成状态”和“投入时长”互相替代。
6. **导航恢复规则需要统一。** 主 Tab 会记住本次会话最后一个子页，但普通子页没有持久路由，刷新会回到今日；阅读却有可恢复 hash。建议给可分享/可回看的视图统一 URL、刷新恢复和浏览器返回规则。

## 测试结果与边界

- Python 本轮运行记录 77 项：75 通过、2 个错误、0 跳过。一个错误是旧学习足迹集成路径在 PostgreSQL 中执行 `PRAGMA table_info`；另一个是旧课程闭环模块缺 `pytest`，未能导入。不能据此宣称全量回归通过。
- 5 个 JavaScript 脚本通过：行动客户端、阅读生成任务、阅读导航、学习草稿会话、学习加载。覆盖重试、账号隔离、暂存恢复、并发版本和迟到响应等已有用例；它们并未覆盖本轮发现的全部真实入口。
- 数据库独立实例仅监听 127.0.0.1:55446；每个后端用例使用独立临时 schema。隔离审计记录真实数据库访问拦截、工作区写入拦截、外网连接拦截次数均为 0。
- 周报浏览器夹具未注册真实报告路由，曾出现 undefined；错误列表因夹具兜底路由影响斜杠重定向出现加载失败。这两种夹具现象未作为产品缺陷。周报结论来自同一数据库对真实 `build_report` 的调用。
- 登录、多用户邀请、生产网络、真实 GitHub 发布、真实 AI 调用、系统通知和所有异常组合不在本轮完整验收范围。课程计划、课程管理仅核对分类和源码，未完成这两个子页的端到端生成流程。
- 文章未保存确认触发后内嵌浏览器控制超时，未完成取消/放弃分支以及后续待办提交验证；未将这些未完成步骤记为通过或产品故障。窄屏只确认今日页布局，不代表全部页面已适配。
- 截图、DOM 和源码检查不足以证明完整 WCAG 合规；本轮没有完成读屏、全键盘及全部对比度测试。

## 建议实施顺序

第一轮修复 5 项 P1，逐一加入能覆盖真实入口与跨页数据的一致性用例。第二轮保留五主 Tab，统一记录模型和学习历史，再收敛二级导航。第三轮补齐全部窄屏、键盘、未保存离开、网络失败与刷新恢复验收。
