## B. 真实数据运转（用户侧地基 · 非代码）

教练洞察依赖真实样本，空表产出的「教练报告」是空转。此项需用户本人执行。

- [ ] **B1** 连续 1 周真实记录：每日四问复盘、预测（附自报概率）、1 个关键决策。
- [ ] **B2** 用「学习计划」生成一套真实规划，学完第 1 课，完整走通 GitHub 内容链路。
- [ ] **B3** 每周日跑一次「行为分析报告」，判断输出是否有意义。

**验收**：`reviews / predictions / decisions / behavior_applications` 各表产生**真实**记录（可区分测试样本）。

## C. 规划 ↔ 行动闭环（代码 · 中风险）

现状：`plans`（AI 生成学习规划）与 `action_plans`（行动计划执行）两套体系独立，生成不落地、学完不回流。

- [x] **C1** 学习计划采用时可选关联，已有规划可从详情关联／同步。只为已发布且未学完课程补入未安排内容行动，后续发布自动补齐；复用已有安排，不改写本人日期和取消状态，失败可单独重试。
- [x] **C2** 复用已有 plans 课程本人完成确认及来源回执：已安排今日的内容行动回写一次完成；无日期行动不补造执行。课程反馈同时更新规划学习进度。该能力原已存在，本轮补做端到端回归。
- [x] **C3** 「行动 → 目标与计划」显示整体／阶段学习进度条，区分已发布、本人学完和行动状态；分母包含未发布课程，草稿与分钟不计学完。

**涉及文件**：`server/learning_actions.py`、`server/plans/{store,api}.py`、`server/action_plans.py`、`static/learning-plan-actions.js` 与规划／行动页面。用户操作见[使用说明](../../docs/learning-plan-actions.md)。

**验收**：从「生成规划 → 学习 → 完成」全程无需重复录入，进度在行动栏目可见。

## D. 教练「主动提醒」最小版（代码 · 低-中风险）

已有行动定时提醒及日常节奏站内提醒。本轮在它们的前台刷新循环中接入事实卡片，不新增付费生成或推送通道。

- [x] **D1** 今日／成长总览加载时自动展示一条「教练今日提醒」，仅依据当前账号已保存数据，包含日期范围、来源和样本边界。无模型调用；支持事实、空态、失败重试和按账号当天收起，不合计重叠时长。
- [x] **D2** 确定性阈值：前三个完整日均有正样本且分类记录数递减；课程最近学完确认距今至少14天；本周有效已核对预测至少5条才展示准确率。只说明记录，不把它们解释成实际能力下滑、没有复习或概率校准结论。规则见[使用说明](../../docs/coach-fact-reminders.md)。
- [ ] **D3** 行为分析报告从「手动生成」加一个「登录时自动跑（可关）」开关，复用 `analyzer.collect_data_summary`。

**涉及文件**：`server/coach_facts.py` 复用 `growth_statistics.py`；`static/coach-facts.js` 接入首页、成长页、确认保存和已有行动提醒循环。行为报告生成保持原入口。

**验收**：打开今日或成长总览无需点击生成即显示数据库事实；无 AI 配置也可使用。样本不足、数据库异常和账号变化不产生假结论；到时行动优先、辅助读取不阻塞完成反馈。隔离 API／PG、Node 与真实 Chrome 专项见上述验收链接，不能据此声称已上线。
