## 第一课：金字塔原理（2天）

### 1.1 什么是金字塔原理

金字塔原理（Pyramid Principle）由麦肯锡顾问芭芭拉·明托在 1987 年提出，是一种结构化思考和表达的方法。

核心思想：**任何事情都可以归纳出一个中心论点，而此中心论点可由三至七个论据支持，这些论据本身也可以是个论点，被更次一级的论据支持，如此延伸，形成金字塔结构。**

### 1.2 金字塔的四大原则

#### 原则一：结论先行

**错误示范**：
> "上周客户投诉了 3 次，都是关于发货延迟的问题。仓库那边说是因为供应商交货晚了。另外，我们新来的同事对系统还不太熟悉，处理订单慢了一些。综合来看，我觉得我们的发货流程需要改进。"

**正确示范**：
> "我建议优化发货流程。原因有三：第一，上周客户因发货延迟投诉了 3 次；第二，供应商交货不稳定；第三，新员工操作效率有待提升。"

**为什么结论先行？**
- 听众的注意力在前 30 秒最集中
- 先有结论，后面的论据才有"归属"
- 符合大脑处理信息的方式——先有框架，再填细节

#### 原则二：以上统下

每一层的论点必须能概括其下一层的所有内容。

```
        我们应该换工作
       /      |      \
    收入更高  发展更好  生活质量提升
    /  \      /  \       /  \
  薪A   薪B  晋升  学习  通勤  环境
```

检验方法：如果去掉上层，下层的要点能否被自然总结成上层的话？如果不能，说明以上统下不成立。

#### 原则三：归类分组

同一组的内容必须属于同一逻辑范畴。

```
✅ 正确分组（都是"改进措施"）：
   改进方案
   ├── 增加人手
   ├── 优化流程
   └── 引入工具

❌ 错误分组（混了不同范畴）：
   改进方案
   ├── 增加人手（措施）
   ├── 成本太高（问题）
   └── 优化流程（措施）
```

#### 原则四：逻辑递进

同一组内的论点排列要有逻辑顺序。

三种常见顺序：
- **时间顺序**：第一步 → 第二步 → 第三步
- **结构顺序**：内部 → 外部；上部 → 下部
- **重要性顺序**：最重要 → 次重要 → 一般

### 1.3 金字塔的构建方法

**方法一：自上而下（适合已有结论）**

1. 确定中心论点（塔尖）
2. 设想听众会问什么问题
3. 给出回答（第一层论据）
4. 继续问：每个回答需要什么支撑？
5. 逐层展开，直到有足够的事实支撑

**方法二：自下而上（适合还在思考中）**

1. 列出所有想表达的要点
2. 找出要点之间的关系
3. 把相关的要点归为一组
4. 为每组提炼一个上层结论
5. 继续向上归纳，直到形成中心论点

### 1.4 实战练习

**练习 1：改造一段话**

原始文字：
> "我觉得我们的团队需要改进沟通方式。上周有两个项目因为信息不同步出了差错。A 项目是因为设计改了但开发不知道，B 项目是因为需求变了但测试不知道。另外，我们的周会经常有人缺席，信息传达不到位。还有，群里的消息太多，重要的通知经常被淹没。"

请用金字塔原理重新组织。

参考答案：
> **我们的团队需要改进沟通方式，具体有三个改进方向：**
>
> 1. **建立信息同步机制**：上周 A 项目设计修改未通知开发、B 项目需求变更未通知测试，说明跨角色信息传递存在断层。
> 2. **提高周会效果**：目前周会缺席率高，信息传达不到位，需要确保关键人员参与或建立会后纪要机制。
> 3. **优化群消息管理**：群消息过多导致重要通知被淹没，建议设立专门的通知渠道或用置顶/公告功能。

**练习 2：用金字塔结构准备一次汇报**

选一个你近期需要汇报的工作/学习成果，按以下结构准备：
- 中心论点：我要说的核心结论是___
- 论据 1：___（支撑事实：___）
- 论据 2：___（支撑事实：___）
- 论据 3：___（支撑事实：___）

### 1.5 常见错误

| 错误 | 表现 | 改进方法 |
|------|------|---------|
| 没有结论 | 说了一堆，听众不知道你想表达什么 | 先问自己"我最想传达的一个信息是什么" |
| 结论太多 | 又想说 A 又想说 B，中心不聚焦 | 强制自己只写一个中心论点 |
| 论据不支撑 | 论据和论点之间逻辑断裂 | 用"所以呢？"检验：论据 → 所以 → 论点成立吗？ |
| 分组混乱 | 同一层的内容范畴不一致 | 检查每个论点的范畴，确保同类 |

### 1.6 延伸阅读

- 《金字塔原理》芭芭拉·明托 —— 完整学习结构化思考
- 《结构思考力》李忠秋 —— 更适合中国读者的本土化解读

## 第二课：思维导图（2天）

### 2.1 什么是思维导图

思维导图（Mind Map）由英国心理学家托尼·博赞在 1970 年代提出，是一种模拟大脑神经元网络结构的可视化思维工具。

它从一个中心主题出发，通过分支向外扩展，用关键词、颜色、图像来激发联想和记忆。

### 2.2 思维导图的基本规则

#### 核心规则

1. **一张白纸横放**：横向空间更大，利于发散
2. **中心放主题**：中心图形代表核心主题，用图像更佳
3. **主干用粗曲线**：从中心向外延伸的分支用曲线（比直线更有吸引力）
4. **分支上写关键词**：每条线上只写一个关键词（不是句子）
5. **层级清晰**：主干 → 分支 → 子分支，层层细化
6. **善用颜色**：每个主干用不同颜色，便于区分
7. **加图标和涂鸦**：图像增强记忆和联想

#### 思维导图的结构

```
                    子主题 A1
                   /
          主题 A —— 子主题 A2
         /          \
        /            子主题 A3
中心主题 ——————————
        \
         \            子主题 B1
          主题 B ——
                      子主题 B2
```

### 2.3 思维导图 vs 其他图形工具

| 工具 | 方向 | 特点 | 适用场景 |
|------|------|------|---------|
| 思维导图 | 从一个点发散 | 放射状、自由联想 | 头脑风暴、创意发散、知识整理 |
| 概念图 | 多点互联 | 网状、强调关系 | 展示概念之间的复杂关系 |
| 逻辑树 | 从上到下 | 层级分明、MECE | 问题拆解、决策分析 |
| 鱼骨图 | 左右排列 | 因果归类 | 根因分析 |

### 2.4 手绘思维导图的步骤

**准备**：空白 A4 纸横放、至少 3 种颜色的笔

**Step 1**：在纸中央画中心图（30 秒）
- 不需要画得好，能代表主题就行
- 例：主题是"周末计划"，画一个笑脸或太阳

**Step 2**：画主干分支（1 分钟）
- 从中心向四周画出 5-7 条粗曲线
- 每条主干写一个主要维度
- 每条主干用不同颜色

**Step 3**：细化子分支（3-5 分钟）
- 从每条主干延伸出子分支
- 子分支上写关键词
- 越往外越细

**Step 4**：添加图标和强调（1 分钟）
- 在重要的关键词旁画小图标
- 用箭头连接有关联的分支
- 用圈或框标出重点

| 工具 | 平台 | 特点 | 适合人群 |
|------|------|------|---------|
| XMind | 全平台 | 功能全面、模板丰富 | 进阶用户 |
| MindNode | Mac/iOS | 界面简洁、操作流畅 | Mac 用户 |
| 幕布 | 全平台 | 大纲+思维导图双模式 | 笔记爱好者 |
| ProcessOn | Web | 在线协作、支持多种图形 | 团队协作 |

### 2.6 实战练习

**练习 1：读书笔记思维导图**

选一本你最近在读的书，画一张思维导图总结核心内容：
- 中心：书名
- 主干：书的 3-5 个核心观点
- 子分支：每个观点的关键论据或例子

**练习 2：周末计划思维导图**

用思维导图规划你的周末：
- 中心：周末计划
- 主干：可以按"时间"（周六上午/下午/晚上…）、"地点"、"活动类型"等维度
- 子分支：具体活动安排

**练习 3：会议记录思维导图**

下次参加会议/听讲座时，用思维导图做记录：
- 中心：会议主题
- 主干：讨论的主要议题
- 子分支：每个议题的关键讨论点和决定

### 2.7 常见问题

**Q：我画的思维导图看起来很乱？**
A：思维导图的目的是帮助你思考，不是艺术品。乱一点没关系，只要你能看懂。

**Q：关键词太长怎么办？**
A：如果一个关键词超过 3-4 个字，试着提炼。比如"提高客户满意度"→"客户满意"。

**Q：分支太多了怎么办？**
A：主干控制在 5-7 个（人类短期记忆的容量）。子分支不限，但超过 3 层就要考虑是否需要重新组织。

## 第三课：MECE 原则（2天）

### 3.1 什么是 MECE

MECE（发音为 "me-see"）= Mutually Exclusive, Collectively Exhaustive

- **Mutually Exclusive（相互独立）**：分类之间没有重叠
- **Collectively Exhaustive（完全穷尽）**：分类合在一起没有遗漏

简单说：**不重不漏**。

### 3.2 为什么 MECE 重要

**反面案例**：

> 经理问："我们的客户主要是什么人？"
> 下属答："主要是年轻人、女性和高收入人群。"

这个回答不 MECE：
- 年轻女性既是"年轻人"又是"女性"（重叠）
- 没有提到中年人和低收入人群（遗漏）

**MECE 的回答**：
> 按性别分：男性、女性
> 按年龄分：青年（18-35）、中年（36-60）、老年（60+）
> 按收入分：高收入、中收入、低收入

每一层分类各自满足不重不漏。

### 3.3 常用 MECE 框架

| 框架 | 分类方式 | 应用场景 |
|------|---------|---------|
| 时间 | 过去、现在、未来 | 复盘、规划 |
| 空间 | 内部、外部 | 分析原因、划分范围 |
| 程度 | 高、中、低 | 分级分类 |
| 3W | What、Why、How | 解释任何事物 |
| 4P | Product、Price、Place、Promotion | 营销策略 |
| 人/事/物 | 人的问题、事的问题、物的问题 | 问题分类 |
| 输入/过程/输出 | 资源→流程→结果 | 流程分析 |

### 3.4 如何检验 MECE

**检验方法一：反例法**
- 找重叠：能不能找到一个东西同时属于两个分类？→ 有重叠
- 找遗漏：能不能找到一个东西不属于任何分类？→ 有遗漏

**检验方法二：实际穷举法**
- 列出所有具体实例
- 检查每个实例是否恰好属于一个分类

### 3.5 MECE 的实战应用

**场景 1：分析问题**

问题："为什么销售额下降了？"

MECE 拆解：
```
销售额下降
├── 客户数量减少
│   ├── 新客户获取减少
│   └── 老客户流失增加
└── 客单价下降
    ├── 产品降价
    └── 购买频次/数量减少
```

**场景 2：制定计划**

目标："提升个人能力"

MECE 拆解：
```
个人能力提升
├── 专业能力（硬技能）
│   ├── 本领域深度
│   └── 跨领域广度
├── 通用能力（软技能）
│   ├── 沟通能力
│   ├── 时间管理
│   └── 思维能力
└── 身心状态
    ├── 身体健康
    └── 心理状态
```

### 3.6 实战练习

**练习 1：检验以下分类是否 MECE**

1. "我们的产品线分为：高端产品和低端产品"
2. "员工满意度调查分为：薪酬、工作环境、人际关系、职业发展"
3. "书的分类：小说、非小说、中文书、英文书"

参考答案：
1. ❌ 不穷尽——没有"中端产品"
2. ⚠️ 基本 MECE，但可能有模糊地带（"工作环境"和"薪酬"的边界）
3. ❌ 不独立——中文小说既是"小说"又是"中文书"

**练习 2：用 MECE 拆解以下问题**

1. "如何提高团队效率？"
2. "为什么我最近总是很累？"
3. "如何规划一次旅行？"

### 3.7 注意事项

- MECE 是一种理想标准，实际应用中做到"大致 MECE"即可
- 不要为了追求 MECE 而过度分类——分类的目的是帮助思考，不是制造复杂性
- 同一层级内保持 MECE，不同层级可以用不同的分类维度

## 第四课：5W1H / 5W2H（1天）

### 4.1 什么是 5W1H

5W1H 是通过六个基本问题来全面理解一件事的方法：

| 维度 | 英文 | 问题 | 作用 |
|------|------|------|------|
| What | 什么 | 是什么？做什么？ | 明确对象和目标 |
| Why | 为什么 | 为什么做？原因是什么？ | 理解动机和原因 |
| Who | 谁 | 谁来做？谁参与？谁受影响？ | 明确责任人 |
| When | 何时 | 什么时候开始？什么时候完成？ | 时间规划 |
| Where | 哪里 | 在哪里做？从哪里入手？ | 场景定位 |
| How | 如何 | 怎么做？用什么方法？ | 执行路径 |

扩展版 5W2H 加上：
| How much | 多少 | 需要多少资源？成本多少？收益多少？ | 量化评估 |

### 4.2 使用场景

**场景 1：接到一个任务时**

老板说："你负责下周的客户活动。"

用 5W1H 厘清：
- What：什么样的活动？什么主题？什么规模？
- Why：活动目的是什么？（维护老客户？开发新客户？）
- Who：谁来协助？邀请哪些客户？
- When：具体哪天？什么时间开始和结束？
- Where：在哪里举办？线上还是线下？
- How：怎么组织？预算多少？

**场景 2：写一份报告时**

用 5W1H 检查是否遗漏关键信息：
- What：报告主题和核心结论
- Why：为什么要做这个报告（背景和原因）
- Who：相关人员/利益方
- When：时间线和里程碑
- Where：涉及的地点/范围
- How：方法和执行计划
- How much：预算/资源/预期收益

### 4.3 实战练习

**练习：用 5W1H 分析以下场景**

1. 你要组织一次团队建设活动
2. 你想学习一门新的编程语言
3. 公司要上线一个新功能
