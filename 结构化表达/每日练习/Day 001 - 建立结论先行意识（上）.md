## 一、今日学习内容

### 1.1 PREP 框架复习

| 字母 | 含义 | 作用 |
|------|------|------|
| **P** - Point | 结论/观点 | 让对方知道你要说什么 |
| **R** - Reason | 原因 | 解释为什么 |
| **E** - Example | 例子/数据 | 用事实支撑 |
| **P** - Point | 重申结论 | 强化记忆 |

**口诀：** "我的观点是…因为…比如…所以…"

### 1.2 什么是"结论后置"？

大多数人的表达习惯是"讲故事"——从背景说到结论，让听的人猜。

**典型表现：**
- 说了一堆，对方问"所以你想表达什么？"
- 写邮件写了半页纸，还没说到重点
- 开会发言 3 分钟，大家不知道你要干嘛

### 练习 1：找 3 个"结论后置"的反例

回想你最近 3 天的沟通场景（邮件、微信、会议、口头），找出 3 个"结论后置"的例子。

**格式：**

```
【反例 1】
场景：（什么时候，和谁沟通）
原话/原文：（你实际说了什么/写了什么）
问题：（为什么是结论后置）
```

**示例：**

```
【反例 1】
场景：昨天和领导讨论要不要加新功能
原话："我们最近收到几个用户反馈说想要这个功能，
      然后我看了一下竞品也有，
      技术上实现也不难，
      大概需要 3 天时间，
      所以我觉得可以加。"
问题：结论"可以加"放在最后，前面都是铺垫，
      领导听完可能已经不耐烦了。
```

### 练习 2：改写反例为"结论先行"

把上面 3 个反例改写成"结论先行"的版本。

**格式：**

```
【改写 1】
结论：（第一句话）
支撑：（原因 + 例子）
```

**示例：**

```
【改写 1】
结论："我建议加这个新功能。"
支撑：
"原因有三：
1. 有 5 个用户明确反馈需要
2. 竞品 A 和 B 都有这个功能
3. 技术上 3 天可以搞定，风险低"
```
