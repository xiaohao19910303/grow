- 用户要求系统梳理「功能结构 + 功能逻辑 + 待改进项」，并判断作为「成长陪伴教练/自我学习规划」是否可行。
- 通读：README、长期成长体系总规划、学习系统总览、平台演进规划、app.py、copilot/api.py、behavior_report/analyzer.py、reflections/assist.py、plans/generation.py，以及 10-19/10-20 行动计划评审日志。
- 核心结论：
  1. 顶层 Markdown 规划层 + 知行成长平台层（FastAPI+PostgreSQL+原生前端，5 栏目：今日/行动/学习/记录/成长）双轨，且两者描述已漂移（文档写 SQLite 单用户本地 v2 + 强制打卡，实际是 PG 多用户云端 v4 + 不设每日必学）。
  2. 后端 12+ 模块：copilot/plans/reading/reflections/behavior/errors/predictions/behavior_report/knowledge/stocks/action_plans/search+timeline/accounts/backup。
  3. AI「教练」能力是零散、被动、按需触发的：规划生成、课程续写、复盘追问/三段整理、行为分析报告、行动建议、阅读导读 —— 但无主动陪伴、无跨期记忆、无趋势提醒。
  4. 最大未验证项：真实数据几乎为空（旧复盘 0 条、learning_plans=0、71 知识节点但掌握未知），代码成熟 ≠ 真实使用，教练诊断缺样本。
  5. plans（学习规划生成）与 action_plans（行动计划执行）两套独立体系未打通，规划→执行→度量→回流未闭环。
- 结论：作为「自我学习规划工具」骨架成立、可用；作为「成长陪伴教练」还差「按需工具→主动陪伴」这一步 + 数据回流。
